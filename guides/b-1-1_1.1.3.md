## 1.1.3.1 — ENVIRONMENT VERSUS INTERFACE

**Framing.** The docs describe three **execution environments**, which decide where code runs and where files live: **Local** (your machine, the default), **Cloud** (Anthropic-managed virtual machines or self-hosted environments your organisation operates) and **Remote Control** (your machine, driven from a browser). The interface is a separate choice: terminal, IDE, desktop app, browser or mobile. The loop is the same in all of them [Claude Code docs, How Claude Code works, 2026].

| Environment | Code runs on | Survives closing your laptop? | Typical use |
|---|---|---|---|
| Local | Your machine | No | Default; full access to your files and tools |
| Cloud | Anthropic-managed VMs or self-hosted | Yes | Offload tasks; work on repos you do not have locally |
| Remote Control | Your machine | No: your machine must stay on | Drive a local session from the web UI or phone |

The glossary draws the same line: a **cloud session** keeps running after you close your laptop because it runs on cloud infrastructure; **Remote Control** continues a local session from another device while execution and files stay on your machine [Claude Code docs, Glossary, 2026].

The failure mode: **Environment-surface conflation.** You treat 'the web app' as the environment and assume work started there runs locally, or that the terminal means local when you launched with a cloud flag.

The fix: Ask two separate questions: where does the code run, and where do I interact; write both down for the task.

Cross-references: choosing where to run is Module 7.1; cloud sessions are Module 7.4; remote control is Module 7.5.

**If you remember one thing:** two questions, not one: where it runs and where you steer it.

## 1.1.3.2 — THE SURFACES AND THEIR TRADE-OFFS

**Framing.** The docs list the terminal CLI, VS Code, JetBrains, the desktop app, the web and mobile, plus integrations. Choose by what the task needs from the interface [Claude Code docs, Platforms, 2026].

| Surface | Best for | Trade-off |
|---|---|---|
| CLI | Terminal workflows, scripting, remote servers | The most complete; scripting and the Agent SDK are CLI-only |
| Desktop | Visual diff review, parallel sessions, managed setup | Gives up some CLI-only features |
| VS Code | Inline diffs inside the editor | Gives up some CLI-only features |
| JetBrains | The same inside JetBrains IDEs | The plugin needs the CLI installed separately |
| Web | Long tasks needing little steering; work that continues offline | Cloud; less suited to heavy back-and-forth |
| Mobile | Starting and monitoring tasks away from the computer | A thin client into cloud sessions, Remote Control or Dispatch |

[Claude Code docs, Overview and Platforms, 2026]

Integrations such as Chrome, Slack, GitHub Actions, GitLab CI/CD and Code Review connect to a surface; the glossary notes that Slack and the Chrome extension are integrations rather than surfaces themselves [Claude Code docs, Glossary, 2026].

The failure mode: **Wrong-surface choice.** You start a two-hour migration in a local terminal and close the laptop, or run a task that needs constant steering in a cloud session you cannot see.

The fix: Use the decision tree: match the surface to how much steering the task needs and whether it must outlive your machine.

Cross-references: the desktop app is Module 7.2; IDE integrations are Module 7.3; browser and computer use are Module 7.6.

**If you remember one thing:** pick the surface by the steering the task needs, not by habit.

## 1.1.3.3 — A DECISION TREE YOU CAN RUN IN 30 SECONDS

**Framing.** Four questions settle most choices. Run them in order.

```
 1. Needs my local files, tools or secrets?  yes ► Local (CLI, Desktop or IDE)
                                              no  ▼
 2. Long-running, little steering needed?     yes ► Cloud session (check back later)
                                              no  ▼
 3. Want to steer a local session from phone  yes ► Remote Control
    or browser?                               no  ▼
 4. Should it happen on a schedule or event?  yes ► Scheduled task, Channels or CI
```

| Task | Environment | Surface | Why |
|---|---|---|---|
| Fix a bug in the repo on my laptop, review the diff | Local | CLI or IDE | Needs my tools; quick steering |
| Refactor a 200-file module overnight | Cloud | Web | Outlives the laptop; low steering |
| Check on a running local test loop from the sofa | Remote Control | Mobile or browser | Execution stays local |
| Triage every new issue on a schedule | Scheduled or CI | Integration | No human in the loop |

The failure mode: **Steering-blind delegation.** You send a task needing frequent human judgment to a cloud session, then discover three hours later that it made a wrong early decision.

The fix: Put judgment-heavy work in a local or Remote Control session and reserve cloud sessions for tasks with a check and little steering.

Cross-references: scheduled tasks and loops are Module 6.7; CI and code review are Module 7.8; Dispatch and channels are in Modules 7.5 and 7.7.

**If you remember one thing:** four yes/no questions beat a debate about tools.

## 1.1.3.4 — WORKING WHEN YOU ARE AWAY

**Framing.** The docs treat away-from-terminal work as its own decision with several mechanisms. Dispatch routes a task from the mobile app to a Claude Code session in the desktop app (Pro and Max plans); Remote Control continues a local session from phone or browser; Channels push events from chat apps into a running session; Slack lets you mention Claude; self-hosted environments and scheduled tasks cover team and recurring work [Claude Code docs, Platforms and Glossary, 2026].

| Mechanism | Trigger | Where it runs | Plan or availability note |
|---|---|---|---|
| Dispatch | Message from the mobile app | Desktop app session | Pro and Max [Claude Code docs, Glossary, 2026] |
| Remote Control | You open claude.ai/code or the app | Your machine | Execution stays local |
| Channels | An event in Telegram, Discord or iMessage | Your running session | Research preview [Claude Code docs, Glossary, 2026] |
| Cloud session | `claude --cloud`, web, mobile | Anthropic or self-hosted VMs | Survives disconnect |
| Teleport | `/teleport` | Pulls a cloud session into your terminal | Reverse is `--cloud` |

A persistent Remote Control session that loses its credentials stops making progress and cannot recover until you log in again [Claude Code docs, Authentication, 2026; wording from the translated page, verify in English].

The failure mode: **Offline-assumption.** You leave a Remote Control or local session running and close the laptop, then find nothing happened because execution was on your machine.

The fix: For work that must continue after you disconnect, use a cloud session; for work that stays local, keep the machine awake and signed in.

Cross-references: mobile and remote control are Module 7.5; team chat integrations are Module 7.7; authentication is Module 1.3.

**If you remember one thing:** away-from-terminal means choosing which machine keeps working.

| Element | What is wrong |
