## 8.2.2.1 — FIELDS, DEFAULTS AND WHERE EACH IS DOCUMENTED

**Framing.** Every query() call accepts Options (TypeScript) or ClaudeAgentOptions (Python). Each field is optional, and a session with no options runs with the SDK's defaults [Agent SDK docs, Configure your agent, 2026].

| TypeScript | Python | Controls |
|---|---|---|
| permissionMode | permission_mode | What the agent can do without approval |
| allowedTools | allowed_tools | Pre-approved tool calls |
| canUseTool | can_use_tool | Your approval callback |
| systemPrompt | system_prompt | Agent instructions |
| settingSources | setting_sources | Which filesystem settings load |
| mcpServers | mcp_servers | External tool servers |
| agents | agents | Subagent definitions |
| hooks | hooks | Lifecycle callbacks |
| outputFormat | output_format | Structured output schema |
| resume / forkSession | resume / fork_session | Session continuation and branching |
| sessionStore | session_store | External persistence |
| enableFileCheckpointing | enable_file_checkpointing | Rewindable edits |
| effort | effort | How much work Claude puts in |
| sandbox | sandbox | Sandbox behaviour for tool execution |

[Agent SDK docs, Configure your agent, 2026]. The temperature, top_p and max_tokens request parameters have no fields; use effort or a spend cap, or call the Messages API [same page].

The failure mode: **Phantom parameter.** You search for a temperature or max_tokens option on the options object, find none, and add a prompt instruction that the model cannot honour.

The fix: Use effort and spend caps, or call the Messages API when you need sampling parameters.

Cross-references: field-by-field depth is Module 8.2.3 to Module 8.2.5 and Module 8.3 to Module 8.6.

**If you remember one thing:** every option has a page; the table is the map.

## 8.2.2.2 — MODEL, FALLBACK AND EFFORT

**Framing.** If you do not set model, a new session uses Claude Code's default model, which depends on settings and environment. Setting model pins one; aliases and full names are accepted. fallbackModel (fallback_model) names a backup used when the primary is overloaded or unavailable, and the primary is retried at the start of each user turn [Agent SDK docs, Configure your agent, 2026].

```typescript
const options = {
  model: "claude-sonnet-5",
  fallbackModel: "claude-opus-5,claude-sonnet-5",   // single model or comma-separated list
  effort: "medium",
};
```
[Agent SDK docs, Configure your agent, 2026] (illustrative values; use the model ids you have access to). In TypeScript, a fallback equal to model throws at startup. Switching model mid-session recomputes the whole conversation uncached at the new model's rates because each model has its own prompt cache.

The failure mode: **Silent default model.** You never set model, the session picks whatever Claude Code's default resolves to for that account, and costs or behaviour change when the default changes.

The fix: Pin model explicitly in production and log the model from each AssistantMessage.

Cross-references: cost tracking is Module 8.6.3; effort levels are in Module 8.2.1.

**If you remember one thing:** pin the model, then log which model answered.

## 8.2.2.3 — ENVIRONMENT, WORKING DIRECTORY AND SETTINGS

**Framing.** The env option sets variables for the Claude Code process. In TypeScript it replaces the subprocess environment, so spread process.env to keep PATH, HOME and ANTHROPIC_API_KEY; in Python your values merge over the inherited ones. If unset, the subprocess inherits your environment in both [Agent SDK docs, Configure your agent, 2026].

| Option | Behaviour | Gotcha |
|---|---|---|
| env (TS) | Replaces environment | Forgetting `...process.env` drops the API key |
| env (Python) | Merges over inherited | Your values win |
| cwd | Working directory of the session | No setter; start another session to change it |
| additionalDirectories / add_dirs | Extra paths tools can reach | Grants file access, not configuration |
| settings | Path, inline JSON (TS also object) | Overrides user, project and local settings |
| settingSources | [] disables user/project/local | Managed policy still applies |

[Agent SDK docs, Configure your agent, 2026]. cwd decides which project's settings, hooks, skills and stored sessions apply.

The failure mode: **Env wipe.** In TypeScript you pass env with only ANTHROPIC_BASE_URL, the subprocess loses PATH, HOME and the API key, and the agent fails to start or authenticate.

The fix: Spread process.env first, then add your overrides.

Cross-references: multi-tenant isolation with env and cwd is Module 8.7.3.

**If you remember one thing:** env semantics differ by language; spread in TypeScript.

## 8.2.2.4 — CHANGING CONFIGURATION MID-SESSION

**Framing.** With streaming input you can switch model and permission mode while the session runs: setModel and setPermissionMode on the Query object in TypeScript, set_model and set_permission_mode on ClaudeSDKClient in Python. Calling setModel with no model switches to Claude Code's default, not your options model [Agent SDK docs, Configure your agent, 2026].

| Method | TypeScript | Python |
|---|---|---|
| Switch model | `query.setModel()` | `client.set_model()` |
| Switch permission mode | `query.setPermissionMode()` | `client.set_permission_mode()` |
| Apply runtime settings | `applyFlagSettings()` | not listed |
| Write local settings | `updateSettings()` | not listed |

[Agent SDK docs, Configure your agent, 2026]. query() in Python returns a plain iterator without control methods, so use ClaudeSDKClient. Check the reference for which keys applyFlagSettings accepts.

The failure mode: **Cache-reset switch.** You switch models between turns of a long session and the next request pays full uncached cost for the entire history.

The fix: Switch at session boundaries, or accept the one-time recompute and measure it in the cache token fields.

Cross-references: streaming input is Module 8.4.1; prompt caching is Module 8.6.3.

**If you remember one thing:** mid-session changes are possible, and the cache pays for them.
