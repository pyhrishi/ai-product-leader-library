# MODULE 3.2.6 — SIZE AND PRUNING: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**Keep each CLAUDE.md short, under about 200 lines, and prune by asking of each line whether removing it would cause mistakes.**

**Prove-it, in one sentence:** cut a file below 200 lines and show the behaviour did not regress on three tasks.

**The single most important discipline: for each line ask: if I removed this, would Claude make a mistake? If not, remove it.**

**The counterintuitive claim you will learn to defend:** longer files consume more context and reduce adherence, so adding a rule can make every other rule less likely to be followed [Claude Code docs, Memory, 2026].

## 3.2.6.1 — THE SIZE RULE

**Framing.** The memory guide targets under 200 lines per CLAUDE.md file; longer files consume more context and reduce adherence [Claude Code docs, Memory, 2026]. The Extend page repeats it: keep CLAUDE.md under 200 lines, and move reference content to skills or split into `.claude/rules/` files [Claude Code docs, Extend Claude Code, 2026]. Note that the 200-line figure for CLAUDE.md is a target, while the 200-line-or-25KB cutoff applies to `MEMORY.md` and is a hard load limit.

| File | 200 line figure | Type |
|---|---|---|
| CLAUDE.md | Target per file | Guidance |
| `MEMORY.md` | First 200 lines or 25KB load | Hard load limit |

The failure mode: **Limit-conflation.** You treat the CLAUDE.md target and the MEMORY.md load cutoff as the same rule, and truncate the wrong file's expectations.

The fix: Remember CLAUDE.md loads in full; only MEMORY.md is cut at 200 lines or 25KB.

Cross-references: auto memory is Module 3.3.

**If you remember one thing:** target for one, limit for the other.

## 3.2.6.2 — PRUNING WITH A REGRESSION CHECK

**Framing.** Best practices suggests `/doctor` for proposed cuts and says that if Claude keeps ignoring a line that is in the file, either the file has grown long enough that the line gets lost, or the line is a rule that cannot have exceptions and belongs in a hook [Claude Code docs, Best practices, 2026]. Test changes by watching whether behaviour shifts.

```text
Regression check
 task A (uses rule 3)  before: ok   after pruning: ok
 task B (uses rule 7)  before: ok   after pruning: FAIL -> restore rule 7
 task C (no rules)     before: ok   after pruning: ok
```

The failure mode: **Prune-without-test.** You delete lines by feel and a rule you needed silently disappears.

The fix: Run a few representative tasks before and after, and restore any line whose removal changes behaviour.

Cross-references: verification is Module 2.3.

**If you remember one thing:** prune, then check.

---

## 3.2.6.3 — WHEN PRUNING IS NOT ENOUGH

**Framing.** If the file is still too long after pruning, move area-specific guidance to path-scoped rules or per-directory files, and reference material to skills [Claude Code docs, Large codebases; Extend Claude Code, 2026]. The managed-policy file cannot be excluded by individual settings.

| Content | Moves to |
|---|---|
| API-specific rules | `.claude/rules/api.md` with `paths:` |
| Per-package conventions | Package CLAUDE.md |
| Long procedures | Skill |
| Must-hold rules | Hook |

The failure mode: **Hoarded-file.** You keep every rule in one root file because moving is work, and the file passes 400 lines.

The fix: Split by load condition: path rules, nested files, skills and hooks.

Cross-references: path-scoped rules are Module 3.3; large repos are Module 3.5.

**If you remember one thing:** split by when it should load.

## CLOSING REFRAME

This is the craft of pruning: **fewer lines, each load-bearing.** The engineer who understands this does not ask "what else should I add?" — they ask "what breaks if this goes?"
