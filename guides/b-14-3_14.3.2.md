## 14.3.2.1 — ACCOUNTS AND HEALTH

**Framing.** `claude auth login` supports `--email`, `--sso` and `--console`; `claude auth logout`; `claude auth status` prints JSON (or text with `--text`), exits 0 if logged in and 1 if not, with `authMethod` one of none, claude.ai, oauth_token, api_key, api_key_helper or third_party. `claude doctor` prints read-only installation and settings diagnostics without starting a session. `claude setup-token` generates a long-lived OAuth token for CI and needs a subscription [Claude Code docs, CLI reference, 2026].

```bash
claude auth status --text
claude doctor
```

| Command | Mutates? |
|---|---|
| `claude auth status` | No |
| `claude doctor` | No (read-only) |
| `claude setup-token` | Prints token; not saved |

The failure mode: **Token-in-log.** You run `claude setup-token` in a CI log or shared terminal and the printed token ends up stored.

The fix: Run it locally, copy to a secret store and never echo it in logs.

Cross-references: CI auth is Module 8.1; security is Module 11.1.

**If you remember one thing:** treat the token as a secret.

## 14.3.2.2 — EXTENSIONS AND SERVERS

**Framing.** `claude mcp` configures MCP servers; `claude mcp login <name>` runs OAuth for HTTP, SSE and connector servers and `--no-browser` prints the URL over SSH; `claude mcp logout <name>` clears credentials. `claude plugin` manages plugins (alias `claude plugins`), for example `claude plugin install code-review@claude-plugins-official`. `claude update` updates and `claude install [version]` installs a version, `stable` or `latest` [Claude Code docs, CLI reference, 2026].

```bash
claude mcp login sentry --no-browser
claude plugin install code-review@claude-plugins-official
claude install stable
```

The failure mode: **Unpinned-install.** You install `latest` on a team machine and versions drift between teammates.

The fix: Pin with `claude install <version>` where reproducibility matters.

Cross-references: MCP is Module 5.5; plugins are Module 5.6; admin rollout is Module 10.1.

**If you remember one thing:** pin versions for teams.

## 14.3.2.3 — BACKGROUND SESSIONS

**Framing.** `claude agents` opens agent view (`--json` for scripting, `--json --all` including completed); `claude attach <id|name>`, `claude logs <id|name>`, `claude respawn <id>`, `claude stop <id>` (also `claude kill`) and `claude rm <id>` manage background sessions; `claude daemon status|logs|run|stop` manage the supervisor. Name matching in attach and logs needs v2.1.290 or later [Claude Code docs, CLI reference, 2026].

| Need | Command |
|---|---|
| List | `claude agents --json` |
| Read output | `claude logs <id>` |
| Resume work | `claude attach <id>` |
| Restart all | `claude respawn --all` |
| Stuck supervisor | `claude daemon status`, then `stop` |

The failure mode: **Orphan-sessions.** You leave background sessions running and later cannot tell which are alive or consuming usage.

The fix: List with `claude agents` and stop what you do not need.

Cross-references: background sessions are Module 6.3.

**If you remember one thing:** list before you leave.

## 14.3.2.4 — STATE CLEANUP

**Framing.** `claude purge [path]` deletes all local state for a project: transcripts, task lists, debug logs, file-edit history, prompt history lines and the project's entry in `~/.claude.json`; flags are `--dry-run`, `-y`, `-i` and `--all` [Claude Code docs, CLI reference, 2026].

```bash
claude purge --dry-run
claude purge ./old-project -i
```

The failure mode: **Purge-without-preview.** You run `claude purge --all -y` and delete transcripts you needed.

The fix: Always run `--dry-run` first and use `-i` to confirm items.

Cross-references: transcript retention is Module 11.1.

**If you remember one thing:** preview before you purge.
