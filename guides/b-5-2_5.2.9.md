## THE THESIS OF THIS TOPIC

**Skills accumulate cost and drift, so you need the commands that list them, price them, hide them and refresh them.**

**Prove-it, in one sentence:** run /skill-doctor, hide one unused skill with skillOverrides, and show the listing cost fell.

## 5.2.9.1 — LIST AND PRICE

**Framing.** `/skills` lists available skills; synced claude.ai skills appear under `claude.ai sync`. `/skill-doctor` (v2.1.252+, not available in sessions that skip feature-flag fetching) reports each skill's context cost and usage, flags never-invoked skills and where to turn them off; it covers your skills other than bundled and enterprise ones [Claude Code docs, Skills, 2026]. `/doctor` estimates the listing's context cost.

| Command | Does |
|---|---|
| `/skills` | List, filter and change visibility |
| `/skill-doctor` | Context cost and usage per skill |
| `/doctor` | Listing cost estimate and biggest contributors |
| `/context` | Skills row shows the listing size after budget |

[Claude Code docs, Skills and Commands, 2026]

The failure mode: **Never-reviewed pile.** You add skills for months and never run `/skill-doctor`, so unused skills keep costing context on every turn.

The fix: Review cost and usage after adding skills and switch off the never-invoked ones.

Cross-references: context costs are sub-topic 5.1.8.

**If you remember one thing:** list, price, then prune.

---

## 5.2.9.2 — HIDE WITHOUT EDITING

**Framing.** `skillOverrides` sets visibility from settings: states are `on`, `name-only`, `user-invocable-only` and `off`; plugin skills are not affected, manage those via `/plugin` [Claude Code docs, Skills, 2026]. In the `/skills` editor, press Space to cycle states and Esc to save.

```json
{
  "skillOverrides": {
    "legacy-context": "name-only",
    "deploy": "off"
  }
}
```
| State | Effect |
|---|---|
| `on` | Normal |
| `name-only` | Listed without description |
| `user-invocable-only` | You can invoke; Claude cannot auto-load |
| `off` | Hidden |

The failure mode: **Plugin-skill override.** You add a plugin skill's name to `skillOverrides` expecting it to change, and nothing happens.

The fix: Manage plugin skills through `/plugin`.

Cross-references: plugins are Module 5.6; settings precedence is Module 4.1.

**If you remember one thing:** overrides change visibility without editing the file.

## 5.2.9.3 — REFRESHING

**Framing.** Claude Code watches the skill directories, so adding, editing or removing a skill under `~/.claude/skills/`, the project `.claude/skills/` or an `--add-dir` directory takes effect without a restart. The skills page says `/reload-skills` is needed only after you create a top-level skills directory that did not exist at session start; plugin changes to `hooks/`, `.mcp.json`, `agents/` and `output-styles/` need `/reload-plugins` [Claude Code docs, Skills, 2026]. The commands reference describes `/reload-skills` more broadly, as a rescan so skills added or changed on disk during the session become available [Claude Code docs, Commands, 2026].

| Change | Needed |
|---|---|
| Edit an existing skill | Nothing (live detection) |
| Create `~/.claude/skills/` for the first time mid-session | `/reload-skills` |
| Edit a plugin's hooks | `/reload-plugins` |

The failure mode: **Reload-reflex.** You restart the session after every skill edit, losing context, when live detection would have applied it.

The fix: Edit and retry; reload only for a new top-level directory.

Cross-references: plugins reload is sub-topic 5.6.3.

**If you remember one thing:** most edits apply live.
