## 8.2.3.1 — THREE STARTING POINTS

**Framing.** Without systemPrompt the SDK uses a minimal prompt that covers tool calling but omits the claude_code preset's security instructions and working-directory context; this differs from claude -p, which uses the Claude Code prompt by default [Agent SDK docs, Modifying system prompts, 2026].

| You are building | Use | You get |
|---|---|---|
| CLI/IDE-like coding tool, human steering | claude_code preset | Tool guidance, safety rules, environment context |
| Same plus product rules | preset with `append` | Everything, with your text after it; lowest risk |
| Different surface, identity or permission model; non-coding | Custom string | Only what you write; you replace tool guidance and safety |
| Thin tool-calling loop | No systemPrompt | Minimal default |

```python
system_prompt={"type": "preset", "preset": "claude_code", "append": "Always include type hints."}
```
[Agent SDK docs, Modifying system prompts, 2026]. Unattended coding automation, such as a CI job fixing lint, still fits the preset [same page].

The failure mode: **Bare-prompt assumption.** You leave systemPrompt unset, expect CLI-like behaviour, and the agent lacks the preset's safety and environment guidance.

The fix: Set the claude_code preset explicitly, or write a custom prompt that replaces what you need.

Cross-references: migration default is Module 8.1.2.

**If you remember one thing:** the default is minimal; opt in to the preset.

## 8.2.3.2 — CLAUDE.MD AND OUTPUT STYLES

**Framing.** CLAUDE.md is read when the matching setting source is enabled: project loads CLAUDE.md or .claude/CLAUDE.md from the working directory; user loads ~/.claude/CLAUDE.md. It is not loaded with an empty settingSources array [Agent SDK docs, Modifying system prompts, 2026].

| Feature | Persistence | Default tools | Built-in safety | Customization |
|---|---|---|---|---|
| CLAUDE.md | Per-project file | Preserved | Maintained | Additions only |
| Output styles | Saved files | Preserved | Maintained | Replace or extend default |
| systemPrompt + append | Session only | Preserved | Maintained | Additions only |
| Custom systemPrompt | Session only | Lost unless included | Must be added | Complete |

[Agent SDK docs, Modifying system prompts, 2026]. An output style is a markdown file in ~/.claude/output-styles/ or .claude/output-styles/; a custom style drops the preset's software engineering instructions unless keep-coding-instructions: true is set. In TypeScript, outputStyle goes inside the settings object; Python has no programmatic option to select one.

The failure mode: **Style-in-code assumption.** In Python you expect to select an output style by option, find none, and ship an agent with the wrong persona.

The fix: Use append or a custom string in Python, or write the style into settings the session loads.

Cross-references: settings sources are Module 8.2.4.

**If you remember one thing:** CLAUDE.md and styles ride on settings sources; append and custom ride in code.

## 8.2.3.3 — CUSTOM PROMPTS AND THEIR LIMITS

**Framing.** A custom string replaces the default entirely: the SDK sends only what you provide. In Python, a large prompt can fail at process spawn because the string is passed as one command-line argument; the docs recommend system_prompt={'type':'file','path':...}, and on Linux the error is 'Argument list too long' [Agent SDK docs, Modifying system prompts, 2026].

| Form | Language | Note |
|---|---|---|
| String | Both | Replaces the default |
| `{type: preset, preset: claude_code, append}` | Both | Keeps preset |
| `{type: file, path}` | Python | Avoids argument-length failure |
| Array with `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` | TypeScript | Splits static from per-request text, each with its own cache breakpoint |

[Agent SDK docs, Modifying system prompts, 2026]. The split applies only when the SDK calls the Claude API directly or runs on Claude Platform on AWS; elsewhere the whole prompt is sent as one block.

The failure mode: **Argument-length crash.** A 200-line Python prompt string exceeds the OS argument limit and fails at spawn before any API request.

The fix: Load large prompts from a file with the file form.

Cross-references: hosting differences are Module 8.7.

**If you remember one thing:** size and cache shape belong in the design of a custom prompt.

## 8.2.3.4 — PROMPT CACHING AND PROMPT CHANGES IN RESUMED SESSIONS

**Framing.** Two sessions with the same preset and append still miss the cache from different working directories, because the preset embeds working directory, git status, platform, shell, OS version and auto-memory paths. excludeDynamicSections: true (exclude_dynamic_sections in Python) moves that context into the first user message so identical configurations share a cache entry [Agent SDK docs, Modifying system prompts, 2026].

| Version floor | Feature |
|---|---|
| @anthropic-ai/claude-agent-sdk 0.2.98 / claude-agent-sdk 0.1.58 | excludeDynamicSections |
| TypeScript SDK 0.3.257 | `snapshot` field on systemPrompt |
| Claude Code 2.1.265 (bundled from TS SDK 0.3.265) | Recording append or custom prompt by default |

[Agent SDK docs, Modifying system prompts, 2026]. Tradeoff: instructions in the user message carry marginally less weight. By default the prompt is built once on a session's first request and recorded; a different append passed on resume takes effect after compaction or in a new session. Set snapshot: false to rebuild every request.

The failure mode: **Ignored resume prompt.** You change append on a resumed call and the old prompt still governs, so a hot fix does not take effect.

The fix: Start a new session, wait for compaction, or set snapshot false while iterating.

Cross-references: sessions are Module 8.5; caching metrics are Module 8.6.3.

**If you remember one thing:** a recorded prompt outlives the code that built it.
