## THE THESIS OF THIS TOPIC

**A custom tool is a name, a description, an input schema and a handler, registered through an in-process MCP server, and how the handler reports errors decides what Claude reads next.**

**Prove-it, in one sentence:** build a two-tool server, call it with a wildcard permission, force an error and show the message Claude received.

## 8.3.2.1 — THE FOUR PARTS AND REGISTRATION

**Framing.** A tool has a name, a description Claude reads to decide when to call it, an input schema and an async handler. TypeScript uses a Zod schema; Python uses a dict of types or full JSON Schema. The server is created with createSdkMcpServer or create_sdk_mcp_server and runs inside your application, not as a separate process [Agent SDK docs, Give Claude custom tools, 2026].

```python
@tool("get_temperature", "Get the current temperature at a location",
      {"latitude": float, "longitude": float})
async def get_temperature(args):
    return {"content": [{"type": "text", "text": "..."}]}

server = create_sdk_mcp_server(name="weather", version="1.0.0", tools=[get_temperature])
options = ClaudeAgentOptions(mcp_servers={"weather": server},
                             allowed_tools=["mcp__weather__get_temperature"])
```
[Agent SDK docs, Give Claude custom tools, 2026]. The tool name is `mcp__{server_name}__{tool_name}` where the server name is the key in mcpServers, and characters like `.` or spaces become `_`. A wildcard `mcp__weather__*` covers every tool on the server.

The failure mode: **Unlisted custom tool.** You register the server but omit the tool's full name from allowedTools, and Claude sees the tool but the call needs approval or is denied in an unattended run.

The fix: List the exact mcp__server__tool name or the server wildcard in allowedTools.

Cross-references: tool design principles are Module 8.3.6; permissions are Module 8.6.1.

**If you remember one thing:** register the server, then permit the fully qualified name.

## 8.3.2.2 — HANDLERS: ERRORS, CONTENT BLOCKS AND STRUCTURED DATA

**Framing.** A handler returns content (an array of text, image, audio, resource or resource_link blocks), optionally structuredContent and isError [Agent SDK docs, Give Claude custom tools, 2026].

| Situation | What Claude sees |
|---|---|
| Handler throws | Error result carrying the raw exception message; loop continues |
| Handler returns isError true | The message you composed |
| structuredContent set | The JSON plus image/resource blocks; text blocks in content are not forwarded |
| Python @tool | Forwards only content and is_error; no structuredContent |
| Audio block (TypeScript) | Saved to disk; Claude gets a text block with the path |
| Audio or binary resource (Python) | Dropped with a warning |

[Agent SDK docs, Give Claude custom tools, 2026]. An image block takes base64 data without a data: prefix and a required mimeType; PNG, JPEG, GIF and WebP reach Claude as visual input, other types are saved to disk and the path is given as text.

The failure mode: **Raw-exception reply.** Your handler lets an HTTP failure throw, and Claude reads a bare 'Unexpected token' string with no hint what to retry.

The fix: Catch in the handler and return isError true with the status, the request and a next step.

Cross-references: actionable error design is Module 8.3.6.

**If you remember one thing:** you compose the failure message or the exception does.

## 8.3.2.3 — PARALLELISM, ANNOTATIONS AND APPROVALS

**Framing.** Custom tools default to sequential execution. readOnlyHint: true lets Claude batch the tool with other read-only calls. Annotations are metadata, not enforcement [Agent SDK docs, Give Claude custom tools, 2026].

| Annotation | Default | Meaning |
|---|---|---|
| readOnlyHint | false | No environment changes; enables parallel calls |
| destructiveHint | true | May perform destructive updates |
| idempotentHint | false | Repeat calls have no extra effect; informational |
| openWorldHint | true | Reaches outside your process; informational |

[Agent SDK docs, Give Claude custom tools, 2026]. TypeScript only, v0.3.301 or later: a permission_policy of always_ask or always_deny in a tools array on the server config. In auto or plan mode, also set destructiveHint: true so always_ask calls still reach your callback, because an unset hint counts as false for always_ask.

The failure mode: **Lying hint.** You mark a tool readOnlyHint true because it is usually read-only, and a parallel call performs a write.

The fix: Keep the annotation accurate to the handler; split read and write into separate tools.

Cross-references: approval callbacks are Module 8.4.4.

**If you remember one thing:** annotations describe; they do not enforce.

## 8.3.2.4 — SCHEMAS, OPTIONAL PARAMETERS AND DEFERRAL

**Framing.** TypeScript makes a parameter optional with .optional(); Python's dict schema requires every key, so use JSON Schema, leave the key out of required and read it with args.get() [Agent SDK docs, Give Claude custom tools, 2026]. Tool search is on by default and defers SDK MCP tools, so each tool's schema loads on demand.

| Need | TypeScript | Python |
|---|---|---|
| Enum | z.enum([...]) | Full JSON Schema with enum |
| Optional | .optional() | Omit from required; args.get() |
| Keep schema in prompt | `alwaysLoad: true` in extras or server options | not documented here |
| Unconvertible schema | Tool omitted from the list with a process warning CLAUDE_SDK_MCP_TOOL_SCHEMA_UNCONVERTIBLE | n/a |

[Agent SDK docs, Give Claude custom tools and Connect to external tools with MCP, 2026]. Before TypeScript SDK v0.3.286, one unconvertible schema made the whole listing fail without a warning.

The failure mode: **Vanishing tool.** A tool's schema cannot be converted, the tool is silently left out, and Claude never calls it.

The fix: Watch for the process warning and test that every tool appears in the init tools list.

Cross-references: tool search is Module 8.3.4.

**If you remember one thing:** assert every custom tool shows up in init.
