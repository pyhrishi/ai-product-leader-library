## THE THESIS OF THIS TOPIC

**Nine commands manage work that runs beside your conversation, and the key skill is telling apart the ones that copy the conversation, the ones that detach it and the ones that fan it out.**

## 14.1.3.1 — COPY OR DETACH THE CONVERSATION

**Framing.** `/background [prompt]` detaches the current session as a background agent and frees the terminal (alias `/bg`); monitor it with `claude agents`. `/fork [prompt]` copies the conversation into a new background session while you keep working. `/branch [name]` creates a branch of the conversation, switches you into it and preserves the original, which you return to with `/resume` [Claude Code docs, Commands, 2026].

| Command | You end up | Original conversation |
|---|---|---|
| `/background` | Terminal freed | Keeps running detached |
| `/fork` | Still in the original | Copy runs in the background |
| `/branch` | Inside the copy | Preserved, reachable via `/resume` |

The failure mode: **Copy-confusion.** You use `/branch` expecting the work to continue in the background, and sit in a new conversation while the old one is idle.

The fix: Ask whether you want to stay (`/fork`), move (`/branch`) or leave (`/background`) before you type.

Cross-references: sessions are Module 2.4; background sessions are Module 6.3.

**If you remember one thing:** stay, move or leave.

## 14.1.3.2 — DELEGATE AND WATCH: /SUBTASK, /TASKS, /LIST-AGENTS

**Framing.** `/subtask <task>` spawns a forked subagent that inherits the full conversation and returns its result into this conversation; `/tasks` (alias `/bashes`) shows background work, including finished subagents; `/list-agents` (alias `/peers`) lists subagents, agent team teammates and sessions Claude can message, and requires v2.1.224 or later and cross-session messaging [Claude Code docs, Commands, 2026].

| Question | Command |
|---|---|
| What is running? | `/tasks` |
| Whom can Claude message? | `/list-agents` |
| Hand a side job back to me when done | `/subtask <task>` |

Availability varies by platform, plan and version; if a command is missing, run `/help` and check `claude --version` before assuming it does not exist.

The failure mode: **Orphaned-task.** You launch background work and never check `/tasks`, so a finished or stuck subagent sits unreviewed.

The fix: Check `/tasks` before ending a session and read each finished result.

Cross-references: subagents are Module 1.2.5; cross-session messaging is Module 6.4.

**If you remember one thing:** background work still needs a review pass.

## 14.1.3.3 — FAN OUT AND SCHEDULE: /BATCH, /WORKFLOWS, /SCHEDULE

**Framing.** `/batch <instruction>` is a bundled skill that researches the codebase, decomposes the work into 5 to 30 independent units, presents a plan and, once approved, spawns one background subagent per unit in an isolated worktree; it needs a git repository or a `WorktreeCreate` hook [Claude Code docs, Commands, 2026]. `/workflows` opens the progress view to watch, pause, resume or save workflows, and `/schedule` creates, updates, lists or runs routines that execute in the cloud (alias `/routines`) [Claude Code docs, Commands, 2026].

```text
/batch migrate src/ from JavaScript to TypeScript
```

| Command | Runs where | Use for |
|---|---|---|
| `/batch` | Local worktrees, background subagents | Many independent edits |
| `/workflows` | Progress view | Watching and saving fan-outs |
| `/schedule` | Cloud routines | Recurring work |

The failure mode: **Dependent-units.** You run `/batch` on a change whose pieces depend on each other, so units conflict or each rewrites the same shared file.

The fix: Check the plan for independence before approving; split dependent work into an ordered series instead.

Cross-references: workflows are Module 6.5; scheduled tasks are Module 6.7; worktrees are Module 6.2.

**If you remember one thing:** fan out only independent units.

## CLOSING REFRAME

This is the craft of parallel work: **know where the result lands.** The engineer who understands this does not ask "which parallel command is best?" — they ask "do I stay, move, leave or fan out, and where does the answer come back?"
