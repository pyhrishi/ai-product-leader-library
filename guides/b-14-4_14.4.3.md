## 14.4.3.1 — WHERE EACH THING LIVES

**Framing.** Per the file reference: `skills/<name>/SKILL.md` and `commands/*.md` (project and global), `agents/*.md`, `output-styles/*.md`, `workflows/*.js`, `agent-memory/<name>/`, project-only `.mcp.json`, and hooks defined in `settings.json` [Claude Code docs, Explore the .claude directory, 2026].

| You want | File | Scope |
|---|---|---|
| Reusable prompt | `skills/<name>/SKILL.md` | Project or global |
| Subagent | `agents/*.md` | Project or global |
| Team MCP server | `.mcp.json` | Project only |
| Personal MCP server | `~/.claude.json` | Global |
| Hook | `settings.json` `hooks` | Project or global |
| Saved workflow | `workflows/*.js` | Project or global |

The failure mode: **Misfiled-extension.** You put a team MCP server in your personal config and teammates never get it.

The fix: Use the table to choose project or global before creating the file.

Cross-references: extension choice is Module 5.1.

**If you remember one thing:** scope is part of the path.

---

## 14.4.3.2 — FRONTMATTER FIELDS

**Framing.** Skills accept `name`, `description`, `when_to_use`, `disable-model-invocation`, `allowed-tools`, `model`, `paths`, `hooks` and more; subagents accept `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `memory`, `isolation` and more; rules accept only `paths` [Claude Code docs, Explore the .claude directory, 2026].

| File | Notable fields |
|---|---|
| SKILL.md | name, description, disable-model-invocation, allowed-tools, paths |
| agents/*.md | name, description, tools, model, permissionMode, maxTurns, isolation |
| rules/*.md | paths |
| output-styles/*.md | name, description, keep-coding-instructions |

The failure mode: **Field-guessing.** You invent a frontmatter field name, and it is silently ignored.

The fix: Copy field names from the frontmatter table.

Cross-references: skills are Module 5.2; subagents are Module 5.3.

**If you remember one thing:** unknown fields do nothing.

---

## 14.4.3.3 — PLUGINS AND MARKETPLACES

**Framing.** Installed plugins live under `~/.claude/plugins` with an `installed_plugins.json` record; plugins synced from claude.ai download into `~/.claude/plugins/synced/`; the `command` marketplace source needs v2.1.229 or later [Claude Code docs, Explore the .claude directory, 2026]. Plugin manifests (`plugin.json`, `marketplace.json`) are described in the plugin reference, which this guide did not read.

| Path | Contents |
|---|---|
| `~/.claude/plugins/` | Marketplaces, installed versions, install record |
| `~/.claude/plugins/synced/` | Synced from claude.ai |

The failure mode: **Hand-edited-install-record.** You edit `installed_plugins.json` by hand and Claude Code sets aside a copy and rewrites it.

The fix: Use `claude plugin` commands.

Cross-references: plugins are Module 5.6.

**If you remember one thing:** let the CLI manage plugin state.

---

## 14.4.3.4 — VERIFY THE LOAD

**Framing.** After adding files, reload without restart where available (`/reload-skills`, `/reload-plugins`), and confirm with `/skills`, `/hooks`, `/mcp` and `/status` [Claude Code docs, Commands, 2026].

| Added | Check |
|---|---|
| Skill | `/reload-skills`, `/skills` |
| Hook | `/hooks` |
| MCP server | `/mcp` |
| Plugin | `/reload-plugins` |

The failure mode: **Create-and-hope.** You create a file and assume it loaded.

The fix: Run the matching check command.

Cross-references: diagnostics are Module 14.1.

**If you remember one thing:** every file gets a check.
