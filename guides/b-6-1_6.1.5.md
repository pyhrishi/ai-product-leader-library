## 6.1.5.2 — READ IT AGAINST A TASK

**Framing.** A method that works for a short page: write one real task, read the opening table's Use it when column, and underline the single sentence that matches. Then read the three choosing questions and see whether they confirm or overturn it.

```text
Task:      migrate 300 test files from Jest to Vitest
Table row: Dynamic workflows - 'A job outgrows a handful of subagents ... 500-file migration'
Questions: coordinates = script; talk = no; same files = no (one worktree per unit)
Decision:  workflow or /batch; check with /workflows
```
[row quoted in shortened form from Claude Code docs, Run agents in parallel, 2026]

The failure mode: **Confirmation reading.** You read only the row you already wanted and never test it against the three questions.

The fix: After underlining your row, answer the three questions out loud; if one contradicts the row, reread the neighbouring approaches.

Cross-references: using /batch for such a job is sub-topic 6.5.5.

**If you remember one thing:** one underlined sentence per task.

## 6.1.5.3 — WHAT THE PAGE SAYS IS NOT

**Framing.** Three statements limit the approaches. In every approach the workers are Claude sessions, so another tool joins as an MCP server. Agent teams do not isolate teammates in worktrees. A routine runs a session on a schedule in the cloud, not in parallel on your machine [Claude Code docs, Run agents in parallel, 2026].

| Statement | Consequence |
|---|---|
| Workers are Claude sessions | To use a different tool, expose it as an MCP server (Module 5.5) |
| Agent teams do not use worktrees | Partition files across teammates yourself |
| A routine is not parallel on your machine | It is scheduled, cloud-run work |
| Agent view and subagents report to different places | Agent view sessions report only to you |

The failure mode: **Limit-skipping.** You assume agent teams isolate edits like dispatched agent-view sessions do, because both are 'parallel sessions'.

The fix: Read the not-statements and the Do the tasks touch the same files bullet before running anything that edits.

Cross-references: MCP integration is Module 5.5; team file ownership is sub-topic 6.4.5.

**If you remember one thing:** the limits are on the page; read them first.
