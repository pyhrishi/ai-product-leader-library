# MODULE 3.1.5 — MANAGING IT: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**Five levers manage the window: clear between tasks, compact with a focus, rewind and summarise part of a conversation, delegate reads to subagents, and ask side questions that leave no trace.**

**Prove-it, in one sentence:** run each lever once on a real session and record what it removed and what it cost.

**The single most important discipline: choose the lever by what you want to keep: nothing, a focused summary, a prefix, or only an answer.**

**The counterintuitive claim you will learn to defend:** `/compact` is itself a large request because it reads the whole conversation to summarise it, and more so once the cache has expired [Claude Code docs, Best practices, 2026].

**THE TIME BUDGET.** Reading time: ~22 minutes. Prove-it time: ~2 hours (120 minutes, 5.5 times the reading time).

## 3.1.5.1 — CLEAR AND COMPACT

**Framing.** `/clear` starts over: it costs nothing and stops the next task paying for the previous one's history; `/clear oauth-migration` names the session you are leaving so you can return [Claude Code docs, Best practices, 2026]. `/compact` with instructions, for example `/compact focus on the auth bug fix`, keeps what you choose instead of what the automatic pass guesses is important [Claude Code docs, Context window, 2026]. You can also add a 'Compact Instructions' section to CLAUDE.md [Claude Code docs, How Claude Code works, 2026].

| Lever | Keeps | Cost |
|---|---|---|
| `/clear` | Nothing (old session stays resumable) | Free |
| `/compact` | A structured summary | Large request; cheaper while cache is warm |
| `/compact focus on X` | Summary weighted to X | Same |

The failure mode: **Blind compaction.** You run bare `/compact` mid-task and the summary drops the detail you needed, such as the exact failing test command.

The fix: Pass a focus (`/compact keep the API changes and the test commands`) or add Compact Instructions to CLAUDE.md.

Cross-references: compaction internals are sub-topic 3.1.7 in Module 3.1; Compact Instructions text is Module 3.2.

**If you remember one thing:** tell compaction what to keep.

## 3.1.5.2 — REWIND AND SUMMARISE

**Framing.** `/rewind` (or double `Esc`) opens a menu where you can roll code, conversation or both back, and the same menu can summarise part of the conversation with **Summarize from here** or **Summarize up to here** [Claude Code docs, Context window; Best practices, 2026]. Rewinding truncates to a prefix that is already cached rather than building a new one as compaction does, so abandoning a path by rewinding is cache-friendly [Claude Code docs, Prompt caching, 2026].

```text
Turn 12 goes down a dead end
  /rewind -> pick turn 11 -> conversation truncated to a cached prefix
Or: /rewind -> Summarize from here   (compress the stale part only)
```

Checkpoints cover files edited with Claude's own file tools; a file touched only by a Bash command is not restored [Claude Code docs, Best practices, 2026].

The failure mode: **Rewind-overreach.** You rewind expecting every change undone, but a Bash command modified a file the checkpoint never tracked.

The fix: Check `git status` after a rewind and treat checkpoints as a complement to git, not a replacement.

Cross-references: checkpoints are Module 2.5.

**If you remember one thing:** rewind covers file-tool edits only.

## 3.1.5.3 — DELEGATE AND SIDE QUESTIONS

**Framing.** A subagent handles research in its own context window, so large file reads stay out of yours and only a summary and a small metadata trailer come back [Claude Code docs, Context window, 2026]. Subagents cost tokens because each sends its own requests, and a fresh one must gather context your conversation already had, so it can be slower than doing the task in place [Claude Code docs, Best practices, 2026]. `/btw` answers a quick question without adding anything to the history [Claude Code docs, Best practices, 2026].

| Situation | Lever |
|---|---|
| Switching to unrelated work | `/clear` |
| Same task, history noisy | `/compact focus ...` |
| Dead end 3 turns ago | `/rewind` |
| Need a survey of many files | Subagent |
| One quick factual question | `/btw` |

The failure mode: **Subagent-for-everything.** You spawn a subagent for a three-file question and pay for a fresh context rebuild that exceeds the cost of reading in place.

The fix: Delegate only large or noisy reads; ask for short summaries back.

Cross-references: subagent design is Module 5.3.

**If you remember one thing:** delegation has a rebuild cost.

## 3.1.5.4 — COST-AWARE TIMING

**Framing.** Pick model and effort at the top of a session, then save `/compact` for natural breaks between tasks; the fewer mid-task changes, the higher your cache hit rate [Claude Code docs, Prompt caching, 2026]. `/compact` costs the most when you resume an old session because the cache has expired and the summarisation reprocesses the full history as uncached input. If a 1-hour cache session past about 200K tokens sits idle, it can be compacted shortly before expiry, so you continue from a summary [Claude Code docs, Best practices, 2026].

| Timing | Cache effect |
|---|---|
| Compact mid-session, cache warm | Reads the prefix from cache; fraction of the size's cost |
| Compact after a long break | Full history reprocessed uncached |
| Rewind | Hits the earlier cached prefix |

The failure mode: **Cold-cache compact.** You return from lunch and run `/compact` on a huge session, paying full price for the summarisation request.

The fix: Compact at natural breaks while warm, or start fresh if you do not need the history.

Cross-references: cache lifetime is Module 3.4.

**If you remember one thing:** compact warm, not cold.
