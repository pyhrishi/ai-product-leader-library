## THE THESIS OF THIS TOPIC

**Mid-task commands are steering controls: they change mode, model, effort, context and completion criteria without leaving the session, and each has a cost you can predict.**

**Prove-it, in one sentence:** run one task using /plan, /context, /compact with a focus, /btw and /goal and say what each changed.

**The single most important discipline: check /context before reaching for /compact, and set a goal only when you have a check Claude can run.**

**The counterintuitive claim you will learn to defend:** changing the model or effort mid-session is not free: each model has its own prompt cache, so the first request after a switch re-reads the whole conversation uncached [Claude Code docs, Settings, 2026].

## 14.1.2.1 — MODE AND CAPABILITY: /PLAN, /MODEL, /EFFORT, /FAST, /ADVISOR

**Framing.** `/plan [description]` enters plan mode from the prompt and can start a task immediately, such as `/plan fix the auth bug`. `/model [model]` switches the model and saves it as the default for new sessions; press `s` on a picker row to switch for the current session only. `/effort` sets `low` to `xhigh`, `max` or `auto`, and `max` is session-only. `/fast [on|off]` toggles fast mode, and `/advisor [model|off]` enables a second model consulted at key moments [Claude Code docs, Commands, 2026].

| Command | Saves as default? | Note |
|---|---|---|
| `/model sonnet` | Yes | `s` in the picker is session-only |
| `/model` with `-p` | No | Applies to the current session only |
| `/effort max` | No | `max` is session-only |
| `/fast off` | n/a | Toggles mid-turn; the running turn keeps its speed |
| `/advisor off` | n/a | Accepts fable, opus, sonnet or a full ID; fable needs access |

The failure mode: **Silent-default-switch.** You switch model to test something and the choice is saved as your default, so tomorrow's sessions start on a model you never meant to keep.

The fix: Use the picker's `s` option for a session-only switch and check `/status` at the next launch.

Cross-references: model choice is Module 1.4; effort is Module 2.2.

**If you remember one thing:** decide whether a switch should persist before you confirm it.

## 14.1.2.2 — CONTEXT: /CONTEXT, /COMPACT, /BTW

**Framing.** `/context [all]` draws context usage as a coloured grid with suggestions for heavy tools and memory bloat; in fullscreen it collapses the per-item breakdown and `all` expands it. `/compact [instructions]` summarises the conversation and accepts focus text. `/btw [question]` asks a side question without adding to the conversation; with no question it shows your latest side question [Claude Code docs, Commands, 2026].

```text
/context                         # what is filling the window
/compact keep the migration plan and the failing test names
/btw what does the retry flag do?   # answer is not added to history
```

| Symptom | Command |
|---|---|
| Window filling | `/context`, then `/compact <focus>` |
| Tangent question | `/btw` |
| Task finished, new task | `/clear` |

The failure mode: **Compact-by-reflex.** You run `/compact` the moment answers feel slow without looking at `/context`, and the summary drops a constraint while the real bloat (a tool definition) stays.

The fix: Read `/context` first, remove the actual bloat, and pass focus text to `/compact` so the constraint survives.

Cross-references: context is Module 3.1; compaction survival is Module 1.2.4.

**If you remember one thing:** look before you compact.

## 14.1.2.3 — COMPLETION: /GOAL, /LOOP, /DIFF, /REWIND, /CLEAR, /RECAP

**Framing.** `/goal [condition|clear]` keeps Claude working across turns until the condition is met or the goal clears for another reason; `clear`, `stop`, `off`, `reset`, `none` or `cancel` removes it. `/loop [interval] [prompt]` repeats a prompt while the session stays open, self-pacing if you omit the interval. `/diff` reviews working-tree changes, `/rewind` restores a checkpoint (aliases `/checkpoint`, `/undo`), `/clear [name]` starts a new conversation (aliases `/reset`, `/new`) and `/recap` gives a one-line summary [Claude Code docs, Commands, 2026].

| Need | Command |
|---|---|
| Work until a check passes | `/goal all tests in test/auth pass` |
| Poll something | `/loop 5m check if the deploy finished` |
| See what changed | `/diff` |
| Undo code and/or conversation | `/rewind` |
| Name and archive the old run | `/clear auth-spike` |

The failure mode: **Unverifiable-goal.** You set a goal whose condition Claude cannot test, so the loop either stops on its own judgement or runs on.

The fix: Phrase the goal as a command and an expected output, such as a named test suite passing.

Cross-references: goals and loops are Module 6.7; rewind is Module 2.5.

**If you remember one thing:** a goal needs a check Claude can run.

| Command | Symptom | Observed |
|---|---|---|
| `/context` | Slow answers | MCP schemas biggest |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Model switched and forgotten | **Silent-default-switch** |
| `/compact` with no `/context` check | **Compact-by-reflex** |

## CLOSING REFRAME

This is the craft of steering a task: **right command, right moment, known cost.** The engineer who understands this does not ask "which command should I type?" — they ask "what symptom is this and what will the command cost?"
