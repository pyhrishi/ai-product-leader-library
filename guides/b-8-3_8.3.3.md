# MODULE 8.3.3 — EXTERNAL MCP SERVERS: TRANSPORTS, AUTHENTICATION, ERRORS: THE COMPLETE CRAFT

---

## THE THESIS OF THIS TOPIC

**An external MCP server is configured by transport, permitted by fully qualified tool names, authenticated by environment or headers, and trusted only after you read its status from the init message.**

**Prove-it, in one sentence:** connect a stdio and an HTTP server, authenticate one with a header, and make your CI fail when any server is failed or needs-auth.

**The single most important discipline: never trust a server because the run succeeded; read each server's status.**

**The counterintuitive claim you will learn to defend:** a server that fails to connect does not raise: the run continues without its tools, and Claude may fall back to built-in tools, so success does not mean the server worked [Agent SDK docs, Connect to external tools with MCP, 2026].

## 8.3.3.1 — TRANSPORTS AND WHERE TO CONFIGURE

**Framing.** Pick transport by what the server documents: a command to run means stdio, a URL means HTTP or SSE, tools in your own code mean an SDK server. Configure in code through mcpServers or in a .mcp.json file loaded through the project setting source [Agent SDK docs, Connect to external tools with MCP, 2026].

| Transport | Config shape | Notes |
|---|---|---|
| stdio | `{command, args, env}` | Local process |
| HTTP | `{type: "http", url, headers}` | Streamable HTTP; 'streamable-http' accepted only in JSON files |
| SSE | `{type: "sse", url, headers}` | Remote |
| SDK | createSdkMcpServer result | In-process |

[Agent SDK docs, Connect to external tools with MCP, 2026]. In .mcp.json, `${VAR}` expands environment variables. Tools are named mcp__<server>__<tool>; use `mcp__github__*` in allowedTools. Prefer allowedTools over permission modes: acceptEdits does not approve MCP tools and bypassPermissions is broader than needed.

The failure mode: **Silent skip.** A .mcp.json entry fails validation or settingSources omits project, and the server is never loaded while the run still succeeds.

The fix: Include the project source, and check init mcp_servers for every expected server.

Cross-references: settings sources are Module 8.2.4; custom servers are Module 8.3.2.

**If you remember one thing:** transport follows the docs: command is stdio, URL is HTTP or SSE.

## 8.3.3.2 — AUTHENTICATION

**Framing.** Pass credentials through env for stdio servers and headers for HTTP and SSE. The SDK does not open a browser or run an interactive OAuth flow; complete OAuth in your own application and pass the access token in headers [Agent SDK docs, Connect to external tools with MCP, 2026].

| Status | Meaning | What to do |
|---|---|---|
| needs-auth | No usable sign-in for the server | Pass a token in headers, or sign in from an interactive Claude Code session on the machine first |
| failed with 'Couldn't read the stored credentials' | Credential store unreadable | See the errors page; before Claude Code v2.1.307 a locked Mac keychain showed needs-auth |

[Agent SDK docs, Connect to external tools with MCP, 2026]. In either case the run continues without that server's tools. Poll mcpServerStatus() (TypeScript) or get_mcp_status() (Python).

The failure mode: **Expired bearer.** A short-lived access token placed in headers expires mid-run and the server flips to needs-auth while the agent keeps going.

The fix: Refresh tokens in your app and check status before long runs; reconnect with reconnectMcpServer.

Cross-references: secret handling is Module 8.7.4.

**If you remember one thing:** the SDK carries your token; it does not fetch one.

## 8.3.3.3 — CONNECTION TIMING AND STATUSES

**Framing.** Claude Code starts connecting at session start. stdio and uncached HTTP/SSE servers in mcpServers delay the first turn until they connect, up to MCP_TIMEOUT (30 seconds by default). Statuses are pending, connected, failed, needs-auth and disabled [Agent SDK docs, Connect to external tools with MCP, 2026].

| Setting | Effect |
|---|---|
| MCP_TIMEOUT | Connection limit in ms; default 30 seconds |
| MCP_TOOL_TIMEOUT | How long a tool call may run |
| CLAUDE_CODE_MCP_STARTUP_WAIT_MS | First-turn wait; needs Claude Code v2.1.274 or later; 0 skips waiting for most servers |
| MCP_CONNECTION_NONBLOCKING=0 | Startup waits up to 5 seconds by default for the batch |
| alwaysLoad: true | Startup waits for that server's tools and exempts it from deferral |

[Agent SDK docs, Connect to external tools with MCP, 2026]. Pending is not failure: it can mean not connected yet, served from a cached tool list, or an expired deadline. After five failed reconnection attempts a dropped remote server reports failed.

The failure mode: **Pending-as-failed.** Your gate treats pending at init as failure and blocks healthy runs whose servers use a cached tool list.

The fix: Fail on failed or needs-auth at init, and re-check pending servers later with the status call.

Cross-references: failure handling is Module 8.7.5.

**If you remember one thing:** pending is a question, not an answer.

## 8.3.3.4 — OUTPUT LIMITS AND SAFE USE

**Framing.** MCP output beyond a limit is saved to a file: a successful result over 25,000 tokens with no image is replaced by an error naming the file path, and a text result over 50,000 characters is saved regardless of the token limit unless the tool declares anthropic/maxResultSizeChars. MAX_MCP_OUTPUT_TOKENS changes the token limit [Agent SDK docs, Connect to external tools with MCP, 2026].

| Risk | Control |
|---|---|
| SQL tool runs writes | Server-side read-only (the docs' DBHub example sets readonly = true) |
| Broad permission | Allow specific tools, not the whole server, when only one is needed |
| Large output | Paginate in the server; raise MAX_MCP_OUTPUT_TOKENS only deliberately |
| Server missing at startup | Check status, because Claude can fall back to built-ins |

[Agent SDK docs, Connect to external tools with MCP, 2026]. The read-only control belongs in the server, not in the prompt.

The failure mode: **Prompt-only read-only.** You tell the agent 'do not write' while the database tool accepts writes.

The fix: Enforce read-only in the server configuration.

Cross-references: tool design is Module 8.3.6; secure deployment is Module 8.7.4.

**If you remember one thing:** enforce limits where the data lives.
