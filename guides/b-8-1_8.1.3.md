# MODULE 8.1.3 — WHEN TO CHOOSE THE SDK: THE COMPLETE CRAFT

---

## THE THESIS OF THIS TOPIC

**Choose the Agent SDK when you want Claude Code's built-in tools, context management, sessions, permissions and hooks inside a process you operate, and choose something else when you do not need that harness or do not want to run it.**

**Prove-it, in one sentence:** produce a decision record for one real workload that names the chosen option, two rejected options with reasons, and the cost you accept.

**The single most important discipline: count what you would have to rebuild before you count what you would save.**

**The counterintuitive claim you will learn to defend:** the best reason to pick the SDK is what you refuse to write, and the best reason to refuse it is also what you refuse to run: the SDK means you operate a process and a binary [Agent SDK docs, Overview, 2026].

## 8.1.3.1 — WHAT THE HARNESS GIVES YOU

**Framing.** The SDK's value is the harness it inherits: tools, loop, context management, permissions, sessions and hooks [Agent SDK docs, Overview, 2026]. With the Client SDK, you write the tool loop yourself, or use the beta tool runner [Agent SDK docs, Overview, 2026].

| Concern | Agent SDK | Client SDK |
|---|---|---|
| Tool loop | Provided | You write it (or tool runner) |
| File, shell, search tools | Built in | You implement |
| Context compaction | Automatic; PreCompact hook | You build |
| Permissions | Modes, allow/deny rules, callback | You build |
| Sessions | Resume, continue, fork | You build |
| Hooks | Lifecycle callbacks | You build |

Compaction and tool lists: [Agent SDK docs, How the agent loop works, 2026]. Rows for sessions and hooks: [Agent SDK docs, Overview, 2026]. 'You build' reflects the docs' description that you write the loop; it is not a line-by-line comparison.

The failure mode: **Rebuild blindness.** You choose the Client SDK for control and then spend weeks recreating file tools, permission prompts and compaction that the SDK already had.

The fix: List the six concerns above, estimate each, and pick the SDK unless the list is empty.

Cross-references: the loop internals are Module 8.2.1; Part 4.3 of the AI curriculum covers tool-loop design for the Client SDK route.

**If you remember one thing:** the SDK is chosen by the code you will not write.

## 8.1.3.2 — WHEN THE SDK IS THE WRONG LAYER

**Framing.** Three situations point away: the work is interactive and personal, you do not want to operate a process, or you only need one model call.

| Situation | Better fit | Reason |
|---|---|---|
| Interactive terminal work | CLI | Built for daily interactive use [Overview] |
| A single prompt with schema output from a shell script | `claude -p` with --json-schema | Same engine, no code [Headless page] |
| No process to operate; Anthropic should host | Managed Agents | Hosted harness [Overview] |
| One model call, no tools | Client SDK | No loop needed |
| A language other than Python or TypeScript | CLI as subprocess with -p | Documented route [Overview] |

Sources: [Agent SDK docs, Overview, 2026] and [Claude Code docs, Run Claude Code programmatically, 2026]. The no-tools row is a judgement, not a quote.

The failure mode: **Harness for a prompt.** You stand up a subprocess-driven agent service for a task that is one model call with a schema.

The fix: Use the Client SDK or `claude -p --json-schema` for single-shot extraction, and reserve the SDK for multi-step tool use.

Cross-references: Managed Agents is outside this volume; hosting trade-offs are Module 8.7.

**If you remember one thing:** if there is no loop, there is no reason to buy the harness.

## 8.1.3.3 — OPERATING COST OF CHOOSING THE SDK

**Framing.** Choosing the SDK means you operate a process. The agent loop page says that the loop can run long on open-ended prompts and that a budget is a good default for production agents [Agent SDK docs, How the agent loop works, 2026].

| Operating item | What to decide | Source |
|---|---|---|
| Limits | `max_turns` and `max_budget_usd`; default no limit | Agent loop |
| Auth | API key or cloud provider; not claude.ai login | Quickstart |
| Isolation | `settingSources: []` for CI, multi-tenant, deployed apps | Migration guide |
| Permissions | A mode, rules, or a callback | Agent loop |
| Billing | Costs are client-side estimates; reconcile with the console | Headless page |

Sources: [Agent SDK docs, How the agent loop works, 2026]; [Agent SDK docs, Migration guide, 2026]; [Claude Code docs, Run Claude Code programmatically, 2026].

The failure mode: **Unbounded launch.** You deploy an open-ended agent with no turn or budget limit and a surprise bill is your first signal.

The fix: Set max turns and a max budget in the launch checklist, and branch on both error subtypes.

Cross-references: cost tracking is Module 8.6.3; failure handling is Module 8.7.5.

**If you remember one thing:** choose the SDK with the limits already written.

## 8.1.3.4 — THE DECISION RULE IN PRACTICE

**Framing.** A decision record forces the reasoning into one page. This guide's rule is: pick the highest layer that does not hide something you must control.

```text
Workload: nightly dependency-update PRs
Loop needs files, shell, tests, retries        -> harness wanted
We can operate a container per run             -> SDK OK
Verifiable by `npm test`                       -> good agent candidate
Rejected: Client SDK (rebuild tools), Managed Agents (data must stay on our infra)
Accepted cost: we own the container and the key
Exit criterion: if pass rate < target after 4 weeks, revisit
```
Module 8.8.3 states the product rule: repetitive and verifiable work with a good check is a strong candidate. The target pass rate is yours to set; no benchmark is claimed here.

The failure mode: **Unrecorded choice.** The reason for choosing the SDK lives in one person's head, and a later owner moves the work to a different layer without knowing what was traded.

The fix: Write the decision record with rejected options and the exit criterion, and keep it next to the code.

Cross-references: product fit is Module 8.8; evals are Module 8.6.5.

**If you remember one thing:** write the rejected options down.
