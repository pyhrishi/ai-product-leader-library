## THE THESIS OF THIS TOPIC

**A runbook saved as a skill gives Claude your on-call procedure on demand, and `disable-model-invocation: true` keeps side-effecting steps behind a human typing the command.**

**Prove-it, in one sentence:** write one runbook skill with a safe read-only diagnosis and a gated action and show both invocation modes.

**The single most important discipline: diagnosis can be automatic; actions with side effects are manual.**

**The counterintuitive claim you will learn to defend:** a runbook in a wiki is read by humans under stress; the same runbook as a skill is executed consistently and costs almost no context until it is needed.

## 9.3.6.1 — WHAT A SKILL IS

**Framing.** A skill is a procedure or piece of team knowledge saved at `.claude/skills/<name>/SKILL.md`. For a skill Claude can start on its own, Claude sees the name and description in every session and reads the full file only when the task calls for it; so a long procedure does not weigh on unrelated work like a CLAUDE.md entry would [Claude Code docs, Best practices, 2026].

| Frontmatter field | Use for runbooks |
|---|---|
| `name` | Command name, e.g. `db-failover` |
| `description` | When to use; put key use case first (combined `description` and `when_to_use` truncated at 1,536 characters) |
| `disable-model-invocation: true` | Claude cannot start it; you type `/name` |
| `allowed-tools` | Tools usable without asking during the turn |
| `context: fork` | Run in a forked subagent |
| `paths` | Limit automatic activation to matching files |

Keep `SKILL.md` under 500 lines; move reference material into separate files [Claude Code docs, Skills, 2026].

The failure mode: **Description overflow.** The key trigger sits past character 1,536 of description and when_to_use, so Claude never matches the skill to an incident.

The fix: Put the key use case first and keep the combined text short.

Cross-references: skills are Module 5.2.

**If you remember one thing:** front-load the trigger.

## 9.3.6.2 — SPLIT DIAGNOSIS FROM ACTION

**Framing.** The docs' release example uses `disable-model-invocation: true` for a workflow with side effects, so it runs only when you type `/release` [Claude Code docs, Best practices, 2026]. Apply that to remediation steps.

```markdown
---
name: api-5xx-diagnose
description: Diagnose a spike in API 5xx errors. Read-only: queries logs and dashboards, never changes anything.
allowed-tools: Read, Grep
---
1. Ask for the time window.
2. Query error rate and top error classes through the monitoring MCP.
3. Map the top class to code; check git log for recent changes.
4. Report hypothesis and evidence. Stop.
```

```markdown
---
name: api-rollback
description: Roll back the API to the previous release.
disable-model-invocation: true
---
1. Confirm the target version with the user.
2. ... (steps) ...
```

The failure mode: **Auto-fired remediation.** The rollback skill can be started by Claude, so a hallucinated diagnosis triggers a production change.

The fix: Set `disable-model-invocation: true` on every skill with side effects.

Cross-references: production safety is Module 9.3.7.

**If you remember one thing:** automatic diagnosis, manual action.

## 9.3.6.3 — LIFECYCLE AND MAINTENANCE

**Framing.** Invoked skill content enters the conversation as one message and stays across later turns; `allowed-tools` grants clear on your next message; after auto-compaction the most recent invocation of each skill is re-attached, first 5,000 tokens each, within a combined 25,000-token budget [Claude Code docs, Skills, 2026].

| Fact | Implication |
|---|---|
| Content stays in context | Do not invoke needlessly mid-session |
| allowed-tools grant clears | Re-invoke or approve again next turn |
| 5,000 tokens kept per skill after compaction | Put critical steps first |
| 25,000-token shared budget | Older skills may drop |

The failure mode: **Stale runbook.** The procedure no longer matches infrastructure and Claude follows it faithfully into an error.

The fix: Review the skill after every incident and date its last verification.

Cross-references: learning loop is Module 9.12.9.

**If you remember one thing:** a runbook is code; maintain it.

## CLOSING REFRAME

This is the craft of runbook skills: **front-loaded triggers, split diagnosis from action, maintained like code.** The engineer who understands this does not ask "where is the runbook?" — they ask "which steps may Claude start by itself?"
