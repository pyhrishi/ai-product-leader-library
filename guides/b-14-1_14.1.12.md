## 14.1.12.1 — BEDROCK AND VERTEX WIZARDS

**Framing.** `/setup-bedrock` configures Amazon Bedrock authentication, region and model pins through a wizard and is hidden until `CLAUDE_CODE_USE_BEDROCK=1` is set; `/setup-vertex` does the same for Google Cloud's Agent Platform with `CLAUDE_CODE_USE_VERTEX=1`; both must be typed in full [Claude Code docs, Commands, 2026].

```bash
CLAUDE_CODE_USE_BEDROCK=1 claude     # then type /setup-bedrock in full
```

| Command | Hidden until | Configures |
|---|---|---|
| `/setup-bedrock` | `CLAUDE_CODE_USE_BEDROCK=1` | Auth, region, model pins |
| `/setup-vertex` | `CLAUDE_CODE_USE_VERTEX=1` | Auth, project, region, model pins |

The failure mode: **Missing-command-panic.** You cannot find `/setup-bedrock` in the menu and conclude your version lacks it.

The fix: Set the provider variable and type the command in full.

Cross-references: providers are Module 10.2.

**If you remember one thing:** hidden is not absent.

## 14.1.12.2 — CLOUD SESSIONS FROM THE CLI

**Framing.** `/remote-env` chooses the default cloud environment for cloud sessions started from the CLI. `/web-setup` connects your GitHub account for cloud sessions using your local `gh` CLI credentials [Claude Code docs, Commands, 2026].

| Command | Does |
|---|---|
| `/remote-env` | Pick the default cloud environment |
| `/web-setup` | Connect GitHub via local `gh` credentials |

The failure mode: **Credential-reuse-surprise.** You run `/web-setup` without realising it reuses your local `gh` credentials, which may be broader than the cloud task needs.

The fix: Check the `gh` token scope first and use a narrower account if required.

Cross-references: cloud sessions are Module 6.3; security is Module 11.1.

**If you remember one thing:** know whose credentials it uses.

## 14.1.12.3 — TEAM DOCUMENTATION

**Framing.** A team guide should state the variable, the command, the model pins chosen and the verification, because the wizard output is per user. Environment variables for providers are listed in the environment variable reference (see Module 14.6).

| Doc line | Example |
|---|---|
| Switch | `CLAUDE_CODE_USE_BEDROCK=1` |
| Command | `/setup-bedrock` |
| Verification | One request succeeds; `/status` shows provider |

The failure mode: **Undocumented-pin.** Model pins chosen in the wizard are never recorded, so a teammate runs a different model.

The fix: Write the pins into the team guide and check `/status`.

Cross-references: settings are Module 4.1.

**If you remember one thing:** record the pins.
