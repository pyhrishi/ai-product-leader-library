## THE THESIS OF THIS TOPIC

**You can set how full the window gets before automatic compaction runs, in several places with a strict precedence, and the defaults depend on the model.**

**Prove-it, in one sentence:** set the window three ways and show which one wins.

## 3.1.6.1 — THE FOUR CONTROLS

**Framing.** `/autocompact` saves a window per model in user settings under `modelSettings` (before v2.1.288 it saved one window for all models); the `autoCompactWindow` setting applies to every model; the `--autocompact` flag applies to one launch; `CLAUDE_CODE_AUTO_COMPACT_WINDOW` is for scripts and cloud environments [Claude Code docs, Model configuration, 2026]. `/autocompact auto` returns to the window tuned for your model.

| Control | Scope | Persists? |
|---|---|---|
| `/autocompact 500k` | Current model | Yes, saved per model |
| `autoCompactWindow` setting | Every model | Yes |
| `claude --autocompact auto` | One launch | No |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | Environment | Per environment |

The failure mode: **Scattered-setting.** You set the window in settings, a flag and an environment variable at different times and cannot tell which is active.

The fix: Set one control per environment and confirm with `/autocompact`, which reports an environment override without saving.

Cross-references: settings layering is Module 4.1.

**If you remember one thing:** one control, verified.

## 3.1.6.2 — PRECEDENCE AND ACCEPTED VALUES

**Framing.** The environment variable takes precedence over the command, the flag and the setting; a window saved for a model with `/autocompact` beats `autoCompactWindow` for that model; the `--autocompact` flag is not preempted by a higher-priority scope such as managed settings, unlike `/autocompact` [Claude Code docs, Model configuration, 2026]. Accepted `/autocompact` and `--autocompact` values range from 100K to 1M tokens: a plain count, a `k` or `M` suffix, or a bare number from 100 to 1000 meaning thousands. Claude Code caps any window at the model's context window.

| Input | Meaning |
|---|---|
| `200000` | 200,000 tokens |
| `500k`, `1M` | 500,000; 1,000,000 |
| `200` to `/autocompact` | 200,000 tokens |
| `200` in the env var | 200 tokens, and a warning |
| `200k` in the env var | 200,000 (v2.1.304 or later) |

The failure mode: **Unit-trap.** You export `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200` meaning 200K and the window becomes 200 tokens.

The fix: Write the suffix (`200k`) in the environment variable on v2.1.304 or later, or the full count.

Cross-references: environment variables are Module 4.1.

**If you remember one thing:** check the suffix, then the version.

## 3.1.6.3 — DEFAULT THRESHOLDS

**Framing.** With no window set, Claude Code compacts when the conversation reaches the model's context limit, except: cloud sessions compact as the conversation approaches the limit; Sonnet 4.6 and Opus 4.6 without extended context compact at the 200K boundary; with `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`, models with a native 1M window compact at the 200K boundary; native 1M models otherwise compact before the window fills, at about 967K tokens by default [Claude Code docs, Model configuration, 2026]. The page read was truncated before its full threshold table, so confirm per-model rows on the page.

| Situation | Compacts at |
|---|---|
| Native 1M model, default | About 967K tokens |
| Sonnet 4.6 / Opus 4.6 without `[1m]` | 200K boundary |
| 1M disabled by env var | 200K boundary |
| Unrecognised gateway model ID | Assumed 200K window |

The failure mode: **Threshold-assumption.** You assume compaction fires at 80 percent because another tool does, when the documented default for a native 1M model is about 967K tokens.

The fix: Read the default-thresholds table for your model, then decide whether to lower the window.

Cross-references: model choice is Module 2.6.

**If you remember one thing:** defaults are per model.

## 3.1.6.4 — GATEWAYS AND CUSTOM MODEL IDS

**Framing.** Claude Code warns when it does not recognise a model ID and assumes a 200K window, auto-compacting at the assumed 200K [Claude Code docs, Model configuration, 2026]. Remedies include `claude update`, a `modelOverrides` entry, appending `[1m]` for a 1M model, or `CLAUDE_CODE_MAX_CONTEXT_TOKENS` for another window. For an unrecognised ID, `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1` makes Claude Code compact only after the API rejects the conversation as too long.

| Symptom | Fix |
|---|---|
| 'context assumed to be 200k tokens' warning | `claude update`, `[1m]`, `modelOverrides`, or `CLAUDE_CODE_MAX_CONTEXT_TOKENS` |
| Gateway rewrites too-long error | Recovery will not run |

The failure mode: **Gateway-window mismatch.** Behind a gateway alias, Claude Code assumes 200K and compacts a 1M model early, wasting its window.

The fix: Correct the window with the documented remedy for your ID type and confirm the warning disappears.

Cross-references: gateway setup is Module 8.2.

**If you remember one thing:** tell Claude Code the real window.
