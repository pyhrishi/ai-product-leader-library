## 1.4.5.1 — THE FIVE HABITS

**Framing.** The syllabus lists five habits and the mechanism behind them is shared: fewer tokens per turn and fewer wasted turns [syllabus Module 1.4.5; Claude Code docs, Best practices, Context window and Costs, 2026].

| Habit | Why it works | Practice |
|---|---|---|
| Clear between tasks | Stops re-reading irrelevant history | `/clear` |
| Scope searches | Limits what lands in context | "Search `src/payments/` for X" |
| Subagents for exploration | Keeps big reads out of the main window | Accept the summary |
| Right model for the step | No depth bought for mechanical work | `/model`, subagent `model:` |
| Watch `/context` | Makes bloat visible early | Check at task boundaries |

The failure mode: **Kitchen-sink session.** One session carries a feature, a bug fix and a docs edit, so every turn re-reads all three.

The fix: One task per session, `/clear` between tasks, `/compact` with a focus when a long task must continue.

Cross-references: context is Module 3.1; subagents are Module 1.2.5.

**If you remember one thing:** one task, one session.

## 1.4.5.2 — SCOPING AND DELEGATION

**Framing.** Open-ended exploration fills the window. Name a directory, a symptom and a stopping condition, or delegate to a subagent and keep only the summary.

```text
Weak:  "Investigate why this is slow."
Strong: "In src/checkout/, find why submitOrder takes >2s. Profile with
         `npm run bench`. Stop after naming the top two causes."
```

The failure mode: **Unscoped exploration.** 'Investigate why this is slow' with no boundary makes Claude read dozens of files and fill the window.

The fix: Name the directory, symptom and stopping condition, or delegate to a subagent.

Cross-references: prompting is Module 2.2; large codebases are Module 3.5.

**If you remember one thing:** a boundary and a stop condition.

## 1.4.5.3 — COMPACTION AND TOOL OUTPUT

**Framing.** `/compact focus on the auth bug fix` yields a summary biased to what you still need [Claude Code docs, Context window, 2026]. MCP tool schemas are deferred, so idle servers cost little. Preprocessing hooks can trim noisy tool output before it reaches the model. After more than two failed corrections, `/clear` and rewrite the prompt [Claude Code docs, Best practices, 2026].

| Lever | Effect |
|---|---|
| `/compact focus on ...` | Keeps what you still need |
| Pipe noisy output to a file | Keeps the window small |
| Trimming hook | Removes noise before the model reads it |
| `/clear` after two failed corrections | Drops failed attempts |

The failure mode: **Output flood.** A test run or log dump fills context and degrades later answers.

The fix: Pipe to a file and read the tail, or trim with a hook.

Cross-references: hooks are Module 1.2.6; context hygiene is Module 1.2.4.

**If you remember one thing:** trim what the model must read.

## 1.4.5.4 — MEASURE ONE CHANGE AT A TIME

**Framing.** A rough ranking by judgement, not measured data: clearing between tasks and scoping searches usually matter most; model choice matters most on subagent-heavy work; effort matters most on reasoning-heavy work.

| Change | Before | After | Verdict |
|---|---|---|---|
| (one change) | `/usage`, `/context` | `/usage`, `/context` | Kept or dropped |

The failure mode: **Optimising blind.** You apply every tip at once and cannot say which helped.

The fix: Read `/usage` and `/context` before and after one change at a time and keep a two-line log.

Cross-references: usage reading is Module 1.4.1.

**If you remember one thing:** one change, two readings, one line.
