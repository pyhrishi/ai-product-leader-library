# MODULE 5.1.8 — CONTEXT COSTS: THE COMPLETE CRAFT

---

## THE THESIS OF THIS TOPIC

**Every extension spends some of Claude's context, each in a different way, so a setup is judged by what it loads at start and on every request, not by how many features it has.**

**Prove-it, in one sentence:** measure your setup with /context and trim one item without losing a needed capability.

**The single most important discipline: treat context as a budget and ask what each feature costs on every request.**

**The counterintuitive claim you will learn to defend:** too much configuration does not just fill the window; it adds noise that makes Claude less effective, so skills may not trigger and conventions may be lost [Claude Code docs, Extend Claude Code, 2026].

**THE TIME BUDGET.** Reading time: ~22 minutes. Prove-it time: ~2 hours (120 minutes, 5.5 times the reading time).

## 5.1.8.1 — THE COST TABLE

**Framing.** The docs give each feature a loading strategy and a cost [Claude Code docs, Extend Claude Code, 2026].

| Feature | When it loads | What loads | Cost |
|---|---|---|---|
| CLAUDE.md | Session start | Full content | Every request |
| Output styles | Session start, and on switch | Active style's instructions (nothing for Default) | Every request |
| Skills | Session start, and when used | Descriptions at start; full content when used | Low (descriptions every request) |
| MCP servers | Session start | Tool names; full schemas on demand | Low until a tool is used |
| Code intelligence | After edits, on demand | Diagnostics; symbol locations | Low; can reduce file reads |
| Subagents | When spawned | Fresh context with specified skills (or the parent conversation for a fork) | Isolated from main session |
| Hooks | On trigger | Nothing | Zero unless output is returned |

The failure mode: **Free-feature assumption.** You treat skills and MCP servers as free because they load on demand, then add forty skills whose descriptions all load every request.

The fix: Count descriptions and tool names as a standing cost and prune with `/skill-doctor` and `/context`.

Cross-references: context windows are Module 3.1; managing sessions is Module 2.4.

**If you remember one thing:** descriptions and names are a standing cost.

## 5.1.8.2 — WHAT YOU CAN SWITCH OFF

**Framing.** Setting `disable-model-invocation: true` in a skill keeps its description out of Claude's context, so a user-only skill costs nothing until invoked; for a skill you did not write, `skillOverrides` in settings does the same [Claude Code docs, Extend Claude Code, 2026]. The skills page adds that the listing has a budget of 1% of the model's context window, descriptions are dropped starting from least-invoked skills when it overflows, and each entry's combined `description` and `when_to_use` is capped at 1,536 characters [Claude Code docs, Skills, 2026].

| Knob | Effect |
|---|---|
| `disable-model-invocation: true` | Description not loaded; you invoke manually |
| `skillOverrides` set to `"name-only"` | Listed without description |
| `skillListingBudgetFraction` | Raises or lowers the 1% listing budget |
| `/doctor` | Estimates listing cost and biggest contributors |
| `/context all` | Shows tokens per loaded MCP tool |

The failure mode: **Silent description loss.** You install many skills and the listing overflows, so Claude Code drops descriptions and the skills you rarely use stop matching without any error.

The fix: Run `/doctor`, trim or hide low-value skills and put the key use case first in each description.

Cross-references: skill management is sub-topic 5.2.9.

**If you remember one thing:** overflow removes descriptions, not names.

## 5.1.8.3 — ISOLATION AND ZERO-COST FEATURES

**Framing.** Subagents run in fresh context and the docs say their isolation keeps your main session lean; hooks cost nothing unless they return output [Claude Code docs, Extend Claude Code, 2026]. Code intelligence is described as low cost because symbol lookups often replace broad file reads, so net context can go down.

| If you want to cut cost, prefer | Because |
|---|---|
| Subagent for noisy side tasks | Work stays out of the main window |
| Hook for side effects | Nothing loads |
| Code intelligence plugin in typed codebases | Lookups replace file reads |
| `/mcp` disconnect for idle servers | Fewer tool names loaded |

The failure mode: **Chatty hook.** A hook prints a long report on every tool call and that output becomes messages in your conversation, defeating the zero-cost property.

The fix: Return output only when action is needed; log elsewhere.

Cross-references: hooks are Module 5.4; code intelligence is Module 5.8.

**If you remember one thing:** isolation and silence are the cheapest features.
