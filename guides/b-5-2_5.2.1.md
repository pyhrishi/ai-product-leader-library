# MODULE 5.2.1 — WHAT A SKILL IS: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**A skill is a directory with a SKILL.md file whose body enters context only when used, and slash commands are now part of the same system.**

**Prove-it, in one sentence:** create a skill, run it by name and by automatic match, and show the same procedure no longer needs pasting.

**The single most important discipline: create a skill when you keep pasting the same instructions or a CLAUDE.md section has grown into a procedure.**

**The counterintuitive claim you will learn to defend:** a skill is not loaded at session start: its description is, and its body only when used, which is what separates it from CLAUDE.md [Claude Code docs, Skills, 2026].

## 5.2.1.1 — ANATOMY

**Framing.** A skill is a directory containing a `SKILL.md` file. The file has two parts: YAML frontmatter between `---` markers and markdown instructions; the frontmatter `description` helps Claude decide when to load the skill [Claude Code docs, Skills, 2026].

```text
~/.claude/skills/summarize-changes/
  SKILL.md        <- frontmatter + instructions
```

```yaml
---
description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed, wants a commit message, or asks to review their diff.
---

## Current changes

!`git diff HEAD`

## Instructions
Summarize the changes above in two or three bullet points...
```
[Claude Code docs, Skills, 2026; example abridged]

The `!` line is dynamic context injection: Claude Code runs the command and inlines its output before Claude sees the skill.

The failure mode: **Body-in-description.** The whole procedure is crammed into the `description` line, which is truncated in the listing, so the real steps are cut or never load.

The fix: Keep the description to what and when; put the procedure in the body.

Cross-references: the folder and location rules are sub-topic 5.2.2; frontmatter is sub-topic 5.2.3.

**If you remember one thing:** a skill is a folder with SKILL.md; description decides loading, body does the work.

## 5.2.1.2 — COMMANDS BECAME SKILLS

**Framing.** Custom commands have been merged into skills: `.claude/commands/deploy.md` and `.claude/skills/deploy/SKILL.md` both create `/deploy`, existing command files keep working, and skills add a directory for supporting files, frontmatter controlling invocation, and automatic loading [Claude Code docs, Skills, 2026]. If a skill and a command file share a name, the skill wins [Claude Code docs, Skills, 2026].

| Old | New | Difference |
|---|---|---|
| `.claude/commands/deploy.md` | `.claude/skills/deploy/SKILL.md` | Skill adds supporting files, invocation control, auto-loading |
| Typing the command | Typing `/deploy` or letting Claude match | Both work for skills |

The Agent Skills open standard underlies this; Claude Code extends it with invocation control, subagent execution and dynamic context injection [Claude Code docs, Skills, 2026].

The failure mode: **Command-file inertia.** You keep adding commands as flat files and never gain supporting files or invocation control, then wonder why Claude never picks them up on its own.

The fix: Move the command into a skill directory and add a description Claude can match.

Cross-references: the bundled list is sub-topic 5.2.8.

**If you remember one thing:** slash commands are skills with fewer features.

## 5.2.1.3 — BODY LOADS ONLY WHEN USED

**Framing.** Unlike CLAUDE.md content, a skill's body loads only when used. Once invoked, its rendered SKILL.md enters the conversation as one message and stays across later turns; Claude Code does not re-read the file, so the docs advise standing instructions rather than one-time steps [Claude Code docs, Skills, 2026].

| Moment | In context |
|---|---|
| Session start | Name and description |
| Invoked (by you or Claude) | Full rendered body, as one message |
| Later turns | Same message; file not re-read |
| After auto-compaction | First 5,000 tokens of each recent skill, within a combined 25,000 |

[Claude Code docs, Skills, 2026]

The failure mode: **One-time-step wording.** A skill says 'run the tests' once, in a step list, and Claude treats it as a single action, not a rule for the rest of the session.

The fix: Write standing instructions such as 'run the tests after every edit' when the rule should persist.

Cross-references: compaction detail is sub-topic 5.2.12; context cost is sub-topic 5.1.8.

**If you remember one thing:** a skill is invoked once and then lives in the conversation.

## THE PROVE-IT SECTION

**Deliverable.** A working personal skill, plus a transcript of it running by slash name and by automatic loading.

**Close this topic. Build the artifact below from memory. Return to the text only after your first attempt is complete.**

| Step | Action | Output |
|---|---|---|
| 1 | Pick a procedure you pasted at least twice | Procedure text |
| 2 | Create `~/.claude/skills/<name>/SKILL.md` | File |
| 3 | Write what-and-when description | Description |
| 4 | Run it with `/<name>` | Transcript A |
| 5 | Ask for the task in plain words and see if it loads | Transcript B |
| 6 | Edit the wording to standing instructions and rerun | Revised file |

**A passing artifact looks like this:**

| Check | Result |
|---|---|
| `/summarize-changes` runs | Yes |
| Plain-language request loads it | Yes, description matched |
| Body is standing instructions | Yes |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Steps in `description` | **Body-in-description** |
| Only slash-invocation tested | Auto-loading unproven |

**The verdict.** The artifact passes only if the skill ran both by slash name and by automatic match.
