## 1.2.5.1 — WHAT A SUBAGENT IS

**Framing.** A subagent is a specialised assistant that runs in its own context window with a custom system prompt, specific tool access and independent permissions. Claude delegates to it when a task matches its description; it works independently and returns a summary, so verbose output stays out of your main conversation [Claude Code docs, Subagents, 2026].

| Fact | Detail |
|---|---|
| Starts fresh | No conversation history and no files already read |
| Initial context | System prompt, delegation message, CLAUDE.md, git status snapshot (not for Explore and Plan) |
| Fork | The exception: inherits the parent conversation |
| Scope | Stays inside the session that spawned it |
| Counts toward limits | Yes, the same usage limits |

[Claude Code docs, Subagents and Glossary, 2026]

The failure mode: **Context-blind delegation.** The subagent starts fresh and answers a question missing the key constraint.

The fix: Put every constraint, path and success criterion in the delegation message, or use a fork.

Cross-references: subagent design is Module 5.3; context behaviour is Module 1.2.4.

**If you remember one thing:** a subagent is a clean desk with only what you hand it.

## 1.2.5.2 — BUILT-INS, LIMITS AND BACKGROUND MODE

**Framing.** Claude Code ships built-in subagents and sets defaults on nesting and concurrency [Claude Code docs, Subagents, 2026].

| Built-in | Purpose |
|---|---|
| Explore | Fast read-only codebase search; Write and Edit denied; quick, medium or very thorough |
| Plan | Read-only research during plan mode |
| General-purpose | Multi-step tasks with exploration and action; all subagent tools |
| statusline-setup, claude-code-guide | Helpers for `/statusline` and feature questions |

| Limit | Default | Change with |
|---|---|---|
| Nesting depth | 3 layers below the main conversation | `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (1 turns nesting off) |
| Concurrent subagents | 20 | `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (v2.1.217+) |
| Description size warning | 15,000 tokens combined for non-built-in subagents | Keep descriptions short |

Subagents that Claude spawns from the main conversation start in the background by default; permission prompts surface in your main session; press `Ctrl+B` to background a waiting task [Claude Code docs, Subagents, 2026]. To block a built-in type add `Agent(Explore)` to `permissions.deny`.

The failure mode: **Subagent sprawl.** You spawn many subagents for small tasks, each rebuilding context, and usage climbs with no better results.

The fix: Delegate only large, read-heavy, summarisable work and keep small edits in the main session.

Cross-references: parallel approaches are Module 6.1; background sessions are Module 6.3; usage limits are Module 1.4.

**If you remember one thing:** 20 concurrent and 3 deep are defaults, not goals.

## 1.2.5.3 — A CUSTOM SUBAGENT

**Framing.** A subagent is a Markdown file with frontmatter. Scope it with the tools field and pick a cheaper model for search work [Claude Code docs, Subagents, 2026].

```markdown
---
name: code-improver
description: Scans files and suggests improvements for readability, performance, and best practices. Use after writing or modifying code.
tools: Read, Grep, Glob
model: sonnet
---
You are a code improvement specialist. For each issue you find, explain the problem,
show the current code, and provide an improved version.
```

Scope priority when names collide, highest first: managed settings, `--agents` CLI flag, `.claude/agents/` (project), `~/.claude/agents/` (user), plugin `agents/` [Claude Code docs, Subagents, 2026]. Invoke with: `Use the code-improver agent to suggest improvements in this project`.

The failure mode: **Over-broad subagent.** A subagent gets every tool and a huge description, so it can do more than intended and bloats the startup context.

The fix: Grant only the tools the job needs, keep the description short and move detail into the system prompt.

Cross-references: subagents in depth are Module 5.3; tool names are Module 1.2.2.

**If you remember one thing:** least privilege applies to subagents too.

## 1.2.5.4 — SUBAGENTS VERSUS AGENT TEAMS AND WORKFLOWS

**Framing.** A subagent stays inside one session and reports to its parent. Agent teams are separate sessions with their own context, a shared task list and peer messaging, experimental and disabled by default [Claude Code docs, Glossary, 2026].

| Aspect | Subagent | Agent team |
|---|---|---|
| Sessions | One | Several |
| Reports to | Parent only | Peers via shared task list |
| You can talk to it | Not directly | Yes, to any teammate |
| Status | Stable | Experimental, off by default |

The failure mode: **Look-alike conflation.** You configure a subagent when you needed an agent team (or the reverse) and spend an hour on the wrong feature.

The fix: Ask who must talk to whom: parent-only means subagent, peers means team.

Cross-references: agent teams are Module 6.4; dynamic workflows are Module 6.5.

**If you remember one thing:** who talks to whom decides the feature.

## CLOSING REFRAME

This is the craft of subagents: **a clean context for big reads, a summary back, and the discipline to delegate only what pays.** The engineer who understands this does not ask "can I spawn more agents?" — they ask "does this task need its own context, and what must I hand it?"
