# MODULE 5.1.3 — SKILL VS SUBAGENT: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**A skill is reusable content loaded into a context; a subagent is an isolated worker with its own context; they combine in two documented ways.**

**Prove-it, in one sentence:** for three tasks, choose skill, subagent or both and justify the choice by context-window impact.

**The single most important discipline: ask where the intermediate work should live: in your window (skill) or out of it (subagent).**

**The counterintuitive claim you will learn to defend:** a subagent is not simply 'a skill that runs by itself': it has a separate window with its own input and output tokens, which is its whole point [Claude Code docs, Extend Claude Code, 2026].

## 5.1.3.1 — THE COMPARISON

**Framing.** The docs frame the difference as content versus worker: skills are reusable content you can load into any context; subagents are isolated workers that run separately from your main conversation [Claude Code docs, Extend Claude Code, 2026].

| Aspect | Skill | Subagent |
|---|---|---|
| What it is | Reusable instructions, knowledge or workflows | Isolated worker with its own context |
| Key benefit | Share content across contexts | Context isolation; only a summary returns |
| Context-window impact | Adds to your main window | Separate window with its own input and output tokens |
| Best for | Reference material, invocable workflows | Many-file reads, parallel work, specialised workers |

[Claude Code docs, Extend Claude Code, 2026]

The failure mode: **Worker-by-skill.** You write a skill to do a 40-file investigation, and every file read lands in your main window, which fills with material you will never reference again.

The fix: Route many-file investigations through a subagent so only the summary enters your conversation.

Cross-references: subagents are Module 5.3; skills Module 5.2; context windows Module 3.1.

**If you remember one thing:** skills add to your window; subagents keep their work out of it.

---

## 5.1.3.2 — REFERENCE SKILLS AND ACTION SKILLS

**Framing.** The docs add that skills can be reference (knowledge used throughout a session, such as an API style guide) or action (tell Claude to do something specific, such as `/deploy`) [Claude Code docs, Extend Claude Code, 2026]. A subagent, by contrast, is chosen for isolation.

| Need | Choice | Why |
|---|---|---|
| Claude should know our API style all session | Reference skill | Knowledge in your window |
| Run the deploy checklist when I say so | Action skill | A workflow you trigger |
| Read 60 files and report where auth is wrong | Subagent | Intermediate output not needed |
| Review a file with a fresh, unbiased reader | Subagent | Separate context |

The failure mode: **Reference-as-worker.** You spin up a subagent just to apply a style guide, so the guide, the code and the result are all invisible to your main session and have to be re-explained.

The fix: Use a reference skill when the knowledge must stay in the conversation you are working in.

Cross-references: the choice of when to use subagents is sub-topic 5.3.11.

**If you remember one thing:** if you need to see the work, do not isolate it.

## 5.1.3.3 — THE TWO WAYS THEY COMBINE

**Framing.** The docs give two combinations: a subagent can preload specific skills through its `skills:` field, and a skill can run in an isolated context with `context: fork` [Claude Code docs, Extend Claude Code, 2026]. The skills reference adds that with `context: fork` the `agent` field picks the subagent type, defaulting to general-purpose [Claude Code docs, Skills, 2026].

```yaml
# skill that forks
---
name: pr-summary
description: Summarize changes in a pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---
```

| Direction | Field | Effect |
|---|---|---|
| Subagent uses skills | `skills:` in the agent file | Full skill content preloaded at launch |
| Skill uses a subagent | `context: fork`, optional `agent:` | Skill body becomes the task for a forked worker |

[Claude Code docs, Skills, 2026 (YAML example shown there)]

The failure mode: **Fork-without-task.** You mark a skill `context: fork` but its body is only reference guidelines with no task, so the forked worker has nothing to act on and returns nothing useful.

The fix: Fork only skills whose body contains an explicit task; keep guideline-only skills in the main context.

Cross-references: frontmatter is sub-topic 5.2.3 in Module 5.2; preloading is sub-topic 5.2.10.

**If you remember one thing:** combine by preloading skills into agents or forking skills into agents.
