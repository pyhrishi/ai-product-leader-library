## 7.2.3.1 — WHAT DISPATCH IS

**Framing.** Dispatch is a persistent conversation in Cowork that can spawn Code sessions from your phone, with push notifications when a session finishes or needs approval. It requires a Pro or Max plan and is not available on Team or Enterprise [Claude Code docs, Desktop, 2026].

| Property | Value |
|---|---|
| Trigger | Message a task from the Claude mobile app |
| Runs on | Your machine, through the Desktop app |
| Setup | Pair the mobile app with Desktop |
| Plans | Pro and Max only |
| Notifications | Sent when a spawned Code session finishes or needs approval |
| Computer-use approvals in Dispatch-spawned sessions | Last 30 minutes |

[Claude Code docs, Platforms and integrations and Desktop, 2026]. Pairing steps live in a support article that I did not retrieve [not verified].

The failure mode: **Cloud-by-feel.** You treat a Dispatch task as a cloud task, shut the laptop and find nothing done on return.

The fix: Dispatch runs on your machine; keep Desktop running and the computer awake, or use a cloud session instead.

Cross-references: the surfaces are Module 7.1; mobile is Module 7.5.

**If you remember one thing:** phone is the remote; the computer is the worker.

## 7.2.3.2 — DISPATCH VERSUS REMOTE CONTROL VERSUS CLOUD

**Framing.** All three let you act from a phone, but they differ in what is already running and where it executes [Claude Code docs, Mobile, 2026].

| | Dispatch | Remote Control | Cloud session / project |
|---|---|---|---|
| Starts from | A message to Dispatch | A session already running on your machine | A repository and a prompt |
| Runs on | Desktop on your machine | Your machine (CLI, Desktop or VS Code) | Anthropic cloud |
| Needs machine on | Yes | Yes | No |
| Plans | Pro, Max | Pro, Max, Team, Enterprise | Pro, Max, Team, Enterprise with seat conditions |

If your machine sleeps during Remote Control, Claude Code reconnects when it comes back online [Claude Code docs, Mobile, 2026].

The failure mode: **Wrong-remote.** You choose Dispatch for a task that needs an already-open terminal session, when Remote Control would have continued that session in place.

The fix: Use Remote Control to continue a session you already have, and Dispatch to start new work with minimal setup.

Cross-references: Remote Control is Module 7.5; cloud sessions are Module 7.4.

**If you remember one thing:** continue with Remote Control, delegate with Dispatch, offload with cloud.

## 7.2.3.3 — GOVERNANCE AND APPROVAL LOAD

**Framing.** Dispatch-spawned Code sessions can ask for approvals, and sending one task from a phone can trigger computer use. Treat the delegation as granting a short-lived session on your desktop.

| Control | Where |
|---|---|
| Computer use in Dispatch sessions | Approval for 30 minutes per app [Claude Code docs, Desktop, 2026] |
| Block all Remote Control | `disableRemoteControl: true` in user settings stops sessions connecting to Remote Control (this setting is about Remote Control, not Dispatch) |
| Admin availability | Dispatch and computer use unavailable on Team and Enterprise |

I did not find a documented managed setting that disables Dispatch alone on plans where it is available [not verified].

The failure mode: **Unattended-approval gap.** You dispatch a task that requests computer use, are not watching, and either it stalls or you approve from a phone prompt without reading it.

The fix: Prefer tasks that need no screen control when you are away, and read the approval card before accepting.

Cross-references: permission modes are Module 4.3; safety of remote access is Module 7.5.

**If you remember one thing:** decide in advance what you will approve from a phone.
