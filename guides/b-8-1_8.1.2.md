## THE THESIS OF THIS TOPIC

**A working first agent needs four things in the right order: the package, an API key in the process environment, an options object that names tools and a permission mode, and a loop that handles the final result.**

**Prove-it, in one sentence:** from an empty folder, install the SDK, run the bug-fixing agent end to end, and then convert a legacy claude-code-sdk import to the new names without breaking behaviour.

**The counterintuitive claim you will learn to defend:** the migration is a rename plus a behaviour change: after v0.1.0 the SDK no longer uses Claude Code's system prompt by default, so a straight rename silently changes how your agent behaves [Agent SDK docs, Migration guide, 2026].

## 8.1.2.1 — INSTALL AND AUTHENTICATE

**Framing.** Prerequisites are Node.js 18+ or Python 3.10+ and an Anthropic account [Agent SDK docs, Quickstart, 2026]. The package is installed per language and the key is read from the environment of the process that runs your agent.

| Language | Install |
|---|---|
| TypeScript | `npm install @anthropic-ai/claude-agent-sdk` (plus tsx to run files) |
| Python (uv) | `uv add claude-agent-sdk` |
| Python (pip) | `pip install claude-agent-sdk` in a virtual environment |

[Agent SDK docs, Quickstart, 2026]

```bash
export ANTHROPIC_API_KEY=your-api-key
```
The SDK does not load .env files automatically, so load the file yourself, for example with dotenv [Agent SDK docs, Quickstart, 2026]. Provider switches: `CLAUDE_CODE_USE_BEDROCK=1`, `CLAUDE_CODE_USE_VERTEX=1`, `CLAUDE_CODE_USE_FOUNDRY=1`, and `CLAUDE_CODE_USE_ANTHROPIC_AWS=1` with `ANTHROPIC_AWS_WORKSPACE_ID` [Agent SDK docs, Quickstart, 2026].

The failure mode: **Dotenv assumption.** You keep the key in a .env file, run the agent, and get 'Not logged in' or 'Invalid API key' because the SDK never read the file.

The fix: Export the variable in the shell that runs the agent, or load the .env explicitly before calling query().

Cross-references: auth and secrets for production are Module 8.7.4; Claude Code setup is Module 1.1.

**If you remember one thing:** the key must be in the environment of the process that starts the agent.

## 8.1.2.2 — THE FIRST AGENT

**Framing.** The quickstart agent reviews utils.py for crash bugs and fixes them using three options: a prompt, allowed tools and a permission mode. `allowed_tools` auto-approves the listed tools and `permission_mode='acceptEdits'` auto-approves file edits [Agent SDK docs, Quickstart, 2026].

```python
async for message in query(
    prompt="Review utils.py for bugs that would cause crashes. Fix any issues you find.",
    options=ClaudeAgentOptions(
        allowed_tools=["Read", "Edit", "Glob"],
        permission_mode="acceptEdits",
    ),
):
    ...
```
[Agent SDK docs, Quickstart, 2026]

| Tools allowed | What the agent can do |
|---|---|
| Read, Glob, Grep | Read-only analysis |
| Read, Edit, Glob | Analyze and modify code |
| Read, Edit, Bash, Glob, Grep | Full automation |

[Agent SDK docs, Quickstart, 2026]. A successful run ends with `Done: success`. The seeded file has two bugs: division by zero on an empty list, and a TypeError on a None user.

The failure mode: **Prompt-only safety.** You rely on the prompt ('only edit utils.py') instead of tool and permission options, and the agent edits other files because Edit was allowed everywhere.

The fix: Narrow capability with the tools list and permission rules, and treat the prompt as guidance only.

Cross-references: permissions are Module 8.6.1; the options object is Module 8.2.2.

**If you remember one thing:** the options object, not the prompt, bounds what the agent can do.

## 8.1.2.3 — MIGRATING FROM THE CLAUDE CODE SDK

**Framing.** The Claude Code SDK was renamed the Claude Agent SDK [Agent SDK docs, Migration guide, 2026]. The mapping is mechanical; the behaviour change is not.

| Aspect | Old | New |
|---|---|---|
| TS/JS package | `@anthropic-ai/claude-code` | `@anthropic-ai/claude-agent-sdk` |
| Python package | `claude-code-sdk` | `claude-agent-sdk` |
| Python options type | `ClaudeCodeOptions` | `ClaudeAgentOptions` |
| Default system prompt | Claude Code's | Minimal; opt in with `{"type": "preset", "preset": "claude_code"}` |

[Agent SDK docs, Migration guide, 2026]. Settings sources: omitting `settingSources` on query() loads user, project and local settings, matching the CLI; pass `settingSources: []` or `setting_sources=[]` to run isolated. Python SDK 0.1.59 and earlier treated an empty list like omitting the option, so upgrade before relying on it [Agent SDK docs, Migration guide, 2026].

```bash
npm uninstall @anthropic-ai/claude-code
npm install @anthropic-ai/claude-agent-sdk
```

The failure mode: **Rename-only migration.** You change the package and import names, the code runs, and the agent now answers in a different style and skips conventions the old Claude Code prompt supplied.

The fix: Request the claude_code preset explicitly, or write a custom system prompt, and re-run your acceptance tasks.

Cross-references: system prompts are Module 8.2.3; settings sources are Module 8.2.4.

**If you remember one thing:** a green import is not a finished migration.

## 8.1.2.4 — FIRST-RUN FAILURES BY CAUSE

**Framing.** Most first-run failures come from three places: authentication, a missing binary, and unexpected settings. The quickstart names each cause.

| Symptom | Cause | Fix | Source |
|---|---|---|---|
| 'Not logged in' or 'Invalid API key' | Key not in process environment | Export ANTHROPIC_API_KEY where the agent runs | Quickstart |
| No binary after pip install on ARM64 Windows | Source distribution installed, no platform wheel | Install Claude Code natively; SDK finds it on PATH | Quickstart |
| No binary after `npm ci --omit=optional` | Binary ships as an optional dependency | Reinstall without skipping optionals, or set `pathToClaudeCodeExecutable` | Quickstart |
| Isolation test still loads local config | Python <= 0.1.59 with empty list | Upgrade, then pass setting_sources=[] | Migration guide |

All rows: [Agent SDK docs, Quickstart and Migration guide, 2026]. The docs also point to a Troubleshooting page for CLI start failures.

The failure mode: **Optional-dependency strip.** A CI image installs with optional dependencies disabled and the TypeScript SDK cannot find its binary, which looks like an SDK bug.

The fix: Keep optional dependencies, or install Claude Code natively and pass pathToClaudeCodeExecutable.

Cross-references: container builds are Module 8.7.2; Claude Code installation is Module 1.1.

**If you remember one thing:** classify the failure (key, binary, settings) before changing code.
