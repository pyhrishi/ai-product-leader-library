## THE THESIS OF THIS TOPIC

**Frontmatter is the control surface of a skill: it decides who can invoke it, what it may do unprompted, where it runs and when it activates.**

**Prove-it, in one sentence:** write a side-effecting skill with the right invocation, tool and context fields and show Claude cannot trigger it on its own.

**The single most important discipline: set disable-model-invocation on anything with side effects before writing the body.**

**The counterintuitive claim you will learn to defend:** `allowed-tools` pre-approves; it does not restrict. Tools not listed remain available under your normal permission settings [Claude Code docs, Skills, 2026].

## 5.2.3.1 — THE FIELD LIST

**Framing.** Field names are lowercase with hyphens except `when_to_use`; all fields are optional though `description` is recommended; unrecognised fields are ignored without an error [Claude Code docs, Skills, 2026].

| Field | Controls |
|---|---|
| `name` | Command name in the `/` menu; defaults to directory name |
| `description` | What it does and when; used for matching |
| `when_to_use` | Extra trigger text, appended to description |
| `argument-hint`, `arguments` | Autocomplete hint; named positional arguments |
| `disable-model-invocation` | `true` stops Claude loading it automatically |
| `user-invocable` | `false` hides it from the `/` menu |
| `allowed-tools` / `disallowed-tools` | Pre-approve tools for the turn / remove tools while active |
| `model`, `effort` | Model and effort for the turn (`low` to `max`) |
| `context`, `agent`, `background` | Fork into a subagent; type; wait or not (v2.1.218+) |
| `hooks` | Hooks registered while the skill is active |
| `paths` | Globs limiting automatic loading |
| `shell` | `bash` (default) or `powershell` for injected commands |
| `metadata`, `license`, `compatibility` | Accepted, not acted on by Claude Code |

[Claude Code docs, Skills, 2026]

The failure mode: **Typo-tolerant ignore.** You write `disable-model-invokation: true`; Claude Code ignores the unknown field without error, and the skill with side effects stays auto-invocable.

The fix: Check fields against the table and confirm in `/skills` how the skill is listed.

Cross-references: invocation semantics are sub-topic 5.2.6; forked execution is sub-topic 5.1.3.

**If you remember one thing:** unknown keys fail silently, so verify behaviour.

## 5.2.3.2 — WHO CAN INVOKE

**Framing.** The docs tabulate invocation: by default both you and Claude can invoke and the description is always in context; with `disable-model-invocation: true` only you can invoke and the description is not in context; with `user-invocable: false` only Claude can invoke and the description is still in context [Claude Code docs, Skills, 2026].

| Frontmatter | You | Claude | Description in context |
|---|---|---|---|
| (default) | Yes | Yes | Always |
| `disable-model-invocation: true` | Yes | No | No |
| `user-invocable: false` | No | Yes | Always |

```yaml
---
name: commit
description: Stage and commit the current changes
disable-model-invocation: true
allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)
---
```

The failure mode: **Auto-deploy.** A deploy skill keeps the default invocation setting, and Claude loads and runs it because the conversation matched its description.

The fix: Add `disable-model-invocation: true` to any workflow with side effects.

Cross-references: cost effects are sub-topic 5.1.8.

**If you remember one thing:** side effects mean you invoke, not Claude.

## 5.2.3.3 — SCOPING WHAT A SKILL CAN TOUCH

**Framing.** `allowed-tools` clears when you send your next message and does not restrict other tools; `disallowed-tools` removes tools from Claude's pool while the skill is active; `paths` limits automatic loading; `context: fork` runs it in a subagent whose agent type comes from `agent` (default general-purpose) [Claude Code docs, Skills, 2026]. You can also deny the Skill tool in `/permissions` or allow or deny single skills with rules such as `Skill(commit)` [Claude Code docs, Skills, 2026].

| Need | Field |
|---|---|
| Stop prompts for `git commit` while running | `allowed-tools: Bash(git commit *)` |
| Make the skill read-only | `disallowed-tools` (for the active period) |
| Only load for TypeScript work | `paths: "**/*.ts"` |
| Do the work in isolation | `context: fork` + `agent: Explore` |

The failure mode: **Pre-approval-as-sandbox.** You list two tools in `allowed-tools` and assume Claude can use nothing else, but every other tool still works under your permission settings.

The fix: Use `disallowed-tools` or permission deny rules to restrict; use `allowed-tools` only to pre-approve.

Cross-references: permissions are Module 4.2; hooks in skills are sub-topic 5.2.12.

**If you remember one thing:** allow is not the same as only.
