# MODULE 8.3.5 — SUBAGENTS IN THE SDK: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**A subagent is a separate agent instance with its own context, tools and prompt, defined in code and invoked through the Agent tool, and its power comes from isolation and bounded spend, not from extra intelligence.**

**Prove-it, in one sentence:** define two subagents with different tool sets, prove delegation from the stream, and cap depth, concurrency and spend.

**The single most important discipline: put everything a subagent needs in the Agent tool's prompt, because that string is the only thing passed down.**

**The counterintuitive claim you will learn to defend:** a subagent does not see the parent's conversation: the only content passed from parent to subagent is the Agent tool's prompt string [Agent SDK docs, Subagents in the SDK, 2026].

## 8.3.5.1 — DEFINING SUBAGENTS

**Framing.** Define subagents with the agents parameter, with filesystem files in .claude/agents/, or rely on the built-in general-purpose agent. Programmatic definitions are recommended for SDK applications and take precedence over filesystem agents of the same name. Include Agent in allowed tools [Agent SDK docs, Subagents in the SDK, 2026].

| AgentDefinition field | Required | Notes |
|---|---|---|
| description | Yes | When to use the agent; Claude matches tasks by it |
| prompt | Yes | The agent's system prompt |
| tools | No | Omitted means all tools available to subagents |
| disallowedTools | No | Remove tools; accepts mcp__server patterns |
| model | No | Alias (sonnet, opus, haiku, inherit) or full ID |
| skills | No | Preload up to the first 32 distinct names |
| maxTurns | No | Output marked partial at the limit (Claude Code v2.1.246 or later) |
| background | No | Run as non-blocking task |
| effort, permissionMode, memory, mcpServers | No | Per-agent overrides |

[Agent SDK docs, Subagents in the SDK, 2026]. By default a spawned subagent runs in the background and the Agent result has status async_launched; Claude waits when its next action needs the report. In Python, multi-word fields keep camelCase.

The failure mode: **Missing Agent tool.** You define agents but leave Agent out of allowed tools, and delegation needs approval or never happens.

The fix: Include Agent in allowedTools and mention the subagent by name when you need a guarantee.

Cross-references: tool lists are Module 8.3.1; permissions are Module 8.6.1.

**If you remember one thing:** description routes; prompt defines; tools restrict.

## 8.3.5.2 — WHAT A SUBAGENT INHERITS

**Framing.** A non-fork subagent starts fresh: no parent conversation, no parent system prompt. It gets its own system prompt, the Agent tool's prompt, project CLAUDE.md (unless omitClaudeMd), and its tool definitions [Agent SDK docs, Subagents in the SDK, 2026].

| Receives | Does not receive |
|---|---|
| AgentDefinition.prompt and the Agent tool prompt | Parent history and tool results |
| Project CLAUDE.md via settingSources | Preloaded skill content unless listed in skills |
| Tool definitions (inherited or subset) | Parent's system prompt |

[Agent SDK docs, Subagents in the SDK, 2026]. Only the final message returns to the parent, which may summarize it; ask for verbatim output in your prompt if needed. From Claude Code v2.1.210 the final message is scanned for control-tag imitation and turn markers, which are neutralized in place, never removed. Forks copy the conversation and are available from v2.1.302; deny them with Agent(fork).

The failure mode: **Context assumption.** You write 'fix the bug we discussed' in the Agent prompt and the subagent has no idea what was discussed.

The fix: Pass file paths, error text and decisions explicitly in the prompt string.

Cross-references: context management is Module 8.2.1.

**If you remember one thing:** the prompt string is the whole handoff.

## 8.3.5.3 — DETECTING DELEGATION AND RESUMING

**Framing.** Claude invokes subagents through the Agent tool; detect tool_use blocks named Agent, and Task on older versions. Messages from inside a subagent carry parent_tool_use_id [Agent SDK docs, Subagents in the SDK, 2026].

| Need | How |
|---|---|
| Detect invocation | tool_use name in ("Task","Agent") |
| Know a message is inside a subagent | parent_tool_use_id set |
| Identify the subagent (TypeScript) | agent_id, v0.3.292 or later |
| Resume | Capture session_id and agentId from the Agent result; pass resume with the same agents definition |

[Agent SDK docs, Subagents in the SDK, 2026]. The built-in Explore and Plan agents are one-shot and return no agentId. Resume needs the same session; each query() starts a new session by default.

The failure mode: **Fresh-session resume.** You try to resume a subagent in a new query without resume: session_id, and its transcript is not found.

The fix: Pass the first query's session_id and the same agent definitions.

Cross-references: resume is Module 8.5.1.

**If you remember one thing:** to resume a subagent, resume the session.

## 8.3.5.4 — CAPPING DEPTH, CONCURRENCY AND SPEND

**Framing.** Claude decides how many subagents to spawn, and subagents can spawn subagents, so one prompt can grow into a tree. Three caps bound it; the section applies from TypeScript SDK v0.3.219 and Python SDK v0.2.127 [Agent SDK docs, Subagents in the SDK, 2026].

| Limit | Set with | Default | At the limit |
|---|---|---|---|
| Depth | CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH | 3 layers; 1 stops nesting | Bottom-layer subagent cannot spawn |
| Concurrency | CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS | 20 | 'Concurrent subagent limit reached' |
| Spend | maxBudgetUsd / max_budget_usd | None | 'Budget limit reached', background agents stopped, error_max_budget_usd |

[Agent SDK docs, Subagents in the SDK, 2026]. Opus 5 delegates more readily; the claude_code preset adds a line telling it not to call the Agent tool unless asked, but a custom prompt does not, so set the limits as well.

The failure mode: **Agent tree blowup.** An open-ended audit prompt spawns many subagents, each with its own requests, and spend balloons before the budget is noticed.

The fix: Set depth to 1, a small concurrency cap and a budget before launch.

Cross-references: cost is Module 8.6.3; failure handling is Module 8.7.5.

**If you remember one thing:** limits are enforced by Claude Code, whatever Claude decides.
