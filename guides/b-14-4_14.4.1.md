## 14.4.1.1 — SCOPES AND LOAD ORDER

**Framing.** Scopes from broadest to most specific: managed policy (for example `/etc/claude-code/CLAUDE.md` on Linux), user `~/.claude/CLAUDE.md`, project `./CLAUDE.md` or `./.claude/CLAUDE.md`, and local `./CLAUDE.local.md` which you add to `.gitignore`. Claude walks up from the working directory and concatenates what it finds, ordered from the filesystem root down, with `CLAUDE.local.md` after `CLAUDE.md` in a directory. Subdirectory files load on demand when Claude reads files there [Claude Code docs, Memory, 2026].

| Scope | Location | Shared with |
|---|---|---|
| Managed | OS-specific system path | Whole org |
| User | `~/.claude/CLAUDE.md` | You, all projects |
| Project | `./CLAUDE.md` or `./.claude/CLAUDE.md` | Team via git |
| Local | `./CLAUDE.local.md` | You, this project |

The failure mode: **Override-assumption.** You expect a project CLAUDE.md to override a contradictory user-level line, but both are in context and Claude may follow either.

The fix: Remove the contradiction rather than relying on precedence.

Cross-references: memory design is Module 3.2 and Module 3.3.

**If you remember one thing:** concatenated, not overridden.

## 14.4.1.2 — SIZE, IMPORTS AND AGENTS.MD

**Framing.** The docs target under 200 lines per CLAUDE.md. `@path` imports resolve relative to the importing file, recurse to four hops, and still load at launch, so they organise but do not save context. Claude Code reads CLAUDE.md, not AGENTS.md: import it with `@AGENTS.md` or symlink `ln -s AGENTS.md CLAUDE.md`, and on Windows prefer the import because symlinks need Administrator rights or Developer Mode [Claude Code docs, Memory, 2026].

```markdown
@AGENTS.md

## Claude Code
Use plan mode for changes under `src/billing/`.
```

| Technique | Saves context? |
|---|---|
| `@import` | No; loads at launch |
| Path-scoped rule | Yes, until matching files are read |
| Shorter file | Yes |

The failure mode: **Import-as-saving.** You split a long CLAUDE.md into imported files and expect context to shrink, but imports load at launch.

The fix: Move conditional content into path-scoped rules or skills.

Cross-references: skills are Module 5.2.

**If you remember one thing:** imports organise, they do not trim.

## 14.4.1.3 — RULES AND PATH SCOPES

**Framing.** `.claude/rules/*.md` are discovered recursively; rules without `paths` frontmatter load at launch with the priority of `.claude/CLAUDE.md`, and rules with `paths` load only when Claude reads matching files. User rules in `~/.claude/rules/` load before project rules, so project rules have higher priority [Claude Code docs, Memory, 2026].

```markdown
---
paths:
  - "src/api/**/*.ts"
---
# API rules
- All endpoints validate input
```

The failure mode: **Unscoped-rule-bloat.** You add many rules without `paths`, so all of them load at launch and crowd the window.

The fix: Add `paths` frontmatter to rules that matter only for some files.

Cross-references: context cost is Module 3.1.

**If you remember one thing:** scope rules by path.

## 14.4.1.4 — EXCLUDES, COMMENTS AND THE LOCAL FILE

**Framing.** `claudeMdExcludes` skips ancestor CLAUDE.md files in monorepos by absolute-path glob, arrays merge across layers, and managed CLAUDE.md cannot be excluded. Block-level HTML comments are stripped before injection. `--add-dir` does not load CLAUDE.md unless `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` [Claude Code docs, Memory, 2026].

| Need | Mechanism |
|---|---|
| Skip a parent team's file | `claudeMdExcludes` |
| Maintainer note not sent to Claude | Block-level HTML comment |
| Load CLAUDE.md from added dir | `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1` |

The failure mode: **Comment-leak-belief.** You put a secret in an HTML comment believing it is hidden, but the Read tool shows comments and the file is in git.

The fix: Never place secrets in instruction files.

Cross-references: security is Module 11.1.

**If you remember one thing:** comments are stripped from context, not from the file.

## CLOSING REFRAME
