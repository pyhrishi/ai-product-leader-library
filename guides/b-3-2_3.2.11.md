## 3.2.11.1 — THE RULE

**Framing.** Project-root and user-level CLAUDE.md files are read once at session start and held in memory; editing them mid-session does not invalidate the cache, but the edit also does not apply, and Claude keeps working with the version loaded at session start; the new content loads on the next `/clear`, `/compact` or restart [Claude Code docs, Prompt caching, 2026].

| File type | Mid-session edit |
|---|---|
| Project-root, user CLAUDE.md | No effect until `/clear`, `/compact` or restart |
| Nested CLAUDE.md, not yet loaded | Takes effect when it loads |
| Nested or `paths:` rule already loaded | No retroactive change |

The failure mode: **Edit-and-assume.** You edit CLAUDE.md, ask Claude to follow the new rule and conclude the file is ignored, when it was never reloaded.

The fix: Reload with `/clear`, `/compact` or a restart, then test.

Cross-references: editing flow is sub-topic 3.2.3 of Module 3.2.

**If you remember one thing:** edit, reload, verify.

---

## 3.2.11.2 — WHY: THE CACHE LAYOUT

**Framing.** Claude Code orders each request so rarely-changing content comes first: the system prompt and tool definitions, then project context (CLAUDE.md, auto memory, unscoped rules), then the conversation. Project context changes only when a session starts or after `/clear` or `/compact`; a match is exact, so a change anywhere in the prefix recomputes everything after it [Claude Code docs, Prompt caching, 2026].

| Layer | Content | Changes when |
|---|---|---|
| System prompt | Core instructions, tool definitions | Tool set changes |
| Project context | CLAUDE.md, auto memory, unscoped rules | Session start, `/clear`, `/compact` |
| Conversation | Messages and tool results | Every turn |

The failure mode: **Cache-blame.** You blame the cache for CLAUDE.md not applying and disable caching, which does not change the load rule.

The fix: Leave caching on; reload deliberately.

Cross-references: cache mechanics are Module 3.4.

**If you remember one thing:** the load rule is the cause.

---

## 3.2.11.3 — COMPACTION AND THE RELOAD

**Framing.** Compaction reloads project context from disk, which cache-hits only if CLAUDE.md and memory are unchanged since the session started [Claude Code docs, Prompt caching, 2026]. So editing CLAUDE.md and then compacting pays a cache rebuild for the changed project context. Running `/clear` rebuilds too, with a fresh conversation.

| Action | Result |
|---|---|
| Edit then `/clear` | Edit applies; fresh conversation; cache rebuilt |
| Edit then `/compact` | Edit applies; project context cache misses once |
| Edit then restart | Edit applies; cache rebuilt |

The failure mode: **Mid-task-reload.** You compact mid-task to apply an edit, paying a rebuild and losing detail at a bad moment.

The fix: Batch CLAUDE.md edits and apply them at a natural break between tasks.

Cross-references: natural breaks are covered in Module 3.1.

**If you remember one thing:** reload at breaks.
