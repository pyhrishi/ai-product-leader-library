## THE THESIS OF THIS TOPIC

**The model is a setting, not an identity: models and effort levels trade speed, cost and depth, and the right default is mid-tier with deliberate escalation.**

**Prove-it, in one sentence:** run one hard and one mechanical task at two settings and show where depth paid and where it did not.

**The single most important discipline: match model and effort to the difficulty of the step, not the importance of the project.**

**The counterintuitive claim you will learn to defend:** the strongest model at maximum effort is not the safest default; it spends your limits on steps that did not need it.

**THE TIME BUDGET.** Reading time: ~20 minutes. Prove-it time: ~2 hours (120 minutes, 6.0 times the reading time).

## 1.2.8.1 — MODELS IN THE HARNESS

**Framing.** The same harness drives whichever model you choose. The docs say Sonnet handles most coding tasks well, Opus gives stronger reasoning for complex architectural decisions, and you switch with `/model` or `claude --model <name>` [Claude Code docs, How Claude Code works, 2026].

| Lever | Command or setting |
|---|---|
| Switch model | `/model`, `claude --model <name>` |
| Subagent model | `model:` in subagent frontmatter; `CLAUDE_CODE_SUBAGENT_MODEL` for general-purpose |
| Effort | Effort level setting; supported on Fable models, Opus 4.6 and later, Sonnet 4.6 and later |
| Thinking cap | `MAX_THINKING_TOKENS` on models with a fixed thinking budget |

[Claude Code docs, Glossary and Subagents, 2026]

The failure mode: **Max-everything default.** You run the strongest model at the highest effort for every task and hit plan limits on routine edits.

The fix: Default to a mid-tier model and moderate effort, escalate for hard steps and de-escalate for mechanical ones.

Cross-references: models, effort and speed are Module 4.6; costs are Module 1.4.

**If you remember one thing:** the harness is constant; the model is a dial.

## 1.2.8.2 — EFFORT AND EXTENDED THINKING

**Framing.** Effort controls adaptive reasoning: the model decides whether and how much to think on each step. Higher effort means more thinking tokens and deeper reasoning; lower is faster and cheaper. Extended thinking is the visible step-by-step reasoning before a response, shown in grey italic text in the terminal [Claude Code docs, Glossary, 2026].

| Task type | Effort guidance |
|---|---|
| Rename, format, mechanical edits | Low |
| Typical feature work | Default |
| Architecture, hard debugging, security review | High |

[Guidance is judgement, not an official table; test on your own tasks.]

The failure mode: **Effort-as-default.** You leave effort at maximum for everything because it feels safer, and the plan bar drains on routine work.

The fix: Set a moderate default and raise it deliberately for hard steps.

Cross-references: effort settings are Module 4.6; plan usage is Module 1.4.

**If you remember one thing:** thinking tokens are spent, not free.

## 1.2.8.3 — SPEED AND COST LEVERS

**Framing.** Fast mode trades cost for speed on individual plans and is billed through usage credits [Claude Code docs, Costs, 2026]. Other levers: scoped context, fewer subagents and cheaper models for search workers.

| Lever | Speeds up | Costs |
|---|---|---|
| Fast mode | Output | Usage credits on individual plans |
| Smaller model | Everything | Depth |
| Smaller context | Everything | Nothing, if scoped well |
| Fewer subagents | Total cost | Parallelism |

The exact fast-mode multiplier is not reliably established here; treat any figure as order-of-magnitude and read the Costs page.

The failure mode: **Fast-mode forgetting.** You enable fast mode for an afternoon, forget it, and find the extra credit spend later.

The fix: Treat fast mode as a per-task switch and check month-to-date credit spend weekly.

Cross-references: costs and limits are Module 1.4; fast mode in depth is Module 4.6.

**If you remember one thing:** speed is a per-task purchase.

## 1.2.8.4 — CHOOSING PER STEP

**Framing.** A single task often has hard and easy steps. The practical pattern is a strong model for planning, a default model for implementation and a cheap model for search subagents.

| Step | Model and effort |
|---|---|
| Plan a multi-file change | Stronger model, higher effort |
| Implement against the plan | Default |
| Broad search or log scan (subagent) | Cheap model |
| Final review | Stronger model |

[Judgement-based pattern; measure on your own repos with `/usage`.]

The failure mode: **Single-setting habit.** You use one model and effort for a whole task, overspending on easy steps or underpowering hard ones.

The fix: Switch per step with `/model` and set subagent models in frontmatter.

Cross-references: subagents are Module 1.2.5; planning is Module 2.1.

**If you remember one thing:** switch settings per step, not per project.

## CLOSING REFRAME

This is the craft of the model layer: **a dial for depth, a dial for speed, and a default that is neither maximum nor minimum.** The engineer who understands this does not ask "which model is best?" — they ask "how hard is this step, and what setting does it earn?"
