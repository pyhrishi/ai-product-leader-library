# MODULE 3.2.1 — WHAT CLAUDE.MD IS: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**CLAUDE.md is a file Claude reads at the start of every session to carry knowledge it cannot infer from code, and it is context, not enforced configuration.**

**Prove-it, in one sentence:** show a rule in CLAUDE.md being followed, then show the same rule broken, and place the rule that cannot break in a hook.

## 3.2.1.1 — TWO MECHANISMS, ONE FRESH WINDOW

**Framing.** Each session starts with a fresh context window, and two mechanisms carry knowledge forward: CLAUDE.md files that you write and auto memory that Claude writes; both load at the start of every conversation as context, not enforced configuration [Claude Code docs, Memory, 2026].

|  | CLAUDE.md | Auto memory |
|---|---|---|
| Who writes it | You | Claude |
| Contains | Instructions and rules | Learnings and patterns |
| Scope | Project, user or org | Per repository, shared across worktrees |
| Loaded | Every session, in full | Every session: first 200 lines or 25KB of `MEMORY.md` |

The failure mode: **Config-confusion.** You treat CLAUDE.md as enforced configuration and rely on it to block an action.

The fix: Use a PreToolUse hook to block regardless of Claude's decisions; keep CLAUDE.md for guidance.

Cross-references: auto memory is Module 3.3; hooks are Module 5.4.

**If you remember one thing:** CLAUDE.md informs; hooks enforce.

---

## 3.2.1.2 — WHERE ITS AUTHORITY STOPS

**Framing.** Because CLAUDE.md arrives as a user message after the system prompt, compliance is not guaranteed; for must-run steps use a hook, and for system-prompt-level instructions in scripts use `--append-system-prompt` [Claude Code docs, Memory, 2026]. The Best practices page adds that a line that keeps being missed despite emphasis may belong in a hook [Claude Code docs, Best practices, 2026].

| Need | Mechanism |
|---|---|
| Convention Claude should usually follow | CLAUDE.md |
| Must run every time | Hook |
| Must never happen | Deny rule or PreToolUse hook |
| System-prompt-level in a script | `--append-system-prompt` |

The failure mode: **Request-as-guarantee.** You write 'never edit .env' in CLAUDE.md and treat it as protection.

The fix: Add a deny rule or PreToolUse hook; keep the CLAUDE.md line as an explanation.

Cross-references: permissions are Module 4.2.

**If you remember one thing:** a request is not a guarantee.

---

## 3.2.1.3 — WHEN TO ADD A LINE

**Framing.** Add to CLAUDE.md when Claude repeats a mistake, when code review catches something Claude should have known, or when you retype the same correction; keep it to facts Claude should hold every session, and move multi-step procedures or area-specific guidance to a skill or path-scoped rule [Claude Code docs, Memory, 2026]. The Extend page gives the same trigger: if Claude gets a convention or command wrong twice, add it [Claude Code docs, Extend Claude Code, 2026].

```text
Trigger log (one line per addition)
2026-11-03  Claude ran npm test from repo root   -> added: run tests from package dir
2026-11-05  review: raw SQL in handler            -> added: use query builder
```

The failure mode: **Speculative-rule.** You add rules for mistakes Claude has not made, so the file grows with unproven lines.

The fix: Add a line only after a repeated mistake or a review catch, and log the trigger.

Cross-references: pruning is sub-topic 3.2.6 of Module 3.2.

**If you remember one thing:** every line earns a trigger.
