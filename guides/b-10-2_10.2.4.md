## THE THESIS OF THIS TOPIC

**On a cloud provider, an unpinned alias resolves to Claude Code's built-in default, so the model your developers use, and the price they pay, can change with a client update.**

## 10.2.4.1 — PIN EVERY ALIAS

**Framing.** Without pinning, aliases such as `sonnet` and `opus` resolve to Claude Code's built-in default for the provider, which can lag the newest release and may not be enabled in your account. Pin with `ANTHROPIC_DEFAULT_FABLE_MODEL`, `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` and `ANTHROPIC_DEFAULT_HAIKU_MODEL` [Claude Code docs, Enterprise deployment overview, 2026].

```bash
# Bedrock example from the docs
export ANTHROPIC_DEFAULT_OPUS_MODEL='us.anthropic.claude-opus-4-8'
export ANTHROPIC_DEFAULT_SONNET_MODEL='us.anthropic.claude-sonnet-4-6'
export ANTHROPIC_DEFAULT_HAIKU_MODEL='us.anthropic.claude-haiku-4-5-20251001-v1:0'
```

The failure mode: **Alias drift.** You rely on `opus` and `sonnet` aliases; a client update moves the alias target and every developer silently changes model.

The fix: Pin each alias to an explicit model ID before rollout and re-pin deliberately on upgrade.

Cross-references: model settings are Module 4.6; cost impact is Module 10.6.

**If you remember one thing:** an alias is a moving target.

## 10.2.4.2 — THE COST TRAP

**Framing.** On Bedrock the primary model default is Opus 5.5 and the small/fast default is Sonnet 4.5; on Google's Agent Platform the primary default is `claude-opus-5`. The docs warn that Opus has a higher per-token price than Sonnet, so an unpinned deployment is billed at the Opus rate after updating to v2.1.207 or later; to keep Sonnet 4.5, set `ANTHROPIC_MODEL` to its full ID [Claude Code docs, Claude Code on Amazon Bedrock, 2026] [Claude Code docs, Claude Code on Google Cloud's Agent Platform, 2026].

| Provider | Primary default (no pin) | Small/fast default |
|---|---|---|
| Amazon Bedrock | Opus 5.5 | Sonnet 4.5 |
| Google Agent Platform | `claude-opus-5` | `claude-sonnet-4-5@20250929` |
| Foundry | `opus` alias resolves to Opus 4.6 | Defaults to the primary model |

The failure mode: **Silent Opus upgrade.** A routine client update changes the primary model default to Opus and spend jumps with no policy change.

The fix: Set `ANTHROPIC_MODEL` or the alias pins and alert on model mix in telemetry.

Cross-references: telemetry is Module 10.6.

**If you remember one thing:** an update can change the bill without changing the policy.

## 10.2.4.3 — REGIONAL ROUTING

**Framing.** On Bedrock Claude Code resolves cross-region inference profile prefixes by region: `us-gov.` for `us-gov-*`, `us.` for `us-*`, `eu.` for `eu-*`, `apac.` for `ap-*`, and `global.` otherwise; `ANTHROPIC_BEDROCK_REGION_PREFIX` accepts `us`, `eu`, `apac`, `jp`, `au` and `global` (v2.1.224 or later), and GovCloud always uses `us-gov.` [Claude Code docs, Claude Code on Amazon Bedrock, 2026]. On the Agent Platform, `CLOUD_ML_REGION` can be `global`, a multi-region such as `eu` or `us`, or a region such as `us-east5`, with `VERTEX_REGION_CLAUDE_*` overrides for models without global endpoints; an invalid region falls back to `us-east5` [Claude Code docs, Claude Code on Google Cloud's Agent Platform, 2026].

| AWS region | Prefix |
|---|---|
| `us-gov-*` | `us-gov.` |
| `us-*` | `us.` |
| `eu-*` | `eu.` |
| `ap-*` | `apac.` |
| other | `global.` |

The failure mode: **Prefix mismatch.** You set a prefix for which your account has no inference profiles and requests fail with a 400.

The fix: Run `aws bedrock list-inference-profiles` in the region and choose a prefix you actually have.

Cross-references: data residency is Module 10.7.6 topic and Module 10.7.

**If you remember one thing:** a preferred prefix is a preference, not a guarantee.

## 10.2.4.4 — MAP VERSIONS TO YOUR OWN PROFILES

**Framing.** The `modelOverrides` setting maps Anthropic model IDs to your own inference profile ARNs, so several versions of one family can appear in `/model` without bypassing your profiles; `--model` and `ANTHROPIC_MODEL` values pass through the map from v2.1.200 [Claude Code docs, Claude Code on Amazon Bedrock, 2026]. Startup checks skip pins that are application inference profile ARNs because administrators manage them.

```json
{ "modelOverrides": {
  "claude-opus-4-7": "arn:aws:bedrock:us-east-2:123456789012:application-inference-profile/opus-47-prod"
} }
```

The failure mode: **ARN as alias.** You set an ARN as the default and expect Claude Code to prompt when a newer model arrives; it never does, because ARN pins are skipped.

The fix: Update ARN mappings on your own release calendar.

Cross-references: cost allocation by profile is Module 10.6.

**If you remember one thing:** ARN pins make you the release manager.

## CLOSING REFRAME

This is the craft of pinning: **explicit IDs, a known region, and a calendar for moving on.** The administrator who understands this does not ask "which model do we have?" — they ask "who decided, and when does it change?"
