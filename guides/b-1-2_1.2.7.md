## 1.2.7.1 — WHAT A SESSION IS

**Framing.** A session is a conversation tied to your current directory with its own independent context window. It can be resumed with `claude -c`, forked with `--fork-session` to preserve history under a new session ID, or run in parallel across terminals; `/clear` starts a new session while the previous one stays stored and available via `/resume`; each transcript is stored under `~/.claude/projects/` [Claude Code docs, Glossary, 2026].

| Action | Command | Effect |
|---|---|---|
| Resume latest | `claude -c` | Continue the most recent session |
| Resume by pick | `/resume` | Choose a stored session |
| Fork | `--fork-session` or `/branch` | New ID, history kept |
| Fresh start | `/clear` | New session; old one stays resumable |
| One-shot | `claude -p` | Saved unless `--no-session-persistence` |

The failure mode: **Zombie session.** You resume a days-old session with a cluttered context and wonder why quality dropped.

The fix: Start fresh for a new task and resume only when the prior context is the asset.

Cross-references: session management is Module 2.4; headless runs are Module 6.8.

**If you remember one thing:** resume for continuity, clear for a new task.

## 1.2.7.2 — CHECKPOINTS AND REWIND

**Framing.** A checkpoint is created at each prompt that starts a turn; Claude Code snapshots files before every edit. `Esc Esc` or `/rewind` restores code, conversation or both, or summarises part of the conversation from a chosen message. Checkpoints are saved with the conversation and survive resume, but are separate from git and do not track Bash changes [Claude Code docs, Glossary, 2026].

| You rewind | Restores |
|---|---|
| Code | Files changed through file tools |
| Conversation | History to that turn |
| Both | Both |
| Not restored | Bash-made changes, remote effects |

The failure mode: **Checkpoint-as-git assumption.** You rely on rewind to undo a Bash change or a database write and it does not cover it.

The fix: Keep work in git, commit often and use permission rules for remote effects.

Cross-references: checkpoints are Module 2.5.

**If you remember one thing:** rewind covers edits, not the world.

---

## 1.2.7.3 — TRANSCRIPTS AS SENSITIVE DATA

**Framing.** Transcripts are stored as plain files under `~/.claude/projects/` (plaintext JSONL per earlier research on sessions [Claude Code docs, 2026; confirm on the sessions page]). Anything pasted or printed in a session, including secrets, sits in that file.

| Risk | Control |
|---|---|
| Secret pasted in a prompt | Do not paste secrets; use env vars |
| Secret printed by a command | Deny reads on secret paths |
| Shared machine or backup | Exclude `~/.claude/projects/` or delete sensitive sessions |
| `-p` runs | Pass `--no-session-persistence` when you do not want a stored session |

The failure mode: **Transcript leak.** A token appears in a prompt or tool output and persists in plaintext, then lands in a backup or shared image.

The fix: Keep secrets out of prompts, deny secret paths, and delete or exclude sensitive transcripts.

Cross-references: security is Module 11.1; privacy settings are Module 4.1.

**If you remember one thing:** a session is a file; treat secrets accordingly.

---

## 1.2.7.4 — SESSIONS, WORKTREES AND PARALLEL WORK

**Framing.** Parallel sessions in separate terminals each have their own context. For file isolation, worktree isolation runs Claude in a separate git worktree under `.claude/worktrees/`, enabled with `-w` or `isolation: worktree` in subagent config [Claude Code docs, Glossary, 2026].

| Need | Use |
|---|---|
| Two tasks on the same repo | Two worktrees, two sessions |
| Explore a different approach | Fork the session |
| Hand a task to another device | Cloud session or Remote Control |

The failure mode: **Shared-tree collision.** Two sessions edit the same working tree and overwrite each other's files.

The fix: Use worktree isolation so each session works on its own branch and directory.

Cross-references: worktrees are Module 6.2; parallel approaches are Module 6.1.

**If you remember one thing:** one tree per active session.

## CLOSING REFRAME

This is the craft of sessions: **resume for continuity, fork to explore, rewind edits, clear for new work, and treat the file as sensitive.** The engineer who understands this does not ask "can I get that conversation back?" — they ask "is that context an asset, and what does it contain?"
