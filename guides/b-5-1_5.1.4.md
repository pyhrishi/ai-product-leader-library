# MODULE 5.1.4 — CLAUDE.MD VS SKILL VS RULES: THE COMPLETE CRAFT

---

## THE THESIS OF THIS TOPIC

**CLAUDE.md, path-scoped rules and skills all hold instructions, but they load at different times, so the choice is a decision about when the text should cost you context.**

**Prove-it, in one sentence:** move three instructions to the correct home among CLAUDE.md, a rule file and a skill, and show CLAUDE.md is under 200 lines afterwards.

**The single most important discipline: ask 'when does Claude need this?' (always, when touching these files, or on demand) before choosing a file.**

**The counterintuitive claim you will learn to defend:** a CLAUDE.md that keeps growing is a design smell: the docs' rule of thumb is to stay under 200 lines and move reference content out [Claude Code docs, Extend Claude Code, 2026].

**THE TIME BUDGET.** Reading time: ~20 minutes. Prove-it time: ~2 hours (120 minutes, 6.0 times the reading time).

## 5.1.4.1 — LOADING IS THE DIFFERENCE

**Framing.** All three store instructions; the docs distinguish them by when they load and how they are scoped [Claude Code docs, Extend Claude Code, 2026].

| Aspect | CLAUDE.md | `.claude/rules/` | Skill |
|---|---|---|---|
| Loads | Every session | Every session, or when matching files are opened | On demand, when invoked or relevant |
| Scope | Whole project | Can be scoped to file paths | Task-specific |
| Best for | Core conventions, build commands | Language- or directory-specific guidelines | Reference material, repeatable workflows |

Rules with `paths` frontmatter load only when Claude works with matching files [Claude Code docs, Extend Claude Code, 2026].

The failure mode: **Everything-in-CLAUDE.md.** All guidance, including API reference and a 90-line deploy runbook, sits in one file that loads on every request.

The fix: Keep only always-needed facts in CLAUDE.md; move the rest to rules or skills.

Cross-references: CLAUDE.md loading is Module 3.2 and rules are Module 3.3; context cost is sub-topic 5.1.8.

**If you remember one thing:** the question is when Claude needs the text.

---

## 5.1.4.2 — WHAT BELONGS WHERE

**Framing.** The docs give plain placement advice: CLAUDE.md for instructions every session needs (build commands, test conventions, project architecture); rules to keep CLAUDE.md focused; skills for content Claude needs only sometimes, like API documentation or a deployment checklist triggered with `/<name>` [Claude Code docs, Extend Claude Code, 2026].

| Instruction | Home | Reason |
|---|---|---|
| "Run `pnpm test` before committing" | CLAUDE.md | Needed every session |
| "In `src/api/`, validate input with zod" | Rule with `paths: src/api/**` | Only relevant when touching those files |
| Full REST error catalogue | Skill (reference) | Needed sometimes |
| "Run the release checklist" | Skill (action) | Triggered with `/release` |

The failure mode: **Scope blindness.** A rule about one directory is written into CLAUDE.md, so every session pays for guidance that matters in a small part of the tree.

The fix: Give it a `paths` frontmatter in a rule file so it loads only with matching files.

Cross-references: writing skills is Module 5.2.

**If you remember one thing:** always-needed to CLAUDE.md, path-bound to rules, sometimes-needed to skills.

## 5.1.4.3 — THE 200-LINE RULE OF THUMB

**Framing.** The docs state the rule of thumb directly: keep CLAUDE.md under 200 lines, and if it grows, move reference content to skills or split into `.claude/rules/` files; `/doctor` can propose trims for a checked-in CLAUDE.md [Claude Code docs, Extend Claude Code, 2026]. The number is a rule of thumb, not a limit enforced by the tool.

```text
before:  CLAUDE.md  412 lines  (build, style, API catalogue, deploy runbook)
after:   CLAUDE.md  74 lines   (build, test, architecture)
         .claude/rules/api.md  paths: src/api/**   (validation, error shape)
         .claude/skills/deploy/SKILL.md            (runbook, action)
         .claude/skills/api-catalogue/SKILL.md     (reference)
```
The line counts above are illustrative, not measured from a real repository.

The failure mode: **Line-count worship.** You cut CLAUDE.md to 199 lines by deleting facts Claude needs every session, rather than by moving the right content out.

The fix: Move content by when it is needed, not by how many lines remain.

Cross-references: rules and the .claude directory are Module 3.3.

**If you remember one thing:** the number is a prompt to move content, not a target to hit.
