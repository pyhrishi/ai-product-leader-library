## THE THESIS OF THIS TOPIC

**Tool search withholds tool definitions from context and loads only what a turn needs, trading one extra round trip per search for a much smaller context on every turn.**

**Prove-it, in one sentence:** measure context use with tool search on and off for a 50-tool server and decide the ENABLE_TOOL_SEARCH setting with numbers.

**The single most important discipline: name and describe tools for search, because the search matches names and descriptions.**

**The counterintuitive claim you will learn to defend:** more tools are not free even when idle: the docs say tool selection accuracy degrades with more than 30-50 tools loaded at once, which is why deferral exists, but with fewer than about 10 small tools, loading upfront is typically faster [Agent SDK docs, Scale to many tools with tool search, 2026].

## 8.3.4.1 — WHAT IT DOES AND WHAT IT COSTS

**Framing.** Tool search lets an agent work with hundreds or thousands of tools: definitions are withheld, the agent gets a summary and searches when it needs a capability. Fifty tools can use 10-20K tokens, and selection accuracy degrades with more than 30-50 loaded at once [Agent SDK docs, Scale to many tools with tool search, 2026].

| Property | Value | Source |
|---|---|---|
| Default | On | Tool search page |
| Tools loaded per search | Up to 5 most relevant | Tool search page |
| Persistence | Loaded tools stay until the messages where they were found are compacted | Tool search page |
| Catalogue limit | 10,000 tools | Tool search page |
| Cost | One extra round trip per search | Tool search page |
| Not supported | Models earlier than Opus 4 / Sonnet 4; Microsoft Foundry deployments hosted on Azure | Tool search page |

[Agent SDK docs, Scale to many tools with tool search, 2026]. Core built-in tools such as Bash, Read and Edit load upfront.

The failure mode: **Post-compaction amnesia.** After compaction the discovered tools leave context, Claude must search again, and a fixed workflow suddenly takes an extra round trip.

The fix: Name key tools in the system prompt and use alwaysLoad for the few that every turn needs.

Cross-references: compaction is Module 8.2.1; MCP servers are Module 8.3.3.

**If you remember one thing:** deferral saves context and costs round trips.

## 8.3.4.2 — CONFIGURING ENABLE_TOOL_SEARCH

**Framing.** You control deferral with the ENABLE_TOOL_SEARCH environment variable, set through the env option [Agent SDK docs, Scale to many tools with tool search, 2026].

| Value | Behaviour |
|---|---|
| unset | On, with fallbacks to upfront loading on unsupported models and some platforms |
| true | On, same fallbacks |
| auto | Off until deferrable definitions reach 10% of the context window, then on |
| auto:N | Same with N percent; auto:5 activates sooner |
| false | Off; all definitions load every turn |

[Agent SDK docs, Scale to many tools with tool search, 2026]. CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS keeps it off, and a HIPAA configuration turns it off. In TypeScript, env replaces the subprocess environment, so spread process.env. Behind an ANTHROPIC_BASE_URL gateway it is on by default; before Claude Code v2.1.304 it was disabled there unless set.

The failure mode: **Env replacement.** In TypeScript you set only ENABLE_TOOL_SEARCH in env and drop PATH and the API key.

The fix: Spread process.env and add the variable.

Cross-references: env semantics are Module 8.2.2.

**If you remember one thing:** auto:N is a threshold on deferrable definitions, not on total context.

## 8.3.4.3 — WRITING TOOLS THAT SEARCH FINDS

**Framing.** The search matches queries against tool names and descriptions. Names like search_slack_messages surface for a wider range of requests than query_slack, and a description such as 'Search Slack messages by keyword, channel, or date range' beats 'Query Slack' [Agent SDK docs, Scale to many tools with tool search, 2026].

| Weak | Strong |
|---|---|
| query_slack | search_slack_messages |
| 'Query Slack' | 'Search Slack messages by keyword, channel, or date range' |
| Catalogue unknown to the agent | System prompt line: 'You can search for tools to interact with Slack, GitHub, and Jira.' |

[Agent SDK docs, Scale to many tools with tool search, 2026]. Use the claude_code preset with append so the line adds to the preset.

The failure mode: **Generic name.** Two tools called run and query both match many requests and the agent loads the wrong one.

The fix: Use verb-object names and keyword-rich descriptions.

Cross-references: tool design principles are Module 8.3.6.

**If you remember one thing:** a name is a search key.

## 8.3.4.4 — DECIDING WITH NUMBERS

**Framing.** The decision is empirical: compare context tokens, turns and success for your catalogue under each setting. The docs give the thresholds; your tools give the numbers.

| Setting | Context tokens (turn 1) | Extra round trips | Success on task set |
|---|---|---|---|
| false | measure | 0 | measure |
| unset | measure | measure | measure |
| auto:5 | measure | measure | measure |

Figures are to be measured; none are claimed here. Use the usage fields on the ResultMessage and run each setting on the same tasks.

The failure mode: **Setting by folklore.** You pick auto:5 because a blog said so and never measure on your catalogue.

The fix: Measure all three settings on your task set.

Cross-references: evals are Module 8.6.5; cost tracking is Module 8.6.3.

**If you remember one thing:** measure before you configure.
