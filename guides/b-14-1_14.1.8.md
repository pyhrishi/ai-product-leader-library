## THE THESIS OF THIS TOPIC

**Diagnostic commands answer three different questions: what is loaded (/status), what went wrong at runtime (/debug) and what is the install state (/doctor), and they also include a destructive-to-privacy trap in /heapdump.**

**Prove-it, in one sentence:** pick the right diagnostic for three symptoms and run each.

**The single most important discipline: start with /status, then escalate to /doctor or /debug by the kind of symptom.**

**The counterintuitive claim you will learn to defend:** the .heapsnapshot written by /heapdump contains your full conversation and credentials; only the diagnostics JSON is safe to attach [Claude Code docs, Commands, 2026].

## 14.1.8.1 — WHAT IS LOADED, WHAT IS WRONG

**Framing.** `/status` opens Settings on the Status tab showing version, model, account and connectivity; its Setting sources line lists the loaded settings files [Claude Code docs, Settings, 2026]. `/doctor` diagnoses installation, settings, extension and CLAUDE.md problems and proposes fixes. `/debug [description]` is a bundled skill that enables debug logging from that point on and reads the session debug log; logging is off unless you started with `claude --debug` [Claude Code docs, Commands, 2026].

| Symptom | Start with |
|---|---|
| Wrong model or file loaded | `/status` |
| Install or config looks broken | `/doctor` |
| Odd runtime behaviour | `/debug <description>` |
| Setting ignored in `-p` | `claude doctor` |

The failure mode: **Debug-too-late.** You run `/debug` after the failure already happened and expect it to explain history, but logging starts only from that point.

The fix: Start with `claude --debug` for reproducible issues, or rerun the failing step after `/debug`.

Cross-references: debugging is Part 12.

**If you remember one thing:** logging is forward-only.

## 14.1.8.2 — REPORTING WITHOUT LEAKING

**Framing.** `/bug [report]` and `/feedback` open a consent screen where you choose how much session history to include; signed in to Anthropic first-party, the report goes to Anthropic, otherwise it is written to a local archive under `~/.claude/feedback-bundles/` for you to forward. `/heapdump` writes a heap snapshot and a diagnostics breakdown to `~/Desktop` or your home directory; attach only the `-diagnostics.json` [Claude Code docs, Commands, 2026].

| File | Safe to share? |
|---|---|
| `*-diagnostics.json` | Yes, per the docs |
| `*.heapsnapshot` | No: contains conversation and credentials |
| `feedback-bundles/` archive | Only after you review it |

The failure mode: **Snapshot-attached.** You attach the whole heapdump folder to a public issue and publish your conversation and credentials.

The fix: Attach only the diagnostics JSON and review any bundle before forwarding.

Cross-references: security basics are Module 4.4.

**If you remember one thing:** share the JSON, never the snapshot.

## 14.1.8.3 — LEARNING FROM USAGE

**Framing.** `/help` lists commands, `/release-notes` opens an interactive version picker whose notes stay out of the conversation Claude sees, and `/insights` generates an HTML report analysing recent sessions on this machine, not available in cloud sessions [Claude Code docs, Commands, 2026].

| Command | Output |
|---|---|
| `/help` | Command list |
| `/release-notes` | Per-version notes, not sent to Claude |
| `/insights` | HTML report of your sessions |

Availability varies by platform, plan and version; if a command is missing, run `/help` and check `claude --version` before assuming it does not exist.

The failure mode: **Untested-upgrade.** You read release notes and assume a new behaviour applies to your version without checking it.

The fix: Check `claude --version` and the version tag in the docs row before relying on a change.

Cross-references: keeping up is Module 16.3.

**If you remember one thing:** match the version tag to your version.

## CLOSING REFRAME

This is the craft of diagnostics: **the right command for the right question.** The engineer who understands this does not ask "which diagnostic do I run?" — they ask "is this a what-is-loaded, install-state or runtime question?"
