## THE THESIS OF THIS TOPIC

**Most install and login failures fall into a handful of buckets, and each has an ordered check.**

**Prove-it, in one sentence:** reproduce a PATH failure and fix it with the ordered checks, ending with one binary.

**The single most important discipline: match your exact error string, then check the binary, then PATH, then duplicates, before reinstalling anything.**

## 1.3.7.1 — FIND YOUR ERROR

**Framing.** The Troubleshoot install page is organised by error string. `command not found: claude` or `'claude' is not recognized` means the install directory is not on PATH; a PowerShell installer that finishes but shows no `claude` or an old version means restart the terminal and verify PATH [Claude Code docs, Troubleshoot install, 2026].

| Symptom | Likely cause | First action |
|---|---|---|
| `command not found: claude` | Not on PATH | Verify `~/.local/bin` on PATH; new terminal or `source ~/.zshrc` |
| `A parameter cannot be found that matches parameter name 'fsSL'` | Linux curl command in PowerShell | Use the PowerShell installer |
| Installer cannot download | Network, proxy or firewall | Check connectivity; set proxy variables |
| Crash or hang though `--version` prints | Corrupt or conflicting installs | `claude doctor`; list all copies |
| Old version | Multiple installs, legacy `~/.claude/local` | Keep one |

[Claude Code docs and Claude Help Center, 2026]

The failure mode: **Guess-and-reinstall loop.** You reinstall repeatedly when the binary was fine and PATH was the problem, adding a second copy each time.

The fix: Check the binary, then PATH, then `which -a claude`, before reinstalling.

Cross-references: install is Module 1.3.1; updating is Module 1.3.5.

**If you remember one thing:** match the string, then check in order.

## 1.3.7.2 — THE PATH SEQUENCE

**Framing.** Installers detect the PATH case and report it under Setup notes, for example that `~/.local/bin` is not in your PATH [Claude Code docs, Troubleshoot install, 2026].

```bash
ls -l ~/.local/bin/claude                          # 1. is the binary there?
echo "$PATH" | tr ':' '\n' | grep -n 'local/bin'   # 2. is its folder on PATH?
export PATH="$HOME/.local/bin:$PATH"               # 3. fix now; persist in ~/.zshrc or ~/.bashrc
claude --version && which -a claude                # 4. confirm and list all copies
```

Three places a binary can come from: `~/.local/bin/claude` (native), `~/.claude/local/` (legacy local npm install) and the global npm list [Claude Code docs, Troubleshoot install, 2026].

The failure mode: **Wrong-shell fix.** You fix PATH in one shell's profile while using another, so the fix never applies.

The fix: Identify the shell with `echo $SHELL`, edit the matching profile and open a new terminal.

Cross-references: shell setup is general; environment variables are Module 4.8.

**If you remember one thing:** binary, PATH, copies, in that order.

## 1.3.7.3 — LOGIN AND AUTHENTICATION ERRORS

**Framing.** If you cannot sign in, see the login section of the troubleshooting page; first confirm which account `/login` shows, then check the environment for credentials that override it [Claude Code docs, Authentication and Troubleshoot install, 2026].

| Symptom | Check |
|---|---|
| Login loop | `/logout` then `/login`; clear stale credentials |
| Wrong account | `/login` to switch |
| Provider errors | Provider env vars set correctly; no browser login needed |
| Intermittent network | Wait a few minutes; the docs note failures are often temporary |

The failure mode: **Cached-credential confusion.** A cached credential for another account keeps you in the wrong plan or provider.

The fix: `/logout`, `/login` and confirm the active account.

Cross-references: sign-in is Module 1.3.2; Part 12 covers runtime troubleshooting.

**If you remember one thing:** log out cleanly before debugging further.

## 1.3.7.4 — WRITING A TEAM RUNBOOK

**Framing.** Turn the table into a runbook so teammates fix common issues in minutes.

| Runbook line | Content |
|---|---|
| Symptom | Exact error string |
| First check | The one command to run |
| Fix | The smallest change |
| Escalate | Who to ask and what to attach (`claude --version`, doctor output) |

The failure mode: **Runbook-by-memory.** Every incident is solved from memory by whoever is nearby and the knowledge never lands anywhere.

The fix: Write the symptom, check, fix and escalation attachments and keep it in the repo.

Cross-references: incident handling is Part 12.

**If you remember one thing:** write the fix once.

## CLOSING REFRAME

This is the craft of troubleshooting setup: **match the string, check in order, and never reinstall first.** The engineer who understands this does not ask "how do I reinstall?" — they ask "which layer failed: binary, PATH, copies or credentials?"
