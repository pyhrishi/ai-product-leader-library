## 5.2.5.1 — ARGUMENT SUBSTITUTION

**Framing.** Text typed after the slash command becomes arguments. If the skill has no placeholder for them, Claude Code appends `ARGUMENTS: <value>` so the input is still seen [Claude Code docs, Skills, 2026].

| Variable | Expands to |
|---|---|
| `$ARGUMENTS` | Full argument string |
| `$ARGUMENTS[N]` or `$N` | Argument at 0-based index N |
| `$name` | Named argument from the `arguments` field |
| `${CLAUDE_SKILL_DIR}` | Directory containing SKILL.md |
| `${CLAUDE_PROJECT_DIR}` | Project root |
| `${CLAUDE_SESSION_ID}` | Current session ID |
| `${CLAUDE_EFFORT}` | Current effort level |

Escape a literal dollar sign as `\$1.00`. [Claude Code docs, Skills, 2026]

The failure mode: **Placeholder-less skill.** A skill ignores `$ARGUMENTS`, so the typed value arrives only as an appended `ARGUMENTS:` line and the instructions do not refer to it.

The fix: Reference `$ARGUMENTS` or a named argument where the value belongs.

Cross-references: invocation is sub-topic 5.2.6.

**If you remember one thing:** put the argument where the instruction needs it.

## 5.2.5.2 — INJECTING LIVE OUTPUT

**Framing.** The `` !`command` `` syntax runs a shell command before the skill content reaches Claude and replaces the placeholder with its output. Inline form is recognised only when `!` starts a line or follows whitespace; substitution runs once; multi-line commands use a fenced block opened with ```` ```! ````; each command has the Bash tool's default 2-minute timeout [Claude Code docs, Skills, 2026].

```yaml
---
name: pr-summary
description: Summarize changes in a pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---
- PR diff: !`gh pr diff`
- Changed files: !`gh pr diff --name-only`
```
[Claude Code docs, Skills, 2026]

The failure mode: **Output-as-instruction.** A command's output contains text that reads like an instruction, and Claude follows it because injection puts it into the skill as if you wrote it.

The fix: Inject only trusted, structured output and keep the instructions below it explicit.

Cross-references: injection and security of project skills are sub-topic 5.2.12.

**If you remember one thing:** injection runs once, before Claude sees anything.

## 5.2.5.3 — FAILURE AND PERMISSION BEHAVIOUR

**Framing.** A non-zero exit aborts the invocation, except exit code 1 from search and comparison commands such as `grep`. Injected commands are checked against permission rules: a deny rule aborts the invocation, and any non-allow result aborts unless pre-approved with `allowed-tools`. `disableSkillShellExecution: true` in settings replaces each command with `[shell command execution disabled by policy]` for user, project, plugin and additional-directory skills; Claude Code never runs injected commands in skills synced from your claude.ai account [Claude Code docs, Skills, 2026].

| Situation | Result |
|---|---|
| Command exits 0 | Output substituted |
| `grep` finds nothing (exit 1) | Treated as a normal result |
| Other non-zero exit | Whole invocation aborted |
| Deny rule matches | Aborted |
| Not allowed and not pre-approved | Aborted (auto mode defers to its usual checks) |
| Fix for flaky commands | `command || true` |

The failure mode: **Abort-on-exit.** A `git diff` or `gh` call exits non-zero in a repo with no remote, the invocation aborts, and Claude never sees the skill, which looks like a skill that does not work.

The fix: Append `|| true` where failure is acceptable and test the skill in a clean repo.

Cross-references: permissions are Module 4.2.

**If you remember one thing:** design for the command failing.
