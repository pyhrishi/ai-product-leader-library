## 10.2.2.1 — THE FOUR ROUTES

**Framing.** Amazon Bedrock is enabled with `CLAUDE_CODE_USE_BEDROCK=1`; Google Cloud's Agent Platform (formerly Vertex AI) with `CLAUDE_CODE_USE_VERTEX=1`, `CLOUD_ML_REGION` and `ANTHROPIC_VERTEX_PROJECT_ID`; Microsoft Foundry with `CLAUDE_CODE_USE_FOUNDRY=1` and `ANTHROPIC_FOUNDRY_RESOURCE`; Claude Platform on AWS with `CLAUDE_CODE_USE_ANTHROPIC_AWS=1` and the required `ANTHROPIC_AWS_WORKSPACE_ID` [Claude Code docs, Claude Code on Amazon Bedrock, 2026] [Claude Code docs, Claude Code on Google Cloud's Agent Platform, 2026] [Claude Code docs, Claude Code on Microsoft Foundry, 2026] [Claude Code docs, Claude Code on Claude Platform on AWS, 2026].

| Route | Switch | Auth | Cost console |
|---|---|---|---|
| Amazon Bedrock | `CLAUDE_CODE_USE_BEDROCK=1` | API key or AWS credentials | AWS Cost Explorer |
| Claude Platform on AWS | `CLAUDE_CODE_USE_ANTHROPIC_AWS=1` | API key or AWS credentials (SigV4) | AWS Cost Explorer |
| Google Agent Platform | `CLAUDE_CODE_USE_VERTEX=1` | GCP credentials | GCP Billing |
| Microsoft Foundry | `CLAUDE_CODE_USE_FOUNDRY=1` | API key or Microsoft Entra ID | Azure Cost Management |

The failure mode: **Switch collision.** More than one `CLAUDE_CODE_USE_*` variable is set, and the wrong provider wins: Bedrock and Foundry take precedence over Claude Platform on AWS.

The fix: Set one switch per environment and confirm with `/status`.

Cross-references: wizards are Module 10.2.3; pinning is Module 10.2.4.

**If you remember one thing:** one switch, one provider, one `/status` check.

## 10.2.2.2 — CREDENTIALS PER ROUTE

**Framing.** Bedrock uses the default AWS SDK credential chain, with options from `aws configure` to SSO profiles to `AWS_BEARER_TOKEN_BEDROCK`; resolved credentials are cached until five minutes before expiry and each resolve times out after 60 seconds [Claude Code docs, Claude Code on Amazon Bedrock, 2026]. Foundry accepts an API key, the Azure default credential chain, or a bearer token in `ANTHROPIC_FOUNDRY_AUTH_TOKEN`, which takes precedence over the key [Claude Code docs, Claude Code on Microsoft Foundry, 2026]. Claude Platform on AWS: `ANTHROPIC_AWS_API_KEY` takes precedence over SigV4 [Claude Code docs, Claude Code on Claude Platform on AWS, 2026].

```bash
# Foundry precedence (highest first)
ANTHROPIC_FOUNDRY_AUTH_TOKEN   # bearer
ANTHROPIC_FOUNDRY_API_KEY      # key
# otherwise Azure default credential chain
```

The failure mode: **Stale key shadow.** A leftover API key silently overrides your federated credentials, so every request fails with access denied.

The fix: Unset the key variable or regenerate it; verify which credential wins with `/status`.

Cross-references: login and identity are Module 10.3.

**If you remember one thing:** the more specific credential wins, even when stale.

## 10.2.2.3 — THE ORGANISATION BOUNDARY

**Framing.** Subscribing to Claude Platform on AWS through AWS Marketplace provisions a new Anthropic organisation tied to your AWS account; credentials do not transfer between it and any existing organisation, so use the workspace ID and keys from the AWS-linked one [Claude Code docs, Claude Code on Claude Platform on AWS, 2026]. Claude Platform on AWS bills through AWS Marketplace and gives the same models and API features as the Claude API on the same release schedule.

| Question | Bedrock | Claude Platform on AWS |
|---|---|---|
| Who operates inference | AWS | Anthropic |
| Billing | PAYG through AWS | PAYG through AWS Marketplace |
| Needs workspace ID | No | Yes (`ANTHROPIC_AWS_WORKSPACE_ID`) |

The failure mode: **Wrong-organisation key.** You paste a Console API key into the AWS route and get 403s, because the keys belong to a different organisation.

The fix: Generate keys in the AWS Console under Claude Platform on AWS, and use the AWS-linked workspace ID.

Cross-references: backend differences are Module 10.2.5.

**If you remember one thing:** check which organisation a key belongs to before debugging IAM.

## 10.2.2.4 — OPERATING NOTES

**Framing.** WebSearch is not available on Bedrock; `/logout` is unavailable on cloud providers because authentication is handled by the cloud credentials; Foundry has no startup model check, so requests fail when the default is unavailable [Claude Code docs, Claude Code on Amazon Bedrock, 2026] [Claude Code docs, Claude Code on Microsoft Foundry, 2026]. Where a Foundry deployment auto-updates to latest, create deployments with an explicit version instead.

| Route | Notable limit |
|---|---|
| Bedrock | No WebSearch; Invoke API only, not Converse |
| Foundry | No setup wizard; no startup model check |
| Agent Platform | Model availability varies by region type |

The failure mode: **Latest-alias outage.** A deployment tracks 'latest', the provider moves it, and a model your account cannot invoke becomes the default.

The fix: Pin model versions (Module 10.2.4) and create versioned deployments.

Cross-references: pinning is Module 10.2.4.

**If you remember one thing:** pin before you scale.
