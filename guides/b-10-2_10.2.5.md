# MODULE 10.2.5 — FEATURE AVAILABILITY MATRIX: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**Not every feature exists on every backend; the matrix, not memory, decides what you can promise a team.**

**Prove-it, in one sentence:** produce a one-page matrix for your backend listing what is missing, the alternative, and who needs a separate seat.

**The single most important discipline: read the provider tab before promising a feature.**

**The counterintuitive claim you will learn to defend:** the CLI and everything local work on every provider, but cloud sessions, Routines, Remote Control and the Chrome extension need a claude.ai sign-in [Claude Code docs, Feature availability, 2026].

## 10.2.5.1 — WHAT WORKS EVERYWHERE

**Framing.** These work on every provider: CLI and Agent SDK, VS Code and JetBrains extensions, subagents, hooks, commands, skills, CLAUDE.md, plugins, MCP servers, checkpoints, sandboxing, workflows, OpenTelemetry metrics and the managed settings file [Claude Code docs, Feature availability, 2026].

| Always available | Needs care |
|---|---|
| CLI, Agent SDK, IDE extensions | MCP connectors from claude.ai need a subscription login |
| Subagents, hooks, skills, plugins | Tool search varies by provider and model generation |
| Checkpoints, sandboxing, workflows | `/design-sync`, `/import` unavailable off first-party |

The failure mode: **Everything-works assumption.** You assume local features imply cloud features, and promise scheduled routines on Bedrock.

The fix: Read the subscription-required list before promising anything remote.

Cross-references: backend routes are Module 10.2.2.

**If you remember one thing:** local works everywhere; remote needs a seat.

---

## 10.2.5.2 — THE CLAUDE.AI-ONLY LIST

**Framing.** Features that require a claude.ai account and are unreachable from a Console key or cloud provider: cloud sessions, mobile and Slack, Desktop, Routines (`/schedule`), Ultrareview, Code Review (Team and Enterprise), Remote Control, the Chrome extension, computer use (Pro and Max), Artifacts and voice dictation [Claude Code docs, Feature availability, 2026].

| Needs claude.ai | Plan note |
|---|---|
| Cloud sessions | Enterprise: premium or Chat + Claude Code seat |
| Code Review | Team and Enterprise |
| Computer use | Pro and Max only |
| Remote Control, Channels | Admin-enabled on Team/Enterprise |

The failure mode: **Seat-gap surprise.** A Bedrock team expects Code Review and finds no route; the seat was never purchased.

The fix: Decide which groups also need claude.ai seats before announcing features.

Cross-references: plans are Module 1.4; cloud sessions are Module 4.5.

**If you remember one thing:** some features follow the seat, not the cloud.

## 10.2.5.3 — PER-BACKEND GAPS

**Framing.** Bedrock lacks web search, fast mode, advisor, channels, analytics dashboard, server-managed settings and `/design-sync`/`/import`; Claude Platform on AWS adds web search back but lacks GitHub Actions; Google's platform supports web search on Claude 4 models and later; Foundry supports web search only on Anthropic-hosted deployments and lacks GitLab CI/CD. Auto mode on cloud providers supports only Sonnet 5 or later, Opus 4.7 or later and Fable models [Claude Code docs, Feature availability, 2026].

| Feature | Bedrock | Platform on AWS | Agent Platform | Foundry |
|---|---|---|---|---|
| Web search | No | Yes | Claude 4+ | Anthropic-hosted only |
| GitHub Actions | Yes | No | Yes | Yes |
| GitLab CI/CD | Yes | Yes | Yes | No |
| Server-managed settings | No | No | No | No |

The failure mode: **Matrix memorisation.** You memorise last quarter's matrix and miss a change.

The fix: Re-read the page at every client version upgrade and date your copy.

Cross-references: managed settings delivery alternatives are Module 10.4 and Module 10.5.

**If you remember one thing:** date-stamp your copy of the matrix.

## 10.2.5.4 — GATEWAYS AND ALTERNATIVES

**Framing.** For an LLM gateway, availability matches the underlying provider except what Claude Code turns off: a non-default host in `ANTHROPIC_BASE_URL` switches off Remote Control and server-managed settings [Claude Code docs, Feature availability, 2026]. On gateway sessions through Claude apps gateway, WebSearch is disabled and the 1-hour cache TTL is unavailable [Claude Code docs, Claude apps gateway, 2026]. The page lists alternatives: `/loop` instead of `/schedule`, GitHub Actions or GitLab CI/CD for cloud sessions, WebFetch with a URL for web lookups.

| Missing | Alternative the docs name |
|---|---|
| `/schedule` | `/loop` |
| Cloud sessions | GitHub Actions or GitLab CI/CD |
| Web search (Bedrock) | WebFetch with a specific URL |

The failure mode: **Gateway blind spot.** You route through a gateway and assume nothing changes, but Claude Code disables features whenever the base URL is non-Anthropic.

The fix: Test the feature list through the gateway, not through the provider.

Cross-references: gateways are Module 10.5.

**If you remember one thing:** a gateway can remove features the provider supports.
