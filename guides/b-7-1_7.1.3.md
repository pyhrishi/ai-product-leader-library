## THE THESIS OF THIS TOPIC

**Sessions move between surfaces through a small set of commands, and each move has a direction, a requirement and something that does not come along.**

**Prove-it, in one sentence:** perform or describe each move (/desktop, --cloud, /teleport, /remote-control, --resume) and state what is copied and what is left behind.

**The single most important discipline: before moving a session, check the three preconditions: same account, branch pushed or clean, and the right direction.**

**The counterintuitive claim you will learn to defend:** from the CLI, handoff is one-way: you can pull a cloud session into the terminal with --teleport, but you cannot push an existing terminal session to the cloud [Claude Code docs, Claude Code in the cloud, 2026].

## 7.1.3.1 — THE COMMAND SET

**Framing.** Five commands do almost all moving. The commands reference describes each in one line [Claude Code docs, Commands, 2026].

| Command | What it does | Requires |
|---|---|---|
| `/desktop` (alias `/app`) | Continue the current session in the Desktop app | macOS or x64 Windows, claude.ai subscription |
| `/teleport` (alias `/tp`) | Pull a cloud session into this terminal | claude.ai subscription |
| `/remote-control` (alias `/rc`) | Make this session available from claude.ai | claude.ai subscription |
| `claude --cloud "task"` | Start a new cloud session for the current repository | claude.ai account, GitHub remote or bundle |
| `claude --resume` | Reopen a conversation from this machine's local history | Same machine |

`--remote` still works as a deprecated alias for `--cloud` [Claude Code docs, Claude Code in the cloud, 2026]. `/desktop` appears only on macOS and x64 Windows when signed in with a subscription [Claude Code docs, Commands, 2026].

The failure mode: **Alias-blur.** You use `--remote` and `--remote-control` interchangeably, then wonder why one created a cloud session and the other exposed a local one.

The fix: Remember that `--cloud` creates cloud sessions and `--remote-control` only lets you monitor and steer a local CLI session from claude.ai or the app.

Cross-references: commands by moment are Module 14.1; Remote Control detail is Module 7.5.

**If you remember one thing:** cloud makes a new remote session; remote-control exposes a local one.

## 7.1.3.2 — CLOUD TO TERMINAL: TELEPORT

**Framing.** `claude --teleport` opens a session picker, and `claude --teleport <session-id>` resumes one directly. Inside a CLI session, `/teleport` or `/tp` opens the same picker; `/tasks` then `t` also works [Claude Code docs, Claude Code in the cloud, 2026].

| Requirement | Detail |
|---|---|
| Clean git state | No uncommitted changes; teleport offers to stash |
| Correct repository | Same repository, not a fork |
| Branch available | The session's branch must be pushed |
| Same account | Same claude.ai account as the cloud session |

Teleport verifies the repository, fetches and checks out the branch, and loads the full history. The terminal gets its own copy: new work there stays local and does not appear in the cloud session. To keep steering from a phone, start `/remote-control` in the local session [Claude Code docs, Claude Code in the cloud, 2026].

`--teleport` is distinct from `--resume`: `--resume` reopens local history and does not list cloud sessions.

The failure mode: **Fork-and-diverge.** You teleport a session, keep working locally, and expect the phone to show your new work, but the cloud copy and the local copy have diverged.

The fix: After teleporting, start `/remote-control` if you need the phone to follow, or treat the cloud session as finished.

Cross-references: cloud sessions are Module 7.4; git hygiene before moving is Module 2.5.

**If you remember one thing:** teleport copies; it does not link.

## 7.1.3.3 — TERMINAL TO CLOUD, AND THE FOLLOW-UP PATH

**Framing.** To start cloud work from the terminal use `claude --cloud "task"`. The cloud VM clones your GitHub remote at your current branch, not your local checkout, so push first [Claude Code docs, Claude Code in the cloud, 2026].

```bash
git push                         # cloud clones the remote branch, not your working tree
claude --cloud "Fix the flaky test in auth.spec.ts"
claude -p "also update the changelog" --cloud session_01ABC...   # queue a follow-up
claude --teleport                # later: pull a finished session back
```

If the repository has no GitHub remote or the Claude GitHub App is not installed, Claude Code bundles and uploads your local repository instead; the bundle must be under 100 MB and uncommitted changes to credential-like files such as `.env` are left out on macOS, Linux and WSL [Claude Code docs, Claude Code in the cloud, 2026]. The Desktop app can send a local session to the cloud from its Open in menu, carried over as a summary [Claude Code docs, Desktop, 2026].

The failure mode: **Unpushed-branch launch.** You run `--cloud` with local commits that were never pushed and the cloud session starts from an older commit, so it solves a problem you already fixed.

The fix: Push first, and read the `Branch <name> is not on GitHub` notice if it prints.

Cross-references: cloud environments are Module 4.5; session management is Module 2.4.

**If you remember one thing:** push before you launch; teleport to come back.
