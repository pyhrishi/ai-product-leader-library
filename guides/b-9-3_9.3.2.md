## 9.3.2.1 — FIVE EVIDENCE CHANNELS

**Framing.** The docs' guidance is to hand Claude the thing you have rather than describe it: `@` a file, paste an image, or pipe command output from your shell [Claude Code docs, Best practices, 2026].

| Channel | How | Source |
|---|---|---|
| Pasted error | Paste stack trace | [Claude Code docs, Common workflows, 2026] |
| Piped logs | `cat error.log \| claude -p "what's going on here"` | [Claude Code docs, Best practices, 2026] |
| Screenshot | Drag, paste with `Ctrl+V`, or give a path | [Claude Code docs, Common workflows, 2026] |
| Dashboards | MCP server, for example Sentry | [Claude Code docs, MCP, 2026] |
| Git history | `git log`, `git diff`; ask for the change that introduced the bug | general git use |

The failure mode: **Paraphrased error.** You summarise the error as 'it crashes on login' and Claude proposes a generic fix.

The fix: Paste the exact message and stack trace; attach the log slice around the time of the failure.

Cross-references: MCP is Module 5.5; images in prompts are Module 2.2.

**If you remember one thing:** raw artifacts beat summaries.

## 9.3.2.2 — PIPING AND SIZE LIMITS

**Framing.** Piped stdin is capped at 10MB; larger inputs should be written to a file and referenced by path [Claude Code docs, Headless, 2026]. An `@` file reference includes contents when they fit the Read tool's token limit, 25,000 tokens by default, and a text file over 256KB is not included [Claude Code docs, Common workflows, 2026].

| Input size | Move |
|---|---|
| Small error | Paste |
| Log slice | `tail -n 500 app.log \| claude -p "..."` |
| Over 10MB | Save to file, reference path |
| `@file` over 25,000 tokens | Narrow with grep or a slice first |

Slice before sending: filter to the time window and the request id.

The failure mode: **Log flood.** You pipe an entire day's log and the relevant lines are drowned or truncated.

The fix: Filter to the request id and time window, then attach the slice.

Cross-references: context cost is Module 3.1.

**If you remember one thing:** send the right 500 lines, not 5 million.

## 9.3.2.3 — EVIDENCE FROM TOOLS AND SECRETS HYGIENE

**Framing.** Connected servers add their tool names and instructions to the context even when unused, and servers that fetch external content can expose you to prompt injection, so trust matters [Claude Code docs, Best practices, 2026; Claude Code docs, MCP, 2026]. Redact secrets and personal data from evidence before pasting.

| Evidence type | Handling |
|---|---|
| Stack trace | Strip tokens and URLs with credentials |
| Logs with user data | Mask personal fields |
| Screenshot | Check for visible secrets |
| MCP dashboards | Read-only access (Module 9.3.4) |

The failure mode: **Leaky evidence.** You paste a log containing tokens or customer data into the session.

The fix: Redact first, and keep deny rules for secret files (`Read(./.env)`) as the docs show.

Cross-references: permissions are Module 4.2.

**If you remember one thing:** evidence is data you are responsible for.

## THE PROVE-IT SECTION

**Deliverable.** An evidence pack for one bug: four channels, a note on what each contributed and a redaction log.

**Close this topic. Build the artifact below from memory. Return to the text only after your first attempt is complete.**

| Step | Action | Output |
|---|---|---|
| 1 | Collect error, log slice, screenshot, history | Pack |
| 2 | Redact | Redaction log |
| 3 | Prompt with the pack | Prompt |
| 4 | Record what each channel changed | Notes |

**A passing artifact looks like this:**

| Channel | Contribution |
|---|---|
| Log slice | request id found |
| History | commit that changed refresh |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Summary only | **Paraphrased error** |
| Unredacted tokens | **Leaky evidence** |

**The verdict.** The artifact passes only if at least four channels are present, each with a recorded contribution, and the redaction log is non-empty or states nothing needed redacting.
