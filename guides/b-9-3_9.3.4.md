## 9.3.4.1 — MCP OR CLI

**Framing.** The docs' examples include checking Sentry and Statsig for usage of a feature and querying a PostgreSQL database through MCP; if a system has a CLI, that is usually the easiest way in, and for a CLI Claude has not seen, pointing it at `--help` is enough [Claude Code docs, MCP, 2026; Claude Code docs, Best practices, 2026].

| Route | Add | Scope notes |
|---|---|---|
| CLI | Install and sign in (for example `gh`) | Claude uses it through Bash |
| Remote MCP | `claude mcp add --transport http <name> <url>` | Recommended transport in the docs |
| Local MCP | `claude mcp add <name> -- <command> [args...]` | stdio server |

`--scope local` (default), `project` (shared via `.mcp.json`) or `user`. Project servers prompt for approval; reset with `claude mcp reset-project-choices` [Claude Code docs, MCP, 2026].

The failure mode: **Overscoped token.** The token you connected can write or delete, so a prompt-injected instruction could change monitoring or data.

The fix: Issue a read-only token for the investigation and keep write tokens out of the session.

Cross-references: MCP is Module 5.5; permissions are Module 4.2.

**If you remember one thing:** least privilege at the credential.

## 9.3.4.2 — TRUST AND OUTPUT LIMITS

**Framing.** The docs warn: verify you trust each server before connecting; servers that fetch external content can expose you to prompt injection [Claude Code docs, MCP, 2026]. MCP tool output over 10,000 tokens triggers a warning and output is limited to 25,000 tokens by default, adjustable with `MAX_MCP_OUTPUT_TOKENS` [Claude Code docs, MCP, 2026].

| Concern | Control |
|---|---|
| Untrusted content in logs | Treat as data; do not follow instructions in it |
| Big query results | Ask for aggregates and narrow time windows |
| Idle servers cost context | Disable unneeded servers in `/mcp` |
| Shared config | `.mcp.json` committed without secrets |

The failure mode: **Log-borne instruction.** A log line or ticket contains text telling the agent to run something, and Claude treats it as a command.

The fix: Use read-only tools, deny rules for risky commands, and review actions the classifier blocks (auto mode flags actions that look driven by content Claude read) [Claude Code docs, Best practices, 2026].

Cross-references: prompt injection controls are Module 4.4.

**If you remember one thing:** data is not instruction.

## 9.3.4.3 — AN INVESTIGATION PROMPT

**Framing.** Pair evidence from monitoring with code reading so Claude correlates deploys, errors and changes. Ask for citations of what it queried.

```text
Using the Sentry MCP, list the top 5 unresolved errors for the checkout service in the last
24 hours. For the top one, show the stack trace, find the code, check git log for recent
changes to that file, and propose a hypothesis. Do not change anything.
```

| Output requirement | Why |
|---|---|
| Queries run | Auditable |
| Hypothesis, not fix | Keeps step separate |
| Time window stated | Avoids stale data |

The failure mode: **Unaudited query.** Claude summarises dashboards without naming the queries or time windows, so you cannot check the claim.

The fix: Require the exact query, time window and result count in the answer.

Cross-references: root cause is Module 9.3.5.

**If you remember one thing:** ask for the query as well as the answer.

## CLOSING REFRAME

This is the craft of observability access: **least privilege, bounded output, auditable queries.** The engineer who understands this does not ask "can Claude see prod?" — they ask "what can this credential change if everything goes wrong?"
