## 5.2.6.1 — DIRECT INVOCATION

**Framing.** To run a skill directly, put `/name` at the start of your message, such as `/deploy staging`. A command is only recognised at the start of your message, and text after the name becomes its arguments [Claude Code docs, Skills and Commands, 2026].

| Message | Effect |
|---|---|
| `/deploy staging` | Runs the skill directly with `staging` |
| `please run /deploy staging` | Does not run directly; permits Claude to run it for this message |
| `/deploy` while Claude is responding | Queued until the turn ends |

The failure mode: **Mid-message slash.** You type text then `/deploy` and assume the skill ran, but it only gave Claude permission to run it.

The fix: Start the message with the slash name.

Cross-references: commands are sub-topic 5.2.8.

**If you remember one thing:** start of message means run; elsewhere means permit.

---

## 5.2.6.2 — AUTOMATIC LOADING

**Framing.** Claude matches your task to skill descriptions and loads one when relevant, unless `disable-model-invocation: true` hides it. Skills with `user-invocable: false` can only be invoked by Claude [Claude Code docs, Skills, 2026].

| Path | Who decides | Needs |
|---|---|---|
| You type `/name` | You | Skill is user-invocable |
| Claude loads it | Claude | A matching description; model invocation not disabled |
| `paths` match | Claude, only for matching files | `paths` globs |

The failure mode: **Phantom availability.** You expect Claude to use a skill that has `disable-model-invocation: true` and it never does.

The fix: Invoke it yourself or remove the setting if automatic use is wanted.

Cross-references: frontmatter is sub-topic 5.2.3; descriptions are sub-topic 5.2.4.

**If you remember one thing:** three paths, one frontmatter switch each.

---

## 5.2.6.3 — STACKING SKILLS

**Framing.** At the terminal prompt you can chain up to six skills at the start of a message, for example `/write-tests /fix-issue 123`; the trailing text becomes `$ARGUMENTS` for each [Claude Code docs, Skills, 2026].

```text
/write-tests /fix-issue 123
   skill A      skill B   -> "123" becomes $ARGUMENTS for both
```
Each stacked skill's body is loaded into the conversation, so six large skills cost six bodies of context [inference from the lifecycle rule, not stated as a cost in the docs].

The failure mode: **Argument-bleed.** You stack skills and the trailing text is passed to every skill, so a skill that expected something else misreads it.

The fix: Stack only skills that accept the same argument, or invoke them one at a time.

Cross-references: context costs are sub-topic 5.1.8.

**If you remember one thing:** stacking shares one argument string.
