## 5.2.12.1 — NOT TRIGGERING

**Framing.** The documented steps: check the description has keywords users would say; verify the skill appears when you ask what skills are available; rephrase; invoke with `/skill-name`; if that is not recognised, check whether Claude Code refused the name; if `paths` is set, check the files are inside the working directory [Claude Code docs, Skills, 2026]. Run with `--debug` to see a YAML parse error, and `claude plugin validate .claude/skills` (v2.1.233+) finds files whose frontmatter does not parse.

| Step | Check |
|---|---|
| 1 | Keywords in description |
| 2 | Skill listed? |
| 3 | Rephrase request |
| 4 | `/skill-name` directly |
| 5 | Name accepted? |
| 6 | `paths` inside working directory |
| 7 | `--debug`, `claude plugin validate` |

The failure mode: **Skip-the-checklist.** You rewrite the whole skill when the real fault was a `paths` glob outside the working directory.

The fix: Walk the checks in order before editing the body.

Cross-references: descriptions are sub-topic 5.2.4.

**If you remember one thing:** diagnose before rewriting.

## 5.2.12.2 — TOO OFTEN, AND STOPS FOLLOWING

**Framing.** If a skill triggers too often: make the description more specific or add `disable-model-invocation: true`. If Claude stops following it: a must-hold rule belongs in a hook (possibly in the skill's own `hooks` frontmatter); judgement guidance should be worded for the whole task; after compaction, invoke the skill again, because only its start may be kept [Claude Code docs, Skills, 2026].

| Symptom | Cause | Fix |
|---|---|---|
| Fires on unrelated requests | Broad description | Narrow it or disable model invocation |
| Followed once, then ignored | Rule must always hold | Hook |
| Ignored after a long session | Compaction kept only the start | Re-invoke; put key rules first |

The failure mode: **Compaction-blindness.** Claude follows the skill early, then drifts after a long session, and you blame the wording rather than the 5,000-token re-attach limit.

The fix: Re-invoke after compaction and keep critical instructions near the top.

Cross-references: compaction is Module 3.1; hooks are Module 5.4.

**If you remember one thing:** long sessions truncate skills.

---

## 5.2.12.3 — DESCRIPTIONS CUT, HOOKS LIMITS, LOCKDOWNS

**Framing.** When the listing overflows its budget, descriptions are dropped starting with least-invoked skills; run `/doctor`. If managed settings list `hooks` in `strictPluginOnlyCustomization`, personal and project skills that declare hooks lose their `allowed-tools` pre-approval; remove `hooks` from the frontmatter or move the skill into a plugin [Claude Code docs, Skills, 2026]. Before v2.1.280 a `manifest.json` in `~/.claude/skills/` could cause listed skill folders to be moved to `~/.claude/skills/.trash/` (default retention 30 days) [Claude Code docs, Skills, 2026].

| Symptom | Look at |
|---|---|
| Skill listed without description | `/doctor`, `skillListingBudgetFraction` |
| Pre-approval vanished | `strictPluginOnlyCustomization` includes `hooks` |
| Personal skills gone | `~/.claude/skills/.trash/` |

The failure mode: **Policy-blind skill.** A hook-bearing skill prompts for every tool in your org while working elsewhere, because managed policy removed its pre-approval.

The fix: Check managed settings; move the skill into a plugin or drop its hooks.

Cross-references: managed settings are Module 4.1; hooks in skills are sub-topic 5.4.2.

**If you remember one thing:** some failures come from policy, not the skill.
