# MODULE 5.1.6 — MCP VS SKILL: THE COMPLETE CRAFT

---

## THE THESIS OF THIS TOPIC

**MCP supplies the connection and the tools; a skill supplies the knowledge of how to use them well; the strongest pattern is both together.**

**Prove-it, in one sentence:** pair one MCP server with a skill that documents its schema and query patterns and show a task done better with both than with either alone.

**The single most important discipline: separate 'can Claude reach it' (MCP) from 'does Claude know how we use it' (skill).**

**The counterintuitive claim you will learn to defend:** a skill cannot give Claude access to a system, and an MCP server cannot teach Claude your team's conventions for using it [Claude Code docs, Extend Claude Code, 2026].

**THE TIME BUDGET.** Reading time: ~18 minutes. Prove-it time: ~2 hours (120 minutes, 6.7 times the reading time).

|---|---|
| L3 | State what MCP provides versus a skill |
| L4 | Decide for a stated integration which part is MCP and which is skill |
| L5 | Design a Skill + MCP pair and a Hook + MCP pair |

## 5.1.6.1 — DIFFERENT PROBLEMS

**Framing.** The docs state it plainly: MCP connects Claude to external services; skills extend what Claude knows, including how to use those services effectively [Claude Code docs, Extend Claude Code, 2026].

| Aspect | MCP | Skill |
|---|---|---|
| What it is | Protocol for connecting to external services | Knowledge, workflows, reference material |
| Provides | Tools and data access | Knowledge, workflows, reference |
| Examples | Slack integration, database queries, browser control | Code review checklist, deploy workflow, API style guide |

The failure mode: **Instructions-as-connector.** You write a long skill explaining how to query the production database but never connect a server, so Claude can describe a query and cannot run one.

The fix: Add the MCP server for access; keep the skill for schema and conventions.

Cross-references: adding servers is Module 5.5; skills are Module 5.2.

**If you remember one thing:** connection is MCP; knowledge is a skill.

---

## 5.1.6.2 — BOTH TOGETHER

**Framing.** The docs call these complementary: MCP gives purpose-built tools with connection and authentication handled by the server, and a skill might include your team's database schema and query patterns or a `/post-to-slack` workflow with your formatting rules [Claude Code docs, Extend Claude Code, 2026].

| Layer | Holds |
|---|---|
| MCP server | `query` tool, auth, connection |
| Skill | Table meanings, join patterns, "never SELECT * on events" |
| Result | Claude can run queries and writes them the way your team does |

The combine table lists the pattern as Skill + MCP: MCP provides the connection, a skill teaches Claude to use it well [Claude Code docs, Extend Claude Code, 2026].

The failure mode: **Tool-only integration.** A server is connected and nothing teaches the schema, so Claude guesses table names and burns turns on failed queries.

The fix: Write a skill with the schema, naming conventions and two example queries.

Cross-references: tool search and context costs are sub-topic 5.5.5; MCP security is sub-topic 5.5.13.

**If you remember one thing:** ship the skill with the server.

---

## 5.1.6.3 — HOOK PLUS MCP

**Framing.** The docs also list Hook + MCP: a hook triggers external actions through MCP, for example a post-edit hook that sends a Slack notification when Claude modifies critical files [Claude Code docs, Extend Claude Code, 2026]. This uses MCP for action, but without the model deciding to act.

| Pattern | Who decides to act |
|---|---|
| Skill + MCP | Claude, guided by the skill |
| Hook + MCP | The event; no model choice |

The failure mode: **Notification-by-hope.** You ask Claude in prose to post to Slack whenever it edits a critical file, and some edits go unannounced.

The fix: Use a hook on the edit event that calls the MCP tool.

Cross-references: hooks are Module 5.4; mcp_tool handler is sub-topic 5.4.4.

**If you remember one thing:** choose Claude-decides or event-decides, then wire MCP accordingly.

## THE PROVE-IT SECTION

**Deliverable.** A paired MCP server and skill for one real system, with a before/after of one task.

**Close this topic. Build the artifact below from memory. Return to the text only after your first attempt is complete.**

| Step | Action | Output |
|---|---|---|
| 1 | Pick one external system you use | System name |
| 2 | Connect it with an MCP server | `claude mcp add` result |
| 3 | Run one task with the server only and log the errors | Error count |
| 4 | Write the skill: schema, conventions, two queries | `SKILL.md` |
| 5 | Rerun the same task and compare errors | Second count |
| 6 | Add one hook if an action must always follow | Hook entry |

**A passing artifact looks like this:**

| Setup | Failed queries | Turns | Notes |
|---|---|---|---|
| MCP only | 4 | 9 | Guessed table names |
| MCP + skill | 0 | 4 | Used documented joins |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Only a skill, no server | **Instructions-as-connector** |
| Counts are asserted, not logged | No evidence |

**The verdict.** The artifact passes only if both runs have logged counts and the skill content is specific to the system.
