## 14.2.6.1 — THE METHODS

**Framing.** Methods: `\` then Enter works in all terminals; `Option+Enter` after enabling Option as Meta on macOS; `Shift+Enter` natively in iTerm2, WezTerm, Ghostty, Kitty, Warp, Apple Terminal and Windows Terminal; `Ctrl+J` in any terminal without configuration; and pasting directly for code blocks and logs [Claude Code docs, Interactive mode, 2026].

| Method | Works |
|---|---|
| `\` + Enter | Everywhere |
| `Ctrl+J` | Any terminal, no setup |
| `Shift+Enter` | Native in listed terminals |
| `Option+Enter` | macOS with Option as Meta |
| Paste | Code and logs |

The failure mode: **Shift-Enter-submits.** You press Shift+Enter in an unconfigured terminal and the prompt submits half-written.

The fix: Use `\` + Enter or Ctrl+J, then run `/terminal-setup`.

Cross-references: terminal setup is Module 9.1.

**If you remember one thing:** keep the universal fallback in mind.

---

## 14.2.6.2 — SETUP COMMAND

**Framing.** `/terminal-setup` installs a Shift+Enter binding for VS Code, Cursor, Devin Desktop, Alacritty or Zed; in Apple Terminal it enables Option+Enter and turns off the audible bell; in iTerm2 it enables clipboard access so `/copy` works [Claude Code docs, Interactive mode, 2026].

| Terminal | /terminal-setup does |
|---|---|
| VS Code, Cursor, Alacritty, Zed | Installs Shift+Enter |
| Apple Terminal | Option+Enter and bell off |
| iTerm2 | Clipboard access for /copy |

The failure mode: **Setup-skipped.** You never run the setup command and live with accidental submits.

The fix: Run it once per terminal.

Cross-references: terminal config is Module 14.1 (configuration).

**If you remember one thing:** run it once.

---

## 14.2.6.3 — REBINDING

**Framing.** `chat:newline` is bound to Ctrl+J by default and can be rebound in the `Chat` context; `chat:submit` is Enter, and `chat:queueSubmit` submits while marking the message to wait its turn [Claude Code docs, Keybindings, 2026].

```json
{"bindings":[{"context":"Chat","bindings":{"enter":"chat:newline","ctrl+enter":"chat:submit"}}]}
```
This swap is an example of the syntax, not a recommendation; test before relying on it.

The failure mode: **Swap-and-stuck.** You swap Enter and Ctrl+Enter, then your terminal does not report Ctrl+Enter and you cannot submit.

The fix: Keep a working submit key and test the new one before saving.

Cross-references: keybindings are Module 14.2 (customise).

**If you remember one thing:** never remove your only submit key.
