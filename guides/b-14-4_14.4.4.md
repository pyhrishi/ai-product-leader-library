## 14.4.4.1 — SMALL PROJECT FILES

**Framing.** `.worktreeinclude` lists gitignored files to copy into new worktrees; `REVIEW.md` customises Code Review and `loop.md` sets default loop prompts per the syllabus. This guide retrieved the `.worktreeinclude` entry from the file reference; REVIEW.md and loop.md detail were not read [Claude Code docs, Explore the .claude directory, 2026].

| File | Purpose | Source |
|---|---|---|
| `.worktreeinclude` | Gitignored files copied into worktrees | Directory reference |
| `REVIEW.md` | Review customisation | Syllabus; not read |
| `loop.md` | Default loop prompt | Commands page mentions it |

The failure mode: **Missing-env-in-worktree.** A new worktree lacks your gitignored `.env` and tests fail for a reason that looks like code.

The fix: List needed gitignored files in `.worktreeinclude`.

Cross-references: worktrees are Module 6.2.

**If you remember one thing:** worktrees do not carry ignored files by default.

## 14.4.4.2 — TRANSCRIPTS AND HISTORY

**Framing.** Transcripts live at `~/.claude/projects/<project>/<session>.jsonl`; `history.jsonl` stores prompts; `file-history/<session>/` holds pre-edit snapshots for checkpoints (the 100 most recent). They are plaintext, and cleanup removes transcript files older than `cleanupPeriodDays`, default 30 days, minimum 1 [Claude Code docs, Explore the .claude directory, 2026].

| Path | Retention |
|---|---|
| `projects/<project>/<session>.jsonl` | `cleanupPeriodDays` (30 default) |
| `file-history/` | 100 most recent checkpoints |
| `history.jsonl` | Kept until deleted |
| `projects/<project>/memory/` | Not swept |

The failure mode: **Plaintext-blindness.** You assume transcripts are protected, but a command that printed a credential wrote it to disk.

The fix: Deny reads of credential files and shorten retention.

Cross-references: security is Module 11.1.

**If you remember one thing:** transcripts are plaintext.

## 14.4.4.3 — REDUCING EXPOSURE

**Framing.** Options: lower `cleanupPeriodDays`; set `CLAUDE_CODE_SKIP_PROMPT_HISTORY`; use `--no-session-persistence` with `-p`; deny reads of credential files; run `claude purge` (previously `claude project purge` before v2.1.288) with `--dry-run` first [Claude Code docs, Explore the .claude directory, 2026].

```bash
claude purge ~/work/my-repo --dry-run
```

The failure mode: **Heapdump-leftover.** You purge a project but leave a `.heapsnapshot` that contains the full conversation and credentials.

The fix: Delete snapshot files by hand; neither the sweep nor purge touches them.

Cross-references: diagnostics are Module 14.1.

**If you remember one thing:** purge does not cover heap snapshots.

## 14.4.4.4 — FEEDBACK BUNDLES

**Framing.** `feedback-bundles/` holds redacted transcript archives written by `/feedback` on third-party providers or without Anthropic credentials, for you to forward [Claude Code docs, Explore the .claude directory, 2026].

| Path | Keep or delete |
|---|---|
| `feedback-bundles/` | Delete after sending |
| `feedback/drafts/` | Review then send or discard |

The failure mode: **Unsent-bundle.** A bundle sits unsent and your report never reaches anyone.

The fix: Forward it to your account team and then delete it.

Cross-references: support routes are Module 10.1.

**If you remember one thing:** writing a bundle is not sending it.
