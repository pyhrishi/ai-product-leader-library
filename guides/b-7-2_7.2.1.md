## 7.2.1.1 — PARALLEL SESSIONS AND GIT ISOLATION

**Framing.** Each Desktop session has its own chat history, project folder, context and changes. Isolation is a choice: turn on Worktree before starting a session in a Git repository, because it is off by default [Claude Code docs, Desktop, 2026].

| Item | Detail |
|---|---|
| New session | `Cmd+N` / `Ctrl+N` |
| Switch sessions | `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| Split view | Hold Option (Mac) or Alt (Windows) and click a session |
| Worktree location | `<project-root>/.claude/worktrees/` by default |
| Copy ignored files such as `.env` into a new worktree | Add a `.worktreeinclude` file at the project root |
| Archive with uncommitted changes | Desktop asks; **Archive anyway** discards them |
| Cleanup | Local worktrees removed about 30 days after archiving or last opening |

An OS notification fires when a session finishes and you are not viewing it. Claude can also list, read, rename, archive and message your other Desktop sessions (it sees the 20 most recent by default) [Claude Code docs, Desktop, 2026].

The failure mode: **Shared-tree collision.** You start two sessions on the same repository with Worktree off and both edit `src/auth.ts`, so each session's diff includes the other's changes.

The fix: Turn Worktree on before the second session starts and add a `.worktreeinclude` for ignored files the app needs.

Cross-references: worktrees themselves are Module 6.2; choosing a parallel approach is Module 6.1.

**If you remember one thing:** Worktree on, or sessions share a tree.

## 7.2.1.2 — PANES: CHAT, DIFF, TERMINAL, EDITOR, SIDE CHAT

**Framing.** Layout is a set of panes: chat, diff, browser, terminal, file, plan, tasks, subagent and, on macOS, the iOS Simulator. Pane layout, terminal, file editor and view modes require Desktop v1.2581.0 or later [Claude Code docs, Desktop, 2026].

| Pane or tool | Open with | Notes |
|---|---|---|
| Terminal | `Ctrl+` backtick or title-bar button | Runs in the session's working directory; local and SSH sessions |
| File editor | Click a path in chat | Editable in local sessions inside the working directory; view-only in cloud, SSH and WSL; auto save on by default |
| Side chat | `Cmd+;` / `Ctrl+;` or `/btw` | Reads the main thread, adds nothing back, not saved to disk |
| Close focused pane | `Cmd+\` / `Ctrl+\` | Panes can pop out to their own window |
| View modes | `Ctrl+O` | Normal, Thinking, Verbose |

`/context` prints a per-category context breakdown and `/compact` summarizes early [Claude Code docs, Desktop, 2026].

The failure mode: **Pane-sprawl.** You open every pane at once on a laptop screen, the chat shrinks to a sliver, and you miss a permission prompt that is waiting.

The fix: Keep chat and one working pane visible, and move the rest into the overflow menu or a separate window.

Cross-references: context management is Module 3.1; keyboard shortcuts are Module 14.2.

**If you remember one thing:** side chat reads but never writes the main thread.

## 7.2.1.3 — THE REVIEW LOOP: DIFF, PREVIEW, PR MONITOR

**Framing.** Open the diff from the Changes card, hover a line and click the plus to comment, then submit all comments with `Cmd+Enter` / `Ctrl+Enter`; Claude applies them and shows a new diff. Previews use `.claude/launch.json` [Claude Code docs, Desktop, 2026].

| Feature | Fact |
|---|---|
| `autoVerify` | Defaults to on: Claude screenshots, checks errors and verifies after edits |
| `launch.json` port | Defaults to 3000; `autoPort: true` picks a free port |
| Secrets in `launch.json` | Do not put them in `env`; the file is committed |
| PR monitoring | Needs `gh` installed and authenticated |
| Auto-fix | From the PR's menu; fixes failing checks and, in local sessions, review comments from owners, members, collaborators or GitHub Apps |
| Merge when ready | Enables GitHub auto-merge; requests a squash merge unless a merge queue is used; needs auto-merge enabled in repo settings; disabled in SSH and WSL |
| `/code-review` | Results arrive as a Code review card with **Walk through in diff** and **Fix this one** |

[Claude Code docs, Desktop, 2026]

The failure mode: **Comment-by-comment churn.** You submit diff comments one at a time, so Claude rewrites the same file five times and each rewrite invalidates the next comment.

The fix: Leave all comments first, then submit them together with the keyboard shortcut.

Cross-references: verification is Module 2.3; local review commands are Module 7.8.

**If you remember one thing:** batch your diff comments, then send.

**A passing artifact looks like this:**

| Check | Evidence |
|---|---|
| Worktree on before start | Path under `.claude/worktrees/` |
| Comments batched | One submit, one new diff |
| PR monitored | Auto-fix toggle on, `gh auth status` ok |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Both sessions in the repo root | **Shared-tree collision** |
| Five separate comment submits | **Comment-by-comment churn** |

**The verdict.** The artifact passes only if two distinct worktree paths are shown and the diff comments were submitted in one batch.
