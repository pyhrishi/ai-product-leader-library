## 10.2.1.1 — SUBSCRIPTIONS: TEAMS AND ENTERPRISE

**Framing.** For most organisations the docs recommend Claude for Teams or Enterprise: one subscription for Claude Code and Claude on the web, centralised billing and no infrastructure. Teams is self-service with admin tools and billing management; Enterprise adds domain capture, role-based permissions, compliance API access and managed policy settings [Claude Code docs, Enterprise deployment overview, 2026]. Usage draws from a per-seat allowance that resets on a rolling five-hour window and a weekly window, shared with chat and Cowork, sized by seat tier (Standard or Premium) [Claude Code docs, Manage costs effectively, 2026].

| Item | Teams | Enterprise |
|---|---|---|
| Billing | $150/seat (Premium) with PAYG available | Contact sales |
| Includes Claude on web | Yes | Yes |
| Extras named by the overview | Team management, SSO, usage monitoring | SSO and domain capture, role-based permissions, compliance API, managed policy |
| Allowance windows | Rolling 5-hour and weekly | Rolling 5-hour and weekly |

The failure mode: **Chat-seat budgeting.** You size coding seats from chat usage, then developers exhaust the weekly allowance because each Claude Code turn carries file contents, tool calls and multi-step reasoning.

The fix: Budget a coding seat above a chat seat; start from the pilot distribution (Module 10.1).

Cross-references: pilot sizing is Module 10.1; plan limits are Module 1.4.

**If you remember one thing:** the allowance is one shared pool, so coding burns it faster than chat.

## 10.2.1.2 — THE CONSOLE PATH

**Framing.** Console suits API-first organisations that want pay-as-you-go billing. Invite users from the Members page or set up SSO, then assign a role: the Claude Code role lets users only create Claude Code API keys; the Developer role lets them create any kind of key [Claude Code docs, Authentication, 2026]. When you first authenticate with a Console account, a workspace called Claude Code is created automatically for centralised cost tracking; you cannot create API keys for it [Claude Code docs, Manage costs effectively, 2026].

| Role | Can do |
|---|---|
| Claude Code | Create only Claude Code API keys |
| Developer | Create any kind of API key |

Console sign-in without an API key (Claude Code v2.1.242 or later) stores an OAuth token as an Anthropic profile instead of a static key [Claude Code docs, Authentication, 2026].

The failure mode: **Over-privileged role.** You invite every engineer as Developer, so anyone can mint production-scoped API keys.

The fix: Assign the Claude Code role by default; grant Developer only to those who build on the API.

Cross-references: key and login precedence is Module 10.3.

**If you remember one thing:** least privilege starts at the invitation.

## 10.2.1.3 — CONSOLE RATE LIMITS

**Framing.** The costs page recommends per-user Token Per Minute and Request Per Minute figures by team size, which apply at the organisation level, so individuals can temporarily exceed their share when others are idle [Claude Code docs, Manage costs effectively, 2026]. Live training sessions may need more.

| Team size | TPM per user | RPM per user |
|---|---|---|
| 1-5 | 200k-300k | 5-7 |
| 20-50 | 50k-75k | 1.25-1.75 |
| 100-500 | 15k-20k | 0.37-0.47 |
| 500+ | 10k-15k | 0.25-0.35 |

Worked example from the docs: 200 users at 20k TPM each is 4 million total TPM.

The failure mode: **Training-day throttle.** You request limits from the steady-state table and then run a 100-person live workshop, so everyone is rate limited at once.

The fix: Request temporary headroom for concentrated sessions.

Cross-references: cost governance is Module 10.6.

**If you remember one thing:** per-user TPM falls as headcount rises, but events break the assumption.

## 10.2.1.4 — CHOOSING FIRST-PARTY

**Framing.** The deployment overview compares six options on billing, regions, authentication and cost tracking; first-party columns use claude.ai SSO or email (subscriptions) or an API key (Console) and track cost in the usage dashboard [Claude Code docs, Enterprise deployment overview, 2026]. Choose first-party when you want features that need a claude.ai account.

| Need | First-party answer |
|---|---|
| Cloud sessions, Routines, Code Review | Subscription seat required |
| Pay per token, API-first | Console |
| Inherit AWS/GCP/Azure compliance | Cloud provider instead (Module 10.2.2) |

The failure mode: **Console-for-everything.** You choose Console because billing is simpler, then discover cloud sessions and Code Review need a subscription.

The fix: List required features before choosing the billing model.

Cross-references: cloud providers are Module 10.2.2; features matrix is Module 10.2.5.

**If you remember one thing:** features pick the account type; billing picks the plan.

## CLOSING REFRAME

This is the craft of first-party choice: **features decide the account type, billing decides the plan, roles follow least privilege.** The administrator who understands this does not ask "which is cheaper?" — they ask "what must developers be able to do?"
