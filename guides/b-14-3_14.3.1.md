## THE THESIS OF THIS TOPIC

**Command-line flags set a session's behaviour before it starts, and the useful ones group into five jobs: scripting, session selection, permission control, isolation and debugging.**

**Prove-it, in one sentence:** run one scripted call with -p and an output format, one resumed-and-forked session, and one debug capture to a file.

**The single most important discipline: pick flags by job, and prefer a narrow permission flag to a broad one.**

**The counterintuitive claim you will learn to defend:** --bare skips auto-discovery of hooks, skills, plugins, MCP servers, auto memory and CLAUDE.md, so a scripted call behaves differently from your interactive setup [Claude Code docs, CLI reference, 2026].

## 14.3.1.1 — SCRIPTING: -P AND FRIENDS

**Framing.** `-p`/`--print` prints the response without interactive mode. `--output-format` takes `text`, `json` or `stream-json`; `--input-format` takes `text` or `stream-json`; `--max-turns` limits agentic turns and exits with an error at the limit; `--max-budget-usd` stops once estimated spend reaches the amount, checked against a client-side estimate that can differ from your bill; `--no-session-persistence` stops sessions being saved; `--bare` gives minimal startup [Claude Code docs, CLI reference, 2026].

```bash
claude -p "summarise failing tests" --output-format json --max-turns 5 --max-budget-usd 2
claude --bare -p "explain this stack trace" < trace.txt
```

| Flag | Print mode only? |
|---|---|
| `--max-turns`, `--max-budget-usd` | Yes |
| `--no-session-persistence` | Yes |
| `--output-format` | Yes |
| `--bare` | Works with `-p`; shown with it |

The failure mode: **Budget-as-bill.** You treat `--max-budget-usd` as an exact spending ceiling, but it is checked against a client-side estimate and spend can pass it.

The fix: Leave headroom under the real limit and confirm against your billing.

Cross-references: headless use is Module 8.1; cost is Module 1.4.

**If you remember one thing:** the cap is an estimate.

## 14.3.1.2 — SESSIONS: -C, -R, -N, --FORK-SESSION, --FROM-PR, --TELEPORT, --CLOUD

**Framing.** `--continue`/`-c` loads the most recent conversation in the current directory and skips `-p` and SDK sessions unless combined with `-p`; `--resume`/`-r` takes an ID, name or picker; `--name`/`-n` names the session; `--fork-session` with resume creates a new session ID; `--from-pr` filters the picker to a pull request; `--teleport` resumes a cloud session locally; `--cloud` creates a cloud session from a task [Claude Code docs, CLI reference, 2026].

```bash
claude -n "auth-refactor"
claude --resume auth-refactor --fork-session
claude --from-pr 123
claude --cloud "Fix the login bug"
```

| Need | Flag |
|---|---|
| Latest here | `-c` |
| Specific one | `-r <id or name>` |
| Same history, new ID | `-r X --fork-session` |
| Everything for a PR | `--from-pr` |

The failure mode: **Continue-misses-sdk.** You run `claude -c` expecting your last scripted `-p` run and it skips it.

The fix: Use `claude -p --continue` for those, or resume by ID.

Cross-references: sessions are Module 2.4; cloud is Module 6.3.

**If you remember one thing:** -c skips -p sessions unless -p is also given.

## 14.3.1.3 — CONTROL AND ISOLATION

**Framing.** `--permission-mode` begins in a mode (`default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions` or `manual`, which needs v2.1.200 or later). `--allowedTools` lists tools that run without prompting and `--disallowedTools` denies them; a bare name removes the tool from Claude's context while a scoped rule denies only matching calls. `--worktree`/`-w` starts in an isolated git worktree under `<repo>/.claude/worktrees/<name>`; `--agent` selects an agent; `--settings` takes a file or inline JSON up to 2 MiB [Claude Code docs, CLI reference, 2026].

```bash
claude -w feature-auth --permission-mode plan
claude --allowedTools "Bash(git log *)" "Bash(git diff *)" "Read"
claude --settings '{"model": "claude-opus-5-5"}'
```

| Flag | Scope |
|---|---|
| `--allowedTools` | Run without prompting |
| `--disallowedTools "Edit"` | Remove Edit entirely |
| `--disallowedTools "Bash(rm *)"` | Deny matching calls only |

The failure mode: **Allow-is-not-restrict.** You use `--allowedTools` to limit what Claude can use, but it only skips prompts; `--tools` restricts availability.

The fix: Use `--tools` or `--disallowedTools` to restrict, `--allowedTools` to pre-approve.

Cross-references: permissions are Module 4.2; worktrees are Module 6.2.

**If you remember one thing:** allow skips prompts; it does not restrict.

## 14.3.1.4 — DEBUGGING

**Framing.** `--debug` enables debug mode with optional categories such as `--debug='mcp,startup'`; the filter binds only in the `=` form. `--debug-file <path>` writes logs to a file, implies debug and beats `CLAUDE_CODE_DEBUG_LOGS_DIR`. `--verbose` shows full turn-by-turn output. `--init-only` runs Setup and SessionStart hooks and exits; `--init` and `--maintenance` run Setup hooks with those matchers in print mode [Claude Code docs, CLI reference, 2026].

```bash
claude --debug='mcp,startup' --debug-file /tmp/claude-debug.log
claude --init-only
```

The failure mode: **Space-separated-filter.** You write `--debug mcp` with a space and get unfiltered debug output.

The fix: Use the `=` form for category filters.

Cross-references: debugging is Part 12; hooks are Module 14.5.

**If you remember one thing:** category filters need an equals sign.
