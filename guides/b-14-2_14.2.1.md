## 14.2.1.1 — THE CYCLE

**Framing.** Shift+Tab cycles through `default` (labelled Manual in the indicator), `acceptEdits`, `plan` and, when available, `bypassPermissions` and then `auto`; from `auto` the first press switches to `default`. On Windows without VT input mode the key is `Alt+M` [Claude Code docs, Interactive mode, 2026].

| From | Next press |
|---|---|
| default (Manual) | acceptEdits |
| acceptEdits | plan |
| plan | bypassPermissions or auto, when available |
| auto | default |

Modes shown depend on availability; read your indicator rather than assuming the order.

The failure mode: **Blind-cycle.** You press Shift+Tab several times without reading the indicator and land in a mode more permissive than you meant.

The fix: Press once, read the indicator, then continue.

Cross-references: modes in depth are Module 4.3.

**If you remember one thing:** one press, one read.

## 14.2.1.2 — A SECOND MEANING ON PROMPTS

**Framing.** On a file permission prompt the same key closes an open comment field; with no field open it selects the option allowing the action for the rest of the session, when the prompt offers that option [Claude Code docs, Interactive mode, 2026]. In the keybindings reference this is `confirm:cycleMode` in the `Confirmation` context [Claude Code docs, Keybindings, 2026].

| Where | Shift+Tab does |
|---|---|
| Main prompt | Cycles mode (`chat:cycleMode`) |
| File permission prompt, field open | Closes the comment field |
| File permission prompt, no field | Allows for the rest of the session |

The failure mode: **Session-allow-by-habit.** You press Shift+Tab on a permission prompt out of mode-cycling habit and grant the action for the whole session.

The fix: On a prompt, press Enter or the numbered option on purpose and treat Shift+Tab as a grant.

Cross-references: permissions are Module 4.2.

**If you remember one thing:** on a prompt, Shift+Tab grants.

---

## 14.2.1.3 — CUSTOMISING IT

**Framing.** `chat:cycleMode` can be rebound in the `Chat` context, and `confirm:cycleMode` in `Confirmation`, through `~/.claude/keybindings.json` [Claude Code docs, Keybindings, 2026]. Changes apply without a restart.

```json
{"bindings":[{"context":"Chat","bindings":{"ctrl+g":"chat:cycleMode"}}]}
```

Choose a key you will not press by accident; reserved keys such as Ctrl+C cannot be used.

The failure mode: **Reserved-rebind.** You bind a mode switch to a reserved key and the binding never fires.

The fix: Pick an unreserved key and check the debug log for validation warnings.

Cross-references: keybinding rules are Module 14.2 (customise).

**If you remember one thing:** bind to unreserved keys.
