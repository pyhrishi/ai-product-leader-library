## 9.1.4.1 — TASK TOOLS AND PLAN MODE IN CLAUDE CODE

**Framing.** Claude Code has task-tracking tools: TaskCreate, TaskGet, TaskList and TaskUpdate. None prompts for permission. TodoWrite is disabled by default in favour of them, and `CLAUDE_CODE_ENABLE_TASKS=0` re-enables it [Claude Code docs, Tools reference, 2026]. The reference says the task tools are provided by default only on the models listed under Task tool availability (it names Opus 4.7, Sonnet 4.6, Haiku 4.5 and earlier), so check your model.

| Mechanism | Lives | Survives `/clear` | Best for |
|---|---|---|---|
| Task tools (TaskCreate etc.) | In the session | No | Pacing a multi-step run |
| PLAN.md with checkboxes | In the repo | Yes | Handoff, review, resume |
| Plan mode plan file | `~/.claude/plans/` or `plansDirectory` | Yes, outside the repo | Approving an approach before edits |

Plan mode: press `Shift+Tab`, prefix a prompt with `/plan`, or start with `claude --permission-mode plan` [Claude Code docs, Permission modes, 2026].

The failure mode: **Two sources of truth.** PLAN.md says step 2 is done while the session task list says it is pending, and nobody knows which is right.

The fix: Name one as canonical (the file) and have Claude mirror ticks into it after each verified step.

Cross-references: plan mode is Module 2.1; sessions and resume are Module 2.4.

**If you remember one thing:** file for durability, tool for pace.

## 9.1.4.2 — A PLAN.MD THAT RESUMES CLEANLY

**Framing.** A plan file helps a fresh session continue. Each step should carry its check so a resumed session can tell done from started. This layout is the guide's own.

```markdown
# PLAN: rate limiter (from SPEC.md)
- [x] 1 Add limiter.ts with check()          verify: vitest limiter  (green, 14:02)
- [x] 2 Wire middleware                      verify: vitest api       (green, 14:20)
- [ ] 3 Add 429 + Retry-After header          verify: curl loop V2
- [ ] 4 Docs + changelog                      verify: link check
## Notes for next session
Step 3 blocked on header name decision D4.
```

The failure mode: **Tick-then-check.** Claude ticks a box when it writes the code, not when the check passes, so the plan overstates progress.

The fix: Define the tick as 'check ran and passed', record the evidence beside the box, and reject unticked-by-evidence steps in review.

Cross-references: specs are Module 9.1.2; verification is Module 9.2.

**If you remember one thing:** a tick means the check ran.

## 9.1.4.3 — USING IT ACROSS RESETS

**Framing.** Starting a session from a file is the same move as the spec workflow: the docs advise a fresh session to build from SPEC.md [Claude Code docs, Best practices, 2026]. `claude --continue` resumes the most recent session in the directory, and `--resume` picks from a list [Claude Code docs, Common workflows, 2026].

| Situation | Move |
|---|---|
| Context bloated mid-plan | `/clear`, then 'continue PLAN.md from the first unticked step' |
| Next day, same work | `claude --continue` or fresh session plus PLAN.md |
| Handoff to a teammate | Commit PLAN.md; they read the notes block |

The failure mode: **Stale plan.** The plan is never updated after reality changed, so the next session executes dead steps.

The fix: Update PLAN.md in the same commit as the code that changes it (Module 9.1.6).

Cross-references: keeping specs alive is Module 9.1.6.

**If you remember one thing:** resume from the file, not from memory.

## THE PROVE-IT SECTION

**Deliverable.** A PLAN.md with four steps, each with a verify command, and a log showing a session reset mid-plan.

**Close this topic. Build the artifact below from memory. Return to the text only after your first attempt is complete.**

| Step | Action | Output |
|---|---|---|
| 1 | Write PLAN.md from a spec | File |
| 2 | Run step 1 and 2 with evidence | Ticks and logs |
| 3 | `/clear` | New context |
| 4 | Resume from the first unticked step | Transcript |
| 5 | Finish and commit PLAN.md | Commit |

**A passing artifact looks like this:**

| Check | Evidence |
|---|---|
| Ticks with evidence | 2 with timestamps |
| Resume from file | Transcript quotes step 3 |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Ticks without evidence | **Tick-then-check** |
| Plan lists finished work as pending | **Stale plan** |

**The verdict.** The artifact passes only if every ticked box has evidence and the resumed session started from the first unticked step.
