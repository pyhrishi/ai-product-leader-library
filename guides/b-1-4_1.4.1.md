## 1.4.1.1 — INCLUDED, BUT WINDOWED

**Framing.** On a subscription, Claude Code usage is included in the plan and limited by rolling windows rather than billed per token [Claude Code docs, Costs, 2026]. Anthropic's help material describes a five-hour session limit and a weekly limit [Claude Help Center, 2026]. Plan prices and window lengths change often; read claude.com/pricing and your Console for current figures.

| Item | Detail |
|---|---|
| Included | Claude Code on Pro, Max, Team and Enterprise plans |
| Horizons | A session window of about five hours, and a weekly limit |
| Higher tiers | Max in 5x and 20x variants |
| Shared pool | Claude Code and the Claude apps draw on the same plan limits [confirm on your plan page] |
| Subagents | Count toward the same limits as the main conversation [Claude Code docs, Subagents, 2026] |

The failure mode: **Limit-surprise.** You start a large multi-agent task near the end of a window or late in the week, and the run stalls half done.

The fix: Check `/usage` before heavy work, split into resumable chunks with checkpoint commits, and start big runs after a reset.

Cross-references: subagents are Module 1.2.5; session management is Module 2.4.

**If you remember one thing:** a subscription trades a bill for a window.

## 1.4.1.2 — /USAGE IS THE INSTRUMENT

**Framing.** For Pro and Max the session cost figure is not relevant to billing; `/usage` instead shows plan usage bars, activity stats and a breakdown of what counts against your limits [Claude Code docs, Costs, 2026]. The authoritative billing view for API users is the Usage page in the Console.

```text
/usage     # plan bars, activity, breakdown of what is counting
/context   # why: where this session's tokens are going now
```

| You see | It means |
|---|---|
| Bars near full | The window is close to its limit |
| Large subagent share | Fan-out is the driver |
| Large context | Re-reads of a big history are the driver |

The failure mode: **Blind-burn session.** A long-lived session accumulates context and background agents, every turn re-reads it, and the bar drains faster than the work justifies.

The fix: `/clear` between tasks, `/compact` with a focus before long new tasks, and read `/usage` hourly during heavy work.

Cross-references: context is Module 3.1; compaction is Module 1.2.4.

**If you remember one thing:** `/usage` says what, `/context` says why.

## 1.4.1.3 — WHAT DRIVES CONSUMPTION

**Framing.** Anything that makes the model read or write more tokens drains the window: long sessions, many parallel subagents, high effort, large file reads and verbose tool output. The window you hit is a symptom; the context is the cause.

| Driver | Control |
|---|---|
| Long history | `/clear`, `/compact focus on ...` |
| Fan-out | Delegate only large read-heavy work |
| High effort | Lower it for mechanical steps |
| Big reads | Scope paths and patterns |
| Noisy output | Pipe to a file, read the tail |

The failure mode: **Driver-blindness.** You blame the plan for the limit and never look at which driver used the window.

The fix: Read `/usage` and `/context` and name the dominant driver before changing anything.

Cross-references: cost habits are Module 1.4.5; effort is Module 1.4.3.

**If you remember one thing:** name the driver, then change one thing.

## 1.4.1.4 — WHEN YOU HIT THE WALL

**Framing.** Anthropic's help material lists the options: upgrade (Pro to Max 5x, Max 5x to Max 20x), enable usage credits to continue past the limit, switch to a Console account with API credits, or wait for the reset. The Max plan's monthly API credits cannot be used in Claude Code or the Claude apps [Claude Help Center, 2026].

| Option | Trade-off |
|---|---|
| Wait for reset | Free, costs time |
| Upgrade tier | Higher fixed cost, more capacity |
| Usage credits | Pay-as-you-go overflow; needs a monthly cap |
| Console account | Per-token billing and workspace limits |

The failure mode: **Panic-upgrade.** You upgrade a tier at the first limit hit without checking whether one habit explains the drain.

The fix: Measure first; upgrade only when a clean, scoped workflow still hits the wall.

Cross-references: API billing is Module 1.4.2.

**If you remember one thing:** fix the habit before you buy the tier.
