## THE THESIS OF THIS TOPIC

**Compaction replaces the conversation with a summary, and what comes back depends on how each thing was loaded: some is re-injected from disk, some reloads on demand, some is summarised away.**

**Prove-it, in one sentence:** predict the post-compaction state of ten items and verify five of them.

**The single most important discipline: never rely on conversation for anything that must persist; know which loader re-injects.**

**The counterintuitive claim you will learn to defend:** path-scoped rules and nested CLAUDE.md files are summarised away with the rest of the conversation and only reload when Claude touches their trigger file again [Claude Code docs, Context window, 2026].

## 3.1.7.1 — THE SURVIVAL TABLE

**Framing.** When a long session compacts, Claude Code summarises the history to fit; what happens to each kind of content depends on how it was loaded [Claude Code docs, Context window, 2026]. As of v2.1.198 the summarisation request inherits your session's extended-thinking configuration.

| Mechanism | After compaction |
|---|---|
| System prompt and output style | Still apply |
| Project-root CLAUDE.md, unscoped rules | Re-injected from disk |
| Auto memory | Re-injected from disk |
| Skill descriptions | Rebuilt and re-injected (v2.1.304 or later) |
| Plan-mode plan | Re-injected from disk |
| Rules with `paths:` frontmatter | Reload on demand |
| Nested CLAUDE.md | Reload on demand |
| Files read or edited | Up to five re-read, most recently modified first |
| Invoked skill bodies | Re-injected, 5,000 tokens per skill, 25,000 total |
| Hook-added context | Summarised with the conversation |
| SessionStart hooks matching `compact` | Run; output added |

The failure mode: **Survival-assumption.** You assume everything in context before compaction is still there after, then act on a rule or file that was summarised away.

The fix: Consult the survival table and re-verify critical items after any compaction.

Cross-references: rules files are Module 3.3; hooks are Module 5.4.

**If you remember one thing:** survival depends on the loader.

## 3.1.7.2 — FILES, SKILLS AND CAPS

**Framing.** Right after compaction Claude Code re-reads up to five files Claude read or edited, most recently modified first; a file over 5,000 tokens comes back as a path reference shown as `Referenced file` instead of `Read` [Claude Code docs, Context window, 2026]. Skill bodies are re-injected but capped at 5,000 tokens per skill and 25,000 total, oldest dropped first; truncation keeps the start of the file, so put the most important instructions near the top of `SKILL.md`.

| Cap | Value |
|---|---|
| Files re-read | 5 |
| File size for content return | 5,000 tokens |
| Per invoked skill | 5,000 tokens |
| Total invoked skills | 25,000 tokens |

The failure mode: **Buried-instruction.** You put the critical rule at the bottom of a long SKILL.md and truncation cuts it after compaction.

The fix: Put the most important instructions at the top of the skill file.

Cross-references: skill authoring is Module 5.1.

**If you remember one thing:** caps cut from the end.

## 3.1.7.3 — MAKING RULES PERSIST

**Framing.** If a rule must persist across compaction, drop the `paths:` frontmatter or move it to the project-root CLAUDE.md; path-scoped rules and nested files load into message history when Claude touches a trigger file, so compaction summarises them [Claude Code docs, Context window, 2026]. Conversation-only instructions are lost, so write them into CLAUDE.md [Claude Code docs, Memory, 2026]. A SessionStart hook with the `compact` source can re-inject context [Claude Code docs, Context window, 2026].

```text
Must persist?
  conversation only           -> will be lost
  project-root CLAUDE.md      -> re-injected
  .claude/rules, no paths     -> re-injected
  .claude/rules with paths    -> reload on demand only
  SessionStart (compact)      -> re-run after compaction
```

The failure mode: **Scoped-rule loss.** You scope a must-always rule with `paths:` and after compaction Claude no longer has it until it reads a matching file.

The fix: Remove the `paths:` filter or move the rule to the project-root CLAUDE.md.

Cross-references: path scoping is Module 3.3.

**If you remember one thing:** scope trades persistence for context.

## 3.1.7.4 — BACKGROUND WORK AND THE THRASHING GUARD

**Framing.** Background commands and background subagents keep running through compaction, and Claude Code reminds Claude which are still running so it does not start a duplicate [Claude Code docs, Context window, 2026]. If one file or tool output is so large that context refills right after each summary, Claude Code stops auto-compacting after a few attempts and shows an error instead of looping [Claude Code docs, How Claude Code works, 2026].

| Case | Outcome |
|---|---|
| Background command running | Continues; reminder injected |
| Refill after every summary | Thrashing error after a few attempts |
| Git status snapshot | Fresh one read if the session started with one |

The failure mode: **Refill-loop.** A single huge output refills the window after each summary, so compaction repeats until the thrashing error appears.

The fix: Find the oversized file or output, stop reading it whole, and use bounded or delegated reads.

Cross-references: troubleshooting is Module 1.3.

**If you remember one thing:** fix the source of the refill.
