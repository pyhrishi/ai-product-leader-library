## THE THESIS OF THIS TOPIC

**Pre-ship commands split by question: /diff shows what changed, /code-review finds correctness bugs, /simplify finds cleanup, /security-review finds vulnerabilities and /verify checks the app actually runs.**

**Prove-it, in one sentence:** run each pre-ship command on one branch and say which question each answered.

**The single most important discipline: match the command to the question and never treat a clean cleanup review as a correctness review.**

## 14.1.4.1 — LOOK AND REVIEW

**Framing.** `/diff` reviews working-tree changes including Claude's edits. `/code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]` is a bundled skill that reviews the diff, a PR number, a branch or a path for correctness bugs; `--fix` applies findings, `--comment` posts them, `ultra` runs a deep cloud review; alias `/review` [Claude Code docs, Commands, 2026].

| Command | Question | Output |
|---|---|---|
| `/diff` | What changed? | Working-tree diff |
| `/code-review high` | Is it correct? | Findings |
| `/code-review high --fix` | Fix what you found | Applied edits |
| `/code-review 1234` | Review PR 1234 | Findings on that PR |
| `/code-review ultra` | Deep review | Cloud multi-agent review |

The failure mode: **Review-as-rubber-stamp.** You run `/code-review --fix` and merge the applied edits unread, so the reviewer and the author are the same unchecked process.

The fix: Read the diff of the applied fixes with `/diff` and rerun your check before commit.

Cross-references: review is Module 2.3 and Module 7.3.

**If you remember one thing:** review the review.

## 14.1.4.2 — CLEANUP AND SECURITY

**Framing.** `/simplify [target]` runs four parallel review agents covering reuse of existing helpers, simplification, efficiency and abstraction level, and applies fixes. `/security-review` analyses the diff against origin's default branch for injection, auth and data-exposure risks, and needs an `origin` remote [Claude Code docs, Commands, 2026].

| Command | Looks for | Does not look for |
|---|---|---|
| `/simplify` | Reuse, simplification, efficiency, abstraction | Correctness bugs |
| `/code-review` | Correctness bugs | (cleanup only at some effort levels) |
| `/security-review` | Injection, auth, exposure | General style |

The failure mode: **Wrong-question-clean.** You see a clean `/simplify` result and conclude the change is safe, though that review never looked for correctness or security issues.

The fix: Run `/code-review` and `/security-review` for those questions and keep `/simplify` for cleanup.

Cross-references: security is Module 4.4 and Module 11.1.

**If you remember one thing:** a clean result answers only its own question.

## 14.1.4.3 — PROVE IT RUNS, THEN HAND OFF

**Framing.** `/verify` builds your project's app, runs it and observes the result rather than relying on tests or type checks; `/run` launches and drives the app, and `/verify` runs only when you invoke it (before v2.1.215 Claude could run it itself). `/autofix-pr [prompt]` spawns a cloud session that watches the branch's PR and pushes fixes for CI failures and review comments, needing the `gh` CLI and cloud access. `/install-github-app` installs the GitHub App for github.com repositories only [Claude Code docs, Commands, 2026].

```text
/autofix-pr only fix lint and type errors
```

| Step | Command |
|---|---|
| Does the app work? | `/verify` |
| Drive the app manually | `/run` |
| Keep a PR green | `/autofix-pr` |
| Connect GitHub | `/install-github-app` (github.com only) |

The failure mode: **Unbounded-autofix.** You start `/autofix-pr` with no instruction and the cloud session tries to fix every CI failure and review comment, including ones you wanted to handle yourself.

The fix: Pass a prompt that bounds scope and review each push.

Cross-references: CI integration is Module 8.1; Actions are Module 8.2.

**If you remember one thing:** bound the autofix prompt.

## THE PROVE-IT SECTION

**Deliverable.** A pre-ship checklist run on a real branch with the output of each command.

**Close this topic. Build the artifact below from memory. Return to the text only after your first attempt is complete.**

| Step | Action | Output |
|---|---|---|
| 1 | Make a small change on a branch | Diff |
| 2 | Run `/diff` and `/code-review high` | Findings |
| 3 | Run `/simplify` and record what it changed | Cleanup diff |
| 4 | Run `/security-review` and record result | Report |
| 5 | Run `/verify` and capture the observed behaviour | Log |
| 6 | Fill the checklist with the question each answered | Checklist |

**A passing artifact looks like this:**

| Command | Question | Result |
|---|---|---|
| `/diff` | What changed | 3 files |
| `/code-review high` | Correct? | 1 finding fixed |
| `/security-review` | Vulnerable? | None found |
| `/verify` | Runs? | Yes, observed |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Only `/simplify` run | **Wrong-question-clean** |
| Fixes applied, not re-diffed | **Review-as-rubber-stamp** |

**The verdict.** The artifact passes only if each question has its own command and an observed result.
