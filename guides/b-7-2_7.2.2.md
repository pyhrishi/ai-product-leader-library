## 7.2.2.1 — THE TOOL PRIORITY ORDER

**Framing.** Claude tries the most precise tool first. In Desktop the order is connector, then Bash, then Claude in Chrome, then iOS Simulator, then computer use, which is the last resort [Claude Code docs, Desktop, 2026].

| Rank | Tool | Use when |
|---|---|---|
| 1 | Connector (MCP) | A service has a structured integration |
| 2 | Bash | The task is a shell command |
| 3 | Claude in Chrome | Browser work as yourself, in logged-in sessions |
| 4 | iOS Simulator pane | Simulated iOS device (macOS) |
| 5 | Computer use | Native apps and GUI-only tools |

Computer use needs a Pro or Max plan (not Team or Enterprise), is a research preview, and requires macOS 14 or later or Windows. Enable it under Settings, This computer, System. On macOS, grant Accessibility and Screen Recording [Claude Code docs, Desktop, 2026].

The failure mode: **Screen-first reflex.** You ask for computer use on a task a connector or shell command could do, and it takes minutes to click through what a command does in seconds.

The fix: State the precise tool in the prompt, or ask Claude which of the five it will use before it starts.

Cross-references: MCP connectors are Module 5.5; the CLI version of computer use is Module 7.6.

**If you remember one thing:** last resort means last.

## 7.2.2.2 — APPROVAL TIERS AND WHAT THEY PERMIT

**Framing.** App access is fixed by category, and you approve per app. The prompt offers Allow for this session or Deny; approvals last the session, or 30 minutes for Dispatch-spawned sessions [Claude Code docs, Desktop, 2026].

| Tier | Capability | Typical apps |
|---|---|---|
| View only | Screenshots only | Browsers, trading platforms |
| Click only | Click and scroll; no typing or shortcuts | Terminals, IDEs |
| Full control | Click, type, drag, shortcuts | Everything else |

Settings include Denied apps (rejected without prompting) and Unhide apps when Claude finishes. On macOS, computer use can run in the background while you work in other apps. Claude flags possible prompt injection from on-screen content [Claude Code docs, Desktop, 2026]. The docs for this guide do not state which Desktop version first shipped background computer use; check the changelog [not verified].

The failure mode: **Blanket-approval habit.** You click Allow for every prompt without reading which app is requested, including a terminal, which is equivalent to shell access.

The fix: Read the app name and its warning, deny anything you did not expect, and add sensitive apps to Denied apps.

Cross-references: least privilege is Module 11.3; prompt injection is Module 11.2.

**If you remember one thing:** an approval is a delegation of your desktop.

## 7.2.2.3 — THE BUILT-IN BROWSER PANE

**Framing.** Open it with `Cmd+Shift+B` / `Ctrl+Shift+B` or the title-bar button. It uses a clean profile with no logins, and Google OAuth sign-in flows work. For logged-in sessions use the Chrome extension instead [Claude Code docs, Desktop, 2026].

| Behavior | Detail |
|---|---|
| Write actions (click, type) on external pages | Reviewed by classifiers in every mode |
| Domain allowlist | Also checked in non-Auto, non-Bypass modes |
| First action on a site | Allow once, Always allow (per site, subdomains separate) or Deny |
| Localhost and project files | No approval needed |
| Claude will not | Buy things, create accounts or bypass CAPTCHAs without you |
| Managed control | `browserExternalPageTools` disables Claude's tools on external pages; `disableBrowserExternalNavigation` blocks external navigation |

[Claude Code docs, Desktop, 2026]

The failure mode: **Always-allow creep.** You choose Always allow on a site once for convenience and later forget that Claude can now act there with no prompt.

The fix: Use Allow once for sites you do not own, and review saved allowances periodically.

Cross-references: Chrome is Module 7.6; managed settings are Module 10.4.

**If you remember one thing:** the Browser is clean; Chrome is you.

## CLOSING REFRAME

This is the craft of screen control: **precise tools first, approvals as delegation.** The engineer who understands this does not ask "can it click this?" — they ask "which tool is least powerful that still does the job?"
