## 3.2.5.1 — THE FIVE CLASSES

**Framing.** The guidance is to omit anything derivable from reading code, standard conventions, long API docs (link instead), frequently changing information and file-by-file descriptions [course brief for this topic; the Memory page read gives the include side and a size target of under 200 lines per file, not an explicit exclusion list, so verify the list against the current Best practices page]. The Memory page does say to keep the file to facts held every session and to move area-specific guidance elsewhere [Claude Code docs, Memory, 2026].

| Class | Why exclude | Replace with |
|---|---|---|
| Derivable from code | Claude reads it anyway | Nothing |
| Standard conventions | Already default behaviour | Nothing |
| Long API docs | Costs every request | Link, or a skill |
| Fast-changing facts | Stale quickly | Point to the source file |
| File-by-file descriptions | Drift from reality | Directory-level note at most |

The failure mode: **Map-in-memory.** You list every file and its purpose in CLAUDE.md, and after two refactors Claude follows a map that no longer matches the tree.

The fix: Delete the file list and, if needed, describe only stable directory roles.

Cross-references: per-directory files are Module 3.5.

**If you remember one thing:** stale confidence is worse than none.

## 3.2.5.2 — IMPORTS DO NOT REDUCE COST

**Framing.** Imports load at launch, so they organise content but do not reduce context [Claude Code docs, Memory, 2026]. Moving long reference content into an `@import` therefore does not fix a bloat problem; a skill or path-scoped rule does, because those load on demand [Claude Code docs, Extend Claude Code, 2026].

| Technique | Reduces always-on context? |
|---|---|
| `@docs/api.md` import | No; loads at launch |
| Skill with the content | Yes; body loads on use |
| Path-scoped rule | Yes; loads on matching files |
| Link in prose | Yes; Claude fetches if needed |

The failure mode: **Import-as-diet.** You split a 600-line file into imports and believe you cut context, but all of it still loads at launch.

The fix: Move the content to a skill or path-scoped rule, or delete it.

Cross-references: imports are sub-topic 3.2.8 of Module 3.2.

**If you remember one thing:** imports organise, they do not shrink.

## 3.2.5.3 — AUDIT PROCEDURE

**Framing.** The `/doctor` checkup suggests cuts for anything Claude can already work out from the code, and the prompt audit flags instructions written for older models, pointing at files that no longer exist, or contradicting each other [Claude Code docs, Best practices, 2026]. Review CLAUDE.md edits in pull requests and revisit after major model releases, since a workaround for an older model's limitation may become overhead [Claude Code docs, Large codebases, 2026].

```text
Audit pass
 1. /doctor            -> proposed cuts
 2. /doctor prompt-audit -> outdated, missing-path, contradictory lines
 3. Hand review each proposed cut; keep gotchas
 4. /context           -> confirm load size after
```

The failure mode: **Model-era residue.** Rules written to work around an older model's weakness stay in the file after newer models no longer need them.

The fix: Revisit the file after each major model release and delete outdated workarounds.

Cross-references: model changes are Module 2.6.

**If you remember one thing:** rules have a shelf life.

## CLOSING REFRAME

This is the craft of exclusion: **if it can go stale, point to the source.** The engineer who understands this does not ask "what else can I add?" — they ask "what will be wrong in a month?"
