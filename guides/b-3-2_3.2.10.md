## THE THESIS OF THIS TOPIC

**You can tell Claude what to preserve when it compacts, through a Compact Instructions section in CLAUDE.md or a focus on /compact, and the project-root file itself is re-read from disk afterwards.**

**Prove-it, in one sentence:** compact twice, once bare and once with instructions, and show what each kept.

**The single most important discipline: decide what must survive compaction before a long task, and write it where compaction reads.**

**The counterintuitive claim you will learn to defend:** the automatic pass guesses what matters; your focus replaces the guess [Claude Code docs, Context window, 2026].

## 3.2.10.1 — TWO CONTROLS

**Framing.** To control what is preserved during compaction, add a 'Compact Instructions' section to CLAUDE.md or run `/compact` with a focus such as `/compact focus on the API changes` [Claude Code docs, How Claude Code works, 2026]. The automatic pass preserves your requests and key code snippets; detailed instructions from early in the conversation may be lost.

| Control | When | Persists |
|---|---|---|
| Compact Instructions in CLAUDE.md | Every compaction | In the file |
| `/compact focus ...` | That compaction | One-off |
| `/compact keep the API changes and the test commands` | That compaction | One-off |

The failure mode: **Bare-compaction.** You rely on automatic compaction to preserve the failing test and modified files, and the summary omits them.

The fix: Name modified files and test commands in Compact Instructions or the `/compact` focus.

Cross-references: managing context is sub-topic 3.1.5 of Module 3.1.

**If you remember one thing:** say what to keep.

---

## 3.2.10.2 — WHAT TO NAME

**Framing.** Sensible items to preserve are the files modified, the exact test and build commands and the current plan state; the docs give the examples 'API changes' and 'test commands' and 'the auth bug fix' as focuses [Claude Code docs, Context window; Best practices, 2026]. The docs read do not specify a required format for the Compact Instructions section.

```markdown
## Compact Instructions
When compacting, always keep: the list of modified files, the exact failing test
command, and any decisions recorded in PLAN.md. Drop exploratory search output.
```

[wording is an illustrative example, not documented text]

The failure mode: **Overstuffed-preserve.** You list so many things to preserve that the summary becomes a transcript and frees little space.

The fix: Keep the list to the few items you cannot rederive.

Cross-references: plan files are Module 2.2.

**If you remember one thing:** preserve what you cannot rederive.

---

## 3.2.10.3 — WHAT RE-INJECTS WITHOUT HELP

**Framing.** After compaction the project-root CLAUDE.md and unscoped rules are re-read from disk, nested subdirectory files reload only when Claude next reads a file there, and conversation-only instructions are lost [Claude Code docs, Memory, 2026]. A SessionStart hook matching the `compact` source can add context after compaction [Claude Code docs, Context window, 2026].

| Item | After compaction |
|---|---|
| Root CLAUDE.md | Re-read |
| Nested CLAUDE.md | On demand |
| Chat-only rule | Lost |
| SessionStart `compact` hook output | Added |

The failure mode: **Duplicate-state.** You copy state into Compact Instructions that already re-injects from the root file, wasting space.

The fix: Preserve only what no loader restores.

Cross-references: survival is sub-topic 3.1.7 of Module 3.1.

**If you remember one thing:** do not preserve what reloads.
