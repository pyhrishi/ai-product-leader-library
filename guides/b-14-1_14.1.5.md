## 14.1.5.1 — RESUME, RENAME, EXPORT

**Framing.** `/resume [session]` resumes a conversation by ID or name or opens the picker, and background sessions appear marked `bg`. `/rename [name]` renames the session and shows the name on the prompt bar; with no name it generates one from history. `/export [filename]` exports the conversation as plain text, writing to the file if you give a name [Claude Code docs, Commands, 2026].

| Command | Input | Output |
|---|---|---|
| `/rename auth-refactor` | Name | Label in prompt bar and picker |
| `/export notes.txt` | File name | Plain-text transcript |
| `/resume auth-refactor` | Name or ID | That conversation |

The failure mode: **Unnamed-session.** You leave sessions with auto-generated or no names and cannot find the right one in the picker a week later.

The fix: Run `/rename` as soon as the task has a name and use `/clear <name>` when switching.

Cross-references: session management is Module 2.4.

**If you remember one thing:** name sessions you will want back.

## 14.1.5.2 — MOVE BETWEEN DEVICES

**Framing.** `/teleport` (alias `/tp`) pulls a cloud session into this terminal and requires a claude.ai subscription. `/remote-control` (alias `/rc`) makes this session available from claude.ai. `/desktop` (alias `/app`) continues the session in the Desktop app and requires macOS or x64 Windows and a subscription [Claude Code docs, Commands, 2026].

| Direction | Command | Needs |
|---|---|---|
| Cloud to terminal | `/teleport` | claude.ai subscription |
| Terminal to other device | `/remote-control` | claude.ai subscription |
| Terminal to Desktop app | `/desktop` | macOS or x64 Windows, subscription |

The failure mode: **Platform-assumption.** You tell a teammate to run `/desktop` and it is missing on their machine because of platform or plan.

The fix: Check the availability note and `/help` before documenting a command in a team guide.

Cross-references: platforms are Module 9.1 and Module 6.3.

**If you remember one thing:** availability is per platform and plan.

## 14.1.5.3 — MOVE VERSUS ADD A DIRECTORY

**Framing.** `/cd <path>` moves the session to a new working directory and keeps the conversation. `/add-dir <path>` adds a working directory for file access during the session; most `.claude/` configuration is not discovered from the added directory [Claude Code docs, Commands, 2026]. Per the settings docs, after `/cd` Claude Code reads both project settings files from the new directory, which requires v2.1.246 or later [Claude Code docs, Settings, 2026].

| | `/cd` | `/add-dir` |
|---|---|---|
| Working directory | Changes | Stays; another is added |
| Project settings read from | New directory (v2.1.246+) | Original only |
| Use for | Switching project | Reading a sibling repo |

The failure mode: **Config-from-added-dir.** You `/add-dir` a repo expecting its CLAUDE.md, skills and hooks to apply, and none do.

The fix: Use `/cd` to switch projects, or start Claude there.

Cross-references: memory loading is Module 3.3; permissions are Module 4.2.

**If you remember one thing:** add-dir gives files, not configuration.

## CLOSING REFRAME

This is the craft of moving work: **name it, export it, and pick cd or add-dir deliberately.** The engineer who understands this does not ask "how do I get back to that?" — they ask "did I name it, and does the destination load its own configuration?"
