## THE THESIS OF THIS TOPIC

**Keep SKILL.md short and put long references, scripts and examples in files the skill points to, so Claude reads them only when needed.**

**Prove-it, in one sentence:** split an oversized skill into a focused SKILL.md under 500 lines plus linked files, and show Claude loads a reference file only when relevant.

**The single most important discipline: every supporting file must be mentioned from SKILL.md with a line saying when to read it.**

**The counterintuitive claim you will learn to defend:** a script in the skill folder is executed, not loaded: it costs no context until its output appears [Claude Code docs, Skills, 2026].

## 5.2.7.1 — THE LAYOUT

**Framing.** Skills can bundle other files so SKILL.md stays focused. The docs' layout has `SKILL.md` as the required overview and navigation, `reference.md` and `examples.md` loaded when needed, and `scripts/helper.py` executed rather than loaded; the tip is to keep SKILL.md under 500 lines and move detailed material to separate files [Claude Code docs, Skills, 2026].

```text
my-skill/
  SKILL.md        required: overview and navigation
  reference.md    detailed API docs, loaded when needed
  examples.md     usage examples, loaded when needed
  scripts/helper.py   executed, not loaded
```

The failure mode: **Orphan file.** A reference file sits in the skill folder but SKILL.md never mentions it, so Claude never knows when to read it.

The fix: Reference every file from SKILL.md with a when-to-read line.

Cross-references: context cost is sub-topic 5.1.8.

**If you remember one thing:** SKILL.md navigates; files hold the depth.

---

## 5.2.7.2 — WHY SHORT MATTERS

**Framing.** A skill's rendered body enters the conversation as one message and stays across turns; after compaction only the first 5,000 tokens of each recently invoked skill are re-attached, within a combined 25,000 [Claude Code docs, Skills, 2026]. A short body stays complete; a long one is cut.

| Size | Consequence |
|---|---|
| Under 500 lines | Fits the tip; stays whole after compaction if within the token budget |
| Long body | Persistent cost in every later turn; truncated on re-attach |
| Instructions near the top | Survive truncation |

The failure mode: **Tail-loaded rules.** The most important rule sits at the bottom of a long SKILL.md and is lost when compaction keeps only the first 5,000 tokens.

The fix: Put the critical instructions first and the detail in linked files.

Cross-references: compaction behaviour is Module 3.1 and sub-topic 5.2.12.

**If you remember one thing:** the top of the file is the safe place.

## 5.2.7.3 — SCRIPTS AND VISUAL OUTPUT

**Framing.** The docs show a skill that bundles a script: its SKILL.md tells Claude to run `python3 ${CLAUDE_SKILL_DIR}/scripts/visualize.py .`, which writes an interactive HTML file and opens it; `${CLAUDE_SKILL_DIR}` resolves at personal, project or plugin level, and `allowed-tools: Bash(python3 *)` pre-approves the call [Claude Code docs, Skills, 2026].

| Job | Where it lives |
|---|---|
| Choosing when and how | SKILL.md prose |
| Deterministic work | `scripts/` |
| Long reference | `reference.md` |
| Output for you | Generated file, path printed |

The failure mode: **Hard-coded path.** A skill calls its script by an absolute path on your machine and breaks for teammates or after a plugin install.

The fix: Use `${CLAUDE_SKILL_DIR}` in every script path.

Cross-references: plugin install is sub-topic 5.6.3.

**If you remember one thing:** scripts do the deterministic part; SKILL.md decides when.
