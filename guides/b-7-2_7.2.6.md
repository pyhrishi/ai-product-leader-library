## 7.2.6.1 — INSTALL ROUTES

**Framing.** Installs differ by platform [Claude Code docs, Desktop, 2026]; the Linux page gives the apt route [Claude Code docs, Desktop on Linux, 2026].

| Platform | Install | Updates |
|---|---|---|
| macOS | Universal `.dmg` (Intel and Apple Silicon) | Claude, Check for Updates |
| Windows | x64 installer; ARM64 installer is separate | Help, Check for Updates |
| Linux (beta) | Anthropic apt repository, or a downloaded `.deb` | Your system's regular package updates (`sudo apt update && sudo apt upgrade`); the app does not update itself |

Linux requirements: Ubuntu 22.04 or later, or Debian 12 or later, on x86_64 or arm64. Verify the repository signing key fingerprint `31DDDE24DDFAB679F42D7BD2BAA929FF1A7ECACE` before installing [Claude Code docs, Desktop on Linux, 2026].

The failure mode: **Distro-blind install.** You try the apt route on Fedora or Arch and the package never appears.

The fix: Use the CLI on non-Debian distributions, which the docs say supports a wider range.

Cross-references: installation overall is Module 1.3; the CLI fallback is Module 7.1.

**If you remember one thing:** Debian family for Desktop, anything for the CLI.

## 7.2.6.2 — LINUX BETA: WHAT IS MISSING

**Framing.** The Linux beta gives parallel sessions, visual diff review, an integrated terminal and editor, and live preview, but several things are absent [Claude Code docs, Desktop on Linux, 2026].

| Missing on Linux beta | Detail |
|---|---|
| Computer Use | Not available |
| Dictation | Not available; use CLI voice dictation |
| Quick Entry global hotkey | Works on X11; native Wayland needs the GlobalShortcuts portal |
| Fedora and RHEL | Unsupported today |
| Cowork (for Dispatch) | Needs KVM, QEMU and UEFI firmware, and `kvm` group membership; checked once at launch |

Common fixes: sign-in not saved means a locked or missing keyring (install `gnome-keyring` or avoid having both keyrings under KDE Plasma); running as root without `--no-sandbox` is not supported [Claude Code docs, Desktop on Linux, 2026].

The failure mode: **Cowork-prereq miss.** Dispatch or Cowork reports it needs QEMU or KVM because you installed with `--no-install-recommends` or never joined the `kvm` group.

The fix: Install the recommended QEMU packages, enable virtualization in firmware, add your user to `kvm`, then log out and in and restart the app.

Cross-references: Dispatch is covered earlier in Module 7.2; remote access is Module 7.5.

**If you remember one thing:** check the requirements once at launch, restart after fixing.

## 7.2.6.3 — WSL 2 SESSIONS

**Framing.** On Windows, the Code tab can run a session inside a WSL 2 distribution: Claude Code, its tools and git all run in the distribution, with Linux paths [Claude Code docs, Desktop in WSL, 2026].

| Fact | Detail |
|---|---|
| Requirements | Windows 10 or 11 with WSL 2 (WSL 1 unsupported); a distribution; git inside it |
| Trust | Granted per distribution and folder |
| Works | Parallel sessions, side chats, diff review, PR status, worktrees |
| Missing | Integrated terminal, connectors and plugins, session forking, file browser pane, `@` file suggestions |
| Merge when ready | Disabled in WSL |
| Editor | Open in editor uses VS Code Remote - WSL |

Use WSL when your repo lives in the distribution's filesystem; working on it from Windows goes through a network filesystem that is slow and breaks file watching [Claude Code docs, Desktop in WSL, 2026]. On managed devices WSL sessions may be unavailable.

The failure mode: **Cross-filesystem slog.** You keep the repository on the Windows side and run a WSL session on it, so file watching breaks and everything is slow.

The fix: Keep the repository inside the distribution and open it with a WSL session.

Cross-references: IDE use under WSL is Module 7.3; sandboxing is Module 4.4.

**If you remember one thing:** repo and session in the same filesystem.
