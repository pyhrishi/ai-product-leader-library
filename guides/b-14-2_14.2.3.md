# MODULE 14.2.3 — CTRL+G: EDITING PROMPTS AND PLANS IN YOUR EDITOR: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**Ctrl+G hands the prompt to your own text editor, which is the right move for long prompts, plans and structured instructions.**

**Prove-it, in one sentence:** write a multi-paragraph prompt in your editor via Ctrl+G and submit it.

**The single most important discipline: move to the editor when the prompt exceeds a few lines.**

**The counterintuitive claim you will learn to defend:** the readline binding Ctrl+X Ctrl+E does the same job, and both are bound to chat:externalEditor [Claude Code docs, Keybindings, 2026].

## 14.2.3.1 — WHAT IT DOES

**Framing.** `Ctrl+G` or `Ctrl+X Ctrl+E` opens your prompt or custom response in your default text editor. Turning on **Show last response in external editor** in `/config` prepends Claude's previous reply as `#`-commented context above your prompt, and Claude Code strips that comment block when you save [Claude Code docs, Interactive mode, 2026].

| Key | Action |
|---|---|
| `Ctrl+G` | Open in editor |
| `Ctrl+X Ctrl+E` | Same, readline style |
| Save and close | Content returns to the prompt |

The failure mode: **Comment-block-edit.** You edit inside the `#` context block and expect your changes to be sent, but the block is stripped on save.

The fix: Write below the comment block only.

Cross-references: plan editing is Module 2.2.

**If you remember one thing:** write below the comments.

---

## 14.2.3.2 — WHEN IT PAYS

**Framing.** Use the editor for multi-paragraph prompts, spec interviews and plan edits; the prompt box is better for one-liners. In agent view the dispatch input follows `chat:externalEditor` single-keystroke bindings, so the `Ctrl+X Ctrl+E` chord does not open the editor there [Claude Code docs, Keybindings, 2026].

| Prompt size | Where to write |
|---|---|
| One line | Prompt box |
| A paragraph or more | Editor via Ctrl+G |
| In agent view | `Ctrl+G` only |

The failure mode: **Chord-in-agent-view.** You press the chord in agent view and nothing opens.

The fix: Use Ctrl+G there.

Cross-references: agent view is Module 6.3.

**If you remember one thing:** single key works everywhere.

---

## 14.2.3.3 — SETTING IT UP

**Framing.** The editor opened is your default text editor; if the wrong one opens, fix the environment your shell exports before launching Claude Code. This guide did not retrieve the editor environment variable name, so confirm it against the docs.

| Check | How |
|---|---|
| Which editor opens | Press Ctrl+G once |
| Wrong editor | Fix your shell environment and relaunch |

The failure mode: **Wrong-editor-surprise.** A blocking GUI editor opens and the session waits on it.

The fix: Choose a terminal editor or one that returns on close.

Cross-references: terminal setup is Module 9.1.

**If you remember one thing:** test the editor once.
