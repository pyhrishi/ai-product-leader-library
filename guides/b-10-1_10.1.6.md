## 10.1.6.1 — FOUR GUARDRAIL GROUPS

**Framing.** The admin-setup page lists the controls and their keys. For this module's four groups: permission lockdown (`allowManagedPermissionRulesOnly`, `permissions.disableBypassPermissionsMode`), sandboxing (`sandbox.enabled`, `sandbox.network.allowedDomains`), hook restrictions (`allowManagedHooksOnly`, `allowedHttpHookUrls`) and plugin marketplace control (`strictKnownMarketplaces`, `blockedMarketplaces`, `disableSideloadFlags`) [Claude Code docs, Set up Claude Code for your organization, 2026].

| Group | Keys | Effect |
|---|---|---|
| Permission lockdown | `allowManagedPermissionRulesOnly`, `permissions.disableBypassPermissionsMode` | Managed rules only; disable bypass mode |
| Sandbox | `sandbox.enabled`, `sandbox.network.allowedDomains` | OS-level filesystem and network isolation |
| Hooks | `allowManagedHooksOnly`, `allowedHttpHookUrls` | Restrict which hooks run |
| Plugins | `strictKnownMarketplaces`, `blockedMarketplaces`, `disableSideloadFlags` | Restrict sources and sideloading |

The failure mode: **Rules-as-boundary.** You deny `Bash(curl *)` and believe network egress is closed, but `/usr/bin/curl` or `sh -c 'curl ...'` still run.

The fix: Add the sandbox network allowlist; use rules for intent, the sandbox for enforcement.

Cross-references: rule syntax is Module 4.2; sandboxing is Module 4.4; hooks are Module 5.4.

**If you remember one thing:** rules express intent; the sandbox enforces.

## 10.1.6.2 — A STARTER DOCUMENT

**Framing.** The server-managed settings page gives a worked example that denies `Bash(curl *)` and reads of `.env` and `secrets`, sets `permissions.disableBypassPermissionsMode` to `disable`, and sets `allowManagedPermissionRulesOnly` to true. Array settings such as `permissions.allow` and `permissions.deny` merge from all sources, so developers can extend managed lists but not remove from them [Claude Code docs, Set up Claude Code for your organization, 2026; Claude Code docs, Configure server-managed settings, 2026].

```json
{
  "permissions": {
    "deny": ["Bash(curl *)", "Read(./.env)", "Read(./.env.*)", "Read(./secrets/**)"],
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true,
  "sandbox": { "enabled": true, "failIfUnavailable": true, "allowUnsandboxedCommands": false }
}
```

The failure mode: **Unsandboxed fallback.** The sandbox is enabled but cannot start on some machines, and Claude runs commands unsandboxed.

The fix: Set `failIfUnavailable` and `allowUnsandboxedCommands: false` in managed settings [Claude Code docs, Sandboxed Bash tool, 2026].

Cross-references: the sandbox page is Module 4.4; managed delivery is Module 10.4.

**If you remember one thing:** set fail-closed sandbox keys, or the sandbox is advisory.

## 10.1.6.3 — TEST ON A REAL MACHINE

**Framing.** Verification is `/status` for the `Setting sources` line and `/permissions` for effective rules. Server-managed settings with shell-command or hook content trigger a security approval dialog, and a user who rejects the settings makes Claude Code exit [Claude Code docs, Configure server-managed settings, 2026]. Plan for the dialog in your rollout messages.

| Check | Command | Expect |
|---|---|---|
| Source | `/status` | `Enterprise managed settings (...)` |
| Rules | `/permissions` | Managed deny rules visible |
| Bypass | `claude --dangerously-skip-permissions` | Refused or disabled |
| Network | `curl` inside sandbox to unlisted host | Blocked |

The failure mode: **Admin-only testing.** You test policy as an administrator account that is exempt or differently configured, and ordinary users see something else.

The fix: Test with a normal user account on a clean machine.

Cross-references: verification detail is Module 10.4.

**If you remember one thing:** test as the user, not as the admin.

## CLOSING REFRAME

This is the craft of guardrails: **intent in rules, enforcement in the sandbox, proof on a real machine.** The administrator who understands this does not ask "what did we deny?" — they ask "what stops it if the rule is bypassed?"
