## 7.2.4.1 — LOCAL VERSUS CLOUD VERSUS LOOP

**Framing.** Claude Code offers three ways to schedule work, and the Desktop page compares them [Claude Code docs, Desktop scheduled tasks, 2026].

| | Cloud | Desktop | `/loop` |
|---|---|---|---|
| Runs on | Cloud | Your machine | Your machine |
| Machine on required | No | Yes | Yes |
| Open session required | No | No | Yes |
| Local files | No (fresh clone) | Yes | Yes |
| Permission prompts | Auto mode by default | Configurable per task | Inherits session |
| Minimum interval | 1 hour | 1 minute when Claude sets it; 1 hour in the forms | 1 minute |

Local tasks need Claude Desktop 1.1.5368 or later. By default they run against whatever state the working directory is in, including uncommitted changes; select **Worktree** in the Edit form for an isolated worktree [Claude Code docs, Desktop scheduled tasks, 2026].

The failure mode: **Wrong-timer.** You schedule a job that must run at 3 a.m. as a Desktop task, and the laptop is asleep so it never fires.

The fix: Use a cloud scheduled task for work that must run with the machine off; use Desktop only when you need local files.

Cross-references: cloud scheduled tasks are Module 7.4; loops and goals are Module 6.7.

**If you remember one thing:** pick the scheduler by whether the machine will be on.

## 7.2.4.2 — CREATING AND RUNNING A TASK

**Framing.** Create one from the Scheduled page in the Code tab, or by describing it in a session, such as 'set up a daily code review that runs every morning at 9am'. A request like 'remind me at 3pm tomorrow' creates a one-time task [Claude Code docs, Desktop scheduled tasks, 2026].

| Option | Meaning |
|---|---|
| Hourly, Daily, Weekdays, Weekly | Presets; Desktop adds a small deterministic delay of a few minutes to stagger traffic |
| Manual | Runs only on **Run now** |
| Custom | Cron in local time; Sunday is `0`; names not accepted; forms reject more often than hourly |

Desktop checks the schedule every minute while the app is open. The task's name becomes a kebab-case folder; the prompt lives in `~/.claude/scheduled-tasks/<task-name>/SKILL.md`, with schedule, folder, model and enabled state kept elsewhere [Claude Code docs, Desktop scheduled tasks, 2026].

The failure mode: **Silent-sleep skip.** The computer sleeps through the scheduled time, the run is skipped, and you assume the task ran.

The fix: Turn on Keep computer awake under Settings, This computer, System, and read the History list, which shows skipped runs and why.

Cross-references: skills and SKILL.md are Module 5.2; time-based work is Module 6.7.

**If you remember one thing:** check History, not your memory.

## 7.2.4.3 — MISSED RUNS, PERMISSIONS AND PROMPT DESIGN

**Framing.** When the app starts or the computer wakes, Desktop looks back seven days; if a task missed runs it starts exactly one catch-up for the most recently missed time. A task scheduled for 9am might run at 11pm [Claude Code docs, Desktop scheduled tasks, 2026].

```text
Prompt with guardrails:
Review only commits since the last run's timestamp in REVIEW_LOG.md.
If the current local time is after 17:00, skip the review and write
"missed run" with the date to REVIEW_LOG.md instead.
```

| Permission fact | Detail |
|---|---|
| Per-task permission mode | Set at creation or edit |
| Allow rules in `~/.claude/settings.json` | Also apply |
| Manual mode and an unapproved tool | The run stalls until you approve in the run's session |
| Fix | Click **Run now** after creating, approve with always allow, review in the Always allowed panel |
| Tools marked `requiresUserInteraction` | Prompt every call; runs stall each time |

The failure mode: **Stale-run assumption.** The prompt says 'review today's commits' and a catch-up run at night reviews the wrong day or finds nothing.

The fix: Anchor the prompt on a recorded timestamp or file, and add an explicit late-start rule.

Cross-references: permissions are Module 4.2; MCP approval is Module 5.5.

**If you remember one thing:** one catch-up, so write for lateness.
