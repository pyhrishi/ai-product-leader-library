## THE THESIS OF THIS TOPIC

**A subagent's skills field preloads full skill content at launch, so the subagent starts already knowing what a normal session would load only on demand.**

**Prove-it, in one sentence:** preload one skill into a subagent and show the subagent applies it without an invocation step.

**The single most important discipline: preload only the skills the subagent always needs; leave the rest discoverable.**

## 5.2.10.1 — PRELOAD VERSUS ON-DEMAND

**Framing.** In a regular session only the description is in context until a skill is used. For a subagent with a `skills` field, the full skill content is injected at startup. The subagent can still discover and invoke unlisted project, user and plugin skills through the Skill tool [Claude Code docs, Extend Claude Code and Skills, 2026].

| Context | What the skill looks like |
|---|---|
| Normal session | Description only until used |
| Subagent with `skills:` listed | Full content from the start |
| Subagent, unlisted skill | Discoverable via the Skill tool |

The failure mode: **Preload-everything.** You list a dozen skills in a subagent's `skills` field, so its fresh context starts with every body loaded and little room for the actual task.

The fix: Preload only skills it needs on every run.

Cross-references: subagent definitions are sub-topic 5.3.3.

**If you remember one thing:** preload for always, discover for sometimes.

---

## 5.2.10.2 — THE TWO COMBINE DIRECTIONS

**Framing.** The docs list two ways skills and subagents combine: a subagent's `skills` field preloads skills; a skill's `context: fork` runs the skill as a task in a subagent, where the subagent does not see your conversation history, so the skill's instructions must stand alone [Claude Code docs, Skills, 2026].

| Direction | Instructions come from | Task comes from |
|---|---|---|
| Subagent + `skills:` | Subagent body + preloaded skills | Delegation message |
| Skill + `context: fork` | The skill body (becomes the task) | The skill body |

A forked skill with only guidelines and no task returns without meaningful output [Claude Code docs, Skills, 2026].

The failure mode: **History-assuming skill.** A forked skill refers to 'the file we just discussed', but the subagent never saw that conversation.

The fix: Write forked skills so the instructions stand alone.

Cross-references: forks of the whole conversation are sub-topic 5.3.7.

**If you remember one thing:** forked agents start without your history.

## 5.2.10.3 — INVOCATION CONTROL AND PRELOAD

**Framing.** The docs state that `disable-model-invocation` also prevents a skill from being preloaded into subagents. A side-effecting skill therefore cannot be handed to a subagent as ambient knowledge, which is usually the point [Claude Code docs, Skills, 2026].

```yaml
# .claude/agents/reviewer.md
---
name: reviewer
description: Review changes against our API conventions
skills: api-conventions
---
```
[Frontmatter field `skills` as named in the docs; example constructed for illustration]

The failure mode: **Disabled-and-expected.** You mark a skill `disable-model-invocation: true`, list it under a subagent's `skills`, and expect it preloaded.

The fix: Remove the setting for knowledge skills, or invoke the action skill from the main session.

Cross-references: frontmatter is sub-topic 5.2.3.

**If you remember one thing:** preload works for knowledge skills, not manual-only ones.
