## 14.1.13.1 — WHY A COMMAND IS MISSING

**Framing.** Claude Code leaves unavailable commands out of the menu; most return Unknown command on submit, a few answer with their own availability message (such as `/schedule` on a Console API key), and some answer with a policy message [Claude Code docs, Commands, 2026]. Examples: `/desktop` only shows on macOS and x64 Windows with a subscription, and `/upgrade` does not show on Enterprise plans.

| Cause | Example |
|---|---|
| Platform | `/desktop` on Linux |
| Plan | `/upgrade` on Enterprise |
| Version | `/list-agents` before v2.1.224 |
| Policy | Admin disabled |
| Hidden by design | `/heapdump` |

The failure mode: **Typo-submit.** You mistype a command, press Enter and send the text as a message instead of running anything.

The fix: After a typo pick the suggestion with Tab or the arrow keys.

Cross-references: troubleshooting is Part 12.

**If you remember one thing:** Enter after a typo submits text.

## 14.1.13.2 — MENU MATCHING

**Framing.** The menu highlights its top suggestion only when your letters match a command name or alias, from the start or from a word within it, ignoring `:`, `_` and `-`; `/adddir` highlights `/add-dir` and `/new` highlights `/clear` through its alias. These highlighting rules need v2.1.236 or later [Claude Code docs, Commands, 2026].

| Typed | Highlights |
|---|---|
| `/adddir` | `/add-dir` |
| `/new` | `/clear` (alias) |
| `/heapd` | Nothing; hidden commands need the full name |

The failure mode: **Partial-hidden.** You type part of a hidden command's name and conclude it does not exist.

The fix: Type the full name; partial names never reveal hidden commands.

Cross-references: command reference is Module 14.1.

**If you remember one thing:** hidden commands need full names.

## 14.1.13.3 — MCP PROMPTS AND SKILLS AS COMMANDS

**Framing.** MCP servers can expose prompts that appear as commands [Claude Code docs, Commands, 2026]. A command is recognised only at the start of the message, and at the terminal prompt up to six skills can be chained in one message [Claude Code docs, Commands, 2026].

```text
/skill-a /skill-b do XYZ     # loads both; text after goes to each as arguments
```

| Source | Appears as |
|---|---|
| Built-in | `/name` |
| Skill | `/skill-name` |
| MCP prompt | A command from the server |

The failure mode: **Mid-message-command.** You type text first and a command after, and the command is treated as plain text.

The fix: Put the command first on the line.

Cross-references: MCP is Module 5.5; skills are Module 5.2.

**If you remember one thing:** a command must lead the message.
