## 14.2.4.1 — INLINE SEARCH

**Framing.** In the classic renderer, `Ctrl+R` starts reverse search: type a query, press `Ctrl+R` again to cycle older matches, `Tab` or `Esc` to accept and keep editing, `Enter` to accept and run, `Ctrl+C` to cancel and restore input. It scans full history newest first with duplicates collapsed [Claude Code docs, Interactive mode, 2026].

| Key | Action |
|---|---|
| Ctrl+R | Start, then next older match |
| Tab / Esc | Accept, keep editing |
| Enter | Accept and execute |
| Ctrl+C | Cancel, restore input |

The failure mode: **Enter-executes.** You press Enter to accept a match and it runs immediately, not edit first.

The fix: Use Tab or Esc to bring it into the prompt for editing.

Cross-references: prompt reuse is Module 2.2.

**If you remember one thing:** Tab edits, Enter runs.

---

## 14.2.4.2 — FULLSCREEN DIALOG

**Framing.** In fullscreen rendering `Ctrl+R` opens a dialog: type to filter, Up and Down to move, `Ctrl+S` to cycle scope through session, project and all projects, `Enter` or `Tab` to place the match in the prompt, `Esc` to cancel [Claude Code docs, Interactive mode, 2026].

| | Classic | Fullscreen |
|---|---|---|
| Scope | All projects, fixed | session, project, all (Ctrl+S) |
| Enter | Executes | Places in prompt |

The failure mode: **Scope-assumption.** You assume a fullscreen search covers all projects and it is still on the session scope.

The fix: Press Ctrl+S and read the scope label.

Cross-references: fullscreen mode is Module 9.1.

**If you remember one thing:** check the scope label.

---

## 14.2.4.3 — HISTORY RULES

**Framing.** Input history is stored per working directory; `/clear` starts a new session with its prompts listed first; a duplicate prompt twice in a row records one entry; history expansion with `!` is off by default [Claude Code docs, Interactive mode, 2026]. Vim NORMAL mode `/` opens history search too [Claude Code docs, Keybindings, 2026].

| Rule | Detail |
|---|---|
| Storage | Per working directory |
| After `/clear` | New session first, earlier after |
| Duplicates | Collapsed |

The failure mode: **Wrong-directory-history.** You look for a prompt in a directory that never held it and conclude it was lost.

The fix: Search from the original directory, or use all-projects scope.

Cross-references: sessions are Module 2.4.

**If you remember one thing:** history follows the directory.

## CLOSING REFRAME

This is the craft of history search: **scope and accept key decide the result.** The engineer who understands this does not ask "where did that prompt go?" — they ask "which scope am I in, and does Enter run or edit?"
