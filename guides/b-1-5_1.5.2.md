## THE THESIS OF THIS TOPIC

**Different questions have different sources of truth, and the product itself outranks any copy of its docs.**

**Prove-it, in one sentence:** answer five questions each from the right source and say why the others were wrong.

**The single most important discipline: link to official pages instead of copying text, and date what you copy.**

**The counterintuitive claim you will learn to defend:** the most convenient source is the most likely to be stale; a mirror or blog can be right yesterday and wrong today.

**THE TIME BUDGET.** Reading time: ~12 minutes. Prove-it time: ~1.5 hours (90 minutes, 7.5 times the reading time).

## 1.5.2.1 — THE SOURCE MAP

**Framing.** Each question type has a primary source.

| You need | Go to | Why |
|---|---|---|
| A Claude Code term | Claude Code Glossary | Entries link to deep pages |
| A model-level concept | Platform glossary | Tokens, temperature, RAG |
| Desktop-app terms | Claude Help Center | DXT, MCPB |
| The page list | `code.claude.com/docs/llms.txt` | Docs index |
| Live behaviour | `/help`, `/context`, `/memory`, `claude doctor` | Your version, your session |
| What changed | `/release-notes` | Renames arrive by release |

The failure mode: **Wrong-glossary lookup.** You look up a model concept in the Claude Code glossary or a Desktop term in the platform glossary and find nothing.

The fix: Use the platform glossary for model concepts and the Help Center for Desktop terms.

Cross-references: in-product help is Module 1.3.6.

**If you remember one thing:** match the question to the glossary.

## 1.5.2.2 — SOURCE-OF-TRUTH RANKING

**Framing.** When sources disagree, rank them: your running product, then official docs, then official blog or help, then secondary sources, then mirrors.

| Rank | Source | Use |
|---|---|---|
| 1 | Your running product | Behaviour on your version |
| 2 | Official docs | Definitions, flags, limits |
| 3 | Help Center | Plan and account questions |
| 4 | Secondary articles | Context; verify before use |
| 5 | Mirrors and forums | Leads only |

The failure mode: **Source-of-truth drift.** A copied table in your wiki goes stale and nobody knows which line is current.

The fix: Date entries, review after each release with `/release-notes`, and link to official pages instead of copying text.

Cross-references: release notes are Module 1.3.5.

**If you remember one thing:** the product beats the page.

## 1.5.2.3 — READING THE DOCS EFFICIENTLY

**Framing.** The docs index at `code.claude.com/docs/llms.txt` lists pages for discovery, and each Glossary entry links to its deep page.

| Task | Method |
|---|---|
| Find a page | Read `llms.txt` and search it |
| Check a flag | Open the CLI reference page |
| Confirm a version note | Read the page's minimum-version line |

The failure mode: **Excerpt-trust.** You rely on a search excerpt of a long page and miss the clause that changes the answer.

The fix: Open the full page for anything you will standardise on.

Cross-references: troubleshooting is Part 12.

**If you remember one thing:** excerpts find; pages confirm.

---

## 1.5.2.4 — A TEAM LINK SHEET

**Framing.** A short link sheet gives everyone the same sources.

| Column | Content |
|---|---|
| Question type | Terms, limits, install, billing |
| Source | Official page URL |
| Last reviewed | Date |
| Version checked | `claude --version` output |

The failure mode: **Link-sheet rot.** The link sheet is created once and never reviewed, so it points at moved pages.

The fix: Add a review date and re-check after each release.

Cross-references: team practice is in Part 11.

**If you remember one thing:** date it, review it.
