## THE THESIS OF THIS TOPIC

**The Agent SDK is Claude Code's agent loop, tools and context management packaged as a Python and TypeScript library, so you embed an agent in a process you operate instead of writing the loop yourself.**

**Prove-it, in one sentence:** given four build scenarios, name the right tool (Agent SDK, CLI, Client SDK or Managed Agents) and say in one sentence what you give up by choosing it.

**The single most important discipline: decide who runs the loop and where it runs before you write any code.**

**The counterintuitive claim you will learn to defend:** the SDK is not a thin API wrapper: it runs the Claude Code binary, so your Python or TypeScript process is a controller around a separate agent process [Agent SDK docs, Overview, 2026].

## 8.1.1.1 — THE FOUR OPTIONS DIFFER BY WHO RUNS THE LOOP

**Framing.** The overview page separates the Agent SDK, the Claude Code CLI, the Client SDK and Managed Agents by who runs the agent, what comes built in and how you reach it [Agent SDK docs, Overview, 2026].

| You want to | Use | What you get |
|---|---|---|
| Embed Claude Code's agent in your own Python or TypeScript app, in a process you operate | Agent SDK | A library that runs the Claude Code binary: built-in tools, permissions, sessions, hooks |
| Work interactively or run one-off tasks from a terminal | Claude Code CLI | The terminal interface |
| Call the Claude API directly | Client SDK | Direct API access; you write the tool loop, or use the beta tool runner |
| Have Anthropic host the agent | Managed Agents | A hosted harness with sessions in an Anthropic-managed cloud sandbox or a self-hosted sandbox |

[Agent SDK docs, Overview, 2026]. The loop in the SDK is the same execution loop that powers Claude Code: Claude evaluates the prompt, calls tools, receives results and repeats until the task is complete [Agent SDK docs, How the agent loop works, 2026].

The failure mode: **Four-way blur.** You say 'we use the SDK' when you mean the Client SDK, the CLI or Managed Agents, and the team plans cost, hosting and tool work for the wrong product.

The fix: Write the row from the table above that matches your build, with the owner of the loop named, before the design review.

Cross-references: the loop itself is Module 8.2; hosting is Module 8.7; the Claude Code loop it descends from is Module 1.2.

**If you remember one thing:** the SDK means you run the loop's host process; the Client SDK means you write the loop.

## 8.1.1.2 — WHAT IS INSIDE THE BOX

**Framing.** The SDK lists eight capabilities inherited from Claude Code: built-in tools, hooks, subagents, MCP, permissions, sessions, skills/commands/memory and plugins [Agent SDK docs, Overview, 2026]. Both language SDKs bundle a native Claude Code binary, so most installs need no separate Claude Code install [Agent SDK docs, How the agent loop works, 2026].

```
your process (Python / TypeScript)
   query(prompt, options) ──►  Claude Code binary (bundled)
        ▲                          │ loop: evaluate → tools → results → repeat
        └── async stream of messages ◄┘
```

| Capability | You configure it with | Module |
|---|---|---|
| Built-in tools (Read, Edit, Bash, Glob, Grep, WebSearch, WebFetch) | allowed and disallowed tool lists | 8.3 |
| Hooks | callbacks at lifecycle points | 8.6 |
| Subagents | agent definitions | 8.3 |
| Sessions | resume, continue, fork | 8.5 |
| Skills, commands, memory | setting sources | 8.2 |

Tool names are listed in [Agent SDK docs, How the agent loop works, 2026].

The failure mode: **Library illusion.** You treat query() as an in-process function call, then are surprised by a subprocess to deploy, a binary to ship and a working directory to manage.

The fix: Draw the process boundary on your architecture diagram: your code, the bundled binary, the model API.

Cross-references: subprocess architecture is Module 8.7; options are Module 8.2.

**If you remember one thing:** the SDK is a controller for a separate agent process.

## 8.1.1.3 — WHAT IT IS NOT: THE OTHER APPROACHES AND THEIR BOUNDARIES

**Framing.** Three neighbours are easy to confuse with the SDK: print mode, the Client SDK, and a hosted agent. Print mode is the same engine reached through the CLI: the headless page says it is available 'as a CLI for scripts and CI/CD, or as Python and TypeScript packages' [Claude Code docs, Run Claude Code programmatically, 2026]. For other languages, run the CLI as a subprocess with -p and --output-format json [Agent SDK docs, Overview, 2026].

| Boundary | Statement | Source |
|---|---|---|
| Not the raw API | With the Client SDK you write the tool loop yourself | Overview |
| Not a login product | Anthropic does not allow third parties to offer claude.ai login or rate limits for their products unless previously approved; use API keys | Overview, Quickstart |
| Not Claude Code branded | Do not name your product 'Claude Code' or 'Claude Code Agent'; 'Claude Agent' and '{YourAgentName} Powered by Claude' are allowed | Overview |
| Not exempt from terms | Governed by Anthropic's Commercial Terms of Service, including for your end users | Overview |
| Not a default coding prompt | The SDK stopped using Claude Code's system prompt by default in v0.1.0; opt in with the claude_code preset | Migration guide |

All rows: [Agent SDK docs, Overview and Migration guide, 2026].

The failure mode: **Borrowed login.** You plan to let customers sign in with their claude.ai subscription inside your SDK product, and the plan collides with the stated policy.

The fix: Plan for API-key or cloud-provider authentication from the first sketch, and treat anything else as needing prior approval from Anthropic.

Cross-references: authentication setup is Module 8.1.2; system prompts are Module 8.2.

**If you remember one thing:** the boundaries are policy and process, not only features.

## 8.1.1.4 — READING THE STREAM: WHAT YOUR CODE RECEIVES

**Framing.** The SDK returns an async iterator of messages. Five core types cover the loop: SystemMessage, AssistantMessage, UserMessage, StreamEvent (only with partial messages on) and ResultMessage [Agent SDK docs, How the agent loop works, 2026].

```python
async for message in query(prompt="Summarize this project"):
    if isinstance(message, ResultMessage):
        if message.subtype == "success":
            print(message.result)
        else:
            print("Stopped:", message.subtype)
```
[Agent SDK docs, How the agent loop works, 2026]

| Result subtype | Meaning |
|---|---|
| success | Finished normally; `result` available |
| error_max_turns | Hit the turn limit |
| error_max_budget_usd | Hit the budget limit |
| error_during_execution | API failure or cancelled request |
| error_max_structured_output_retries | No valid structured output within the retry limit |

[Agent SDK docs, How the agent loop works, 2026]. The result field exists only on success.

The failure mode: **Result-blind loop.** You print every message and never branch on the ResultMessage subtype, so a turn-limit stop looks like a success to downstream code.

The fix: Branch on subtype before reading result, and treat each error subtype as its own path.

Cross-references: turns, budgets and limits are Module 8.2 and Module 8.6; structured output is Module 8.4.

**If you remember one thing:** the end of the stream is a ResultMessage, and its subtype is the truth.
