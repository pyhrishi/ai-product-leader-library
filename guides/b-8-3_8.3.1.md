# MODULE 8.3.1 — BUILT-IN TOOLS AND PERMISSION REQUIREMENTS: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**The SDK ships the same built-in tools as Claude Code in six families, and what the agent can actually do is the product of two separate layers: which tools are available and which calls are approved.**

**Prove-it, in one sentence:** for a given agent spec, write the tools, allowed and disallowed lists that give exactly the required capability and show which layer each entry acts on.

**The single most important discipline: separate availability from permission every time you write a tool list.**

**The counterintuitive claim you will learn to defend:** allowedTools does not restrict anything: it only pre-approves, so a read-only agent is built with the tools option or a bare disallowed name, not with an allow list [Agent SDK docs, Give Claude custom tools, 2026].

## 8.3.1.1 — THE SIX FAMILIES

**Framing.** The SDK includes the tools that power Claude Code, grouped by what they do. Tools are how an agent acts: without them Claude can only respond with text [Agent SDK docs, How the agent loop works, 2026].

| Category | Tools | What they do |
|---|---|---|
| File operations | Read, Edit, Write | Read, modify and create files |
| Search | Glob, Grep | Find files by pattern; search content with regex |
| Execution | Bash | Shell commands, scripts, git |
| Web | WebSearch, WebFetch | Search the web; fetch and parse pages |
| Discovery | ToolSearch | Find and load tools on demand |
| Orchestration | Agent, Skill, AskUserQuestion, TaskCreate, TaskUpdate | Spawn subagents, invoke skills, ask the user, track tasks |

[Agent SDK docs, How the agent loop works, 2026]. The task-tracking tools are only provided automatically on some models; elsewhere you opt in. In `tool_use` blocks the subagent tool is named Agent, but it appears as Task in the system:init tools list [Agent SDK docs, Subagents in the SDK, 2026].

The failure mode: **Name drift.** Your detection code looks for a tool named Task or Agent only, and misses subagent calls on a version that uses the other name.

The fix: Match both names when detecting subagent invocation.

Cross-references: subagents are Module 8.3.5; todo tools are Module 8.4.5; tool search is Module 8.3.4.

**If you remember one thing:** six families, and Agent is also called Task in the init list.

## 8.3.1.2 — TWO LAYERS: AVAILABILITY AND PERMISSION

**Framing.** The tools option and allowed or disallowed lists act on two layers. Availability decides whether a tool appears in Claude's context; permission decides whether a call is approved when Claude attempts it [Agent SDK docs, Give Claude custom tools, 2026].

| Option | Layer | Effect |
|---|---|---|
| `tools: ["Read","Grep"]` | Availability | Only these built-ins are in context; MCP tools unaffected |
| `tools: []` | Availability | All built-ins removed; only your MCP tools remain |
| allowed tools | Permission | Listed tools run without a prompt; others stay available |
| disallowed, bare name `"Bash"` | Both | Removes the tool from context |
| disallowed, scoped `"Bash(rm *)"` | Permission | Tool stays in context; matching calls denied |

[Agent SDK docs, Give Claude custom tools, 2026]. A scoped deny leaves the tool visible, so Claude may waste a turn trying it.

The failure mode: **Visible-but-denied.** You block rm with a scoped deny, Claude keeps trying Bash variants, and turns are wasted on denials.

The fix: Remove the tool with a bare name or the tools list when it should never be attempted.

Cross-references: rule evaluation order is Module 8.6.1.

**If you remember one thing:** availability hides a tool; permission only gates a call.

## 8.3.1.3 — PERMISSION MODES AND WHAT THEY AUTO-APPROVE

**Framing.** permission_mode sets the oversight level. In default mode, tools not covered by allow rules go to your canUseTool callback and no callback means deny [Agent SDK docs, How the agent loop works, 2026].

| Mode | Behaviour |
|---|---|
| default | Uncovered tools go to canUseTool; none means deny |
| acceptEdits | Auto-approves file edits and common filesystem commands (mkdir, touch, mv, cp); other Bash follows default rules |
| plan | Explores and plans; edits never auto-approved |
| dontAsk | Never prompts; only pre-approved tools run, everything else denied |
| auto | A model classifier approves or denies prompts |
| bypassPermissions | Runs allowed tools without asking, except explicit ask rules; TypeScript also needs allowDangerouslySkipPermissions: true; not as root on Unix |

[Agent SDK docs, How the agent loop works, 2026]. acceptEdits does not auto-approve MCP tools; use allowedTools wildcards for those [Agent SDK docs, Connect to external tools with MCP, 2026].

The failure mode: **Mode-as-allowlist.** You use acceptEdits expecting MCP and Bash calls to be approved too, and the unattended run stalls or denies them.

The fix: List MCP and Bash needs in allowedTools, or choose dontAsk for a fixed surface.

Cross-references: modes in depth are Module 8.6.1; secure deployment is Module 8.7.4.

**If you remember one thing:** a mode sets a baseline; lists add exceptions.

## 8.3.1.4 — DESIGNING A LEAST-PRIVILEGE TOOL SET

**Framing.** Start from the task's verbs. A reviewer reads, a tester runs commands, an editor writes. The docs give combinations for subagents that apply equally to a main agent [Agent SDK docs, Subagents in the SDK, 2026].

| Use case | Tools |
|---|---|
| Read-only analysis | Read, Grep, Glob |
| Test execution | Bash, Read, Grep |
| Code modification | Read, Edit, Write, Grep, Glob |
| Full access | All tools (omit the tools field) |

[Agent SDK docs, Subagents in the SDK, 2026]. A tool left out is not in the session at all: Claude works without it, with no prompt or error. Verify the result from the init message's tools array.

The failure mode: **Unverified surface.** You assume the tool set from your options and never read the init message, so a missing or extra tool goes unnoticed.

The fix: Assert on the init tools array in a test.

Cross-references: agent evals are Module 8.6.5; subagent scoping is Module 8.3.5.

**If you remember one thing:** the init message is the proof of what the agent can do.

| Agent | tools | allowed | disallowed | Init tools |

| Element | What is wrong |

| Never checked init | **Unverified surface** |

**The verdict.** The artifact passes only if each entry is labelled with its layer and the init output matches the matrix.
