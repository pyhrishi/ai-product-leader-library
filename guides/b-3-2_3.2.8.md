## 3.2.8.1 — SYNTAX AND RULES

**Framing.** Imports use the at-path syntax inside CLAUDE.md, for example `See @README for project overview and @package.json for available npm commands.` [Claude Code docs, Memory, 2026].

```text
See @README for project overview and @package.json for available npm commands.

# Additional Instructions
- git workflow @docs/git-instructions.md
```

| Rule | Value |
|---|---|
| Relative paths resolve from | The importing file, not the working directory |
| Absolute paths | Work |
| Nesting depth | Up to four hops |
| When imports load | At launch |
| External imports | First encounter shows an approval dialog; if declined, stay disabled |

The failure mode: **Cwd-path error.** You write an import path relative to the working directory, and it fails to resolve from a nested file.

The fix: Write paths relative to the file that contains the import, or use an absolute path.

Cross-references: file locations are sub-topic 3.2.2 of Module 3.2.

**If you remember one thing:** relative to the importer.

## 3.2.8.2 — AGENTS.MD

**Framing.** To share instructions with other agents, import AGENTS.md from CLAUDE.md or symlink it; `/init` also incorporates existing `AGENTS.md`, `.cursorrules` and `.windsurfrules`; on Windows use the import because symlinks need Administrator privileges or Developer Mode [Claude Code docs, Memory, 2026]. The How Claude Code works page says Claude can read an AGENTS.md in place of a CLAUDE.md, and the context-window page says AGENTS.md files can load in place of CLAUDE.md; the Memory page is more explicit that Claude Code reads CLAUDE.md, not AGENTS.md.

```markdown
@AGENTS.md

## Claude Code

Use plan mode for changes under `src/billing/`.
```

```bash
ln -s AGENTS.md CLAUDE.md   # Windows: use the import instead
```

The failure mode: **AGENTS-assumption.** You assume Claude reads AGENTS.md directly and put project rules only there, then find they did not load.

The fix: Add `@AGENTS.md` to CLAUDE.md or symlink it, and confirm the load with `/memory`.

Cross-references: multi-tool setups are Module 7.5.

**If you remember one thing:** bridge it explicitly.

## 3.2.8.3 — IMPORTS AND COST, AND WORKTREES

**Framing.** Imports load at launch, so they organise content but do not reduce context [Claude Code docs, Memory, 2026]. For worktrees, import a home-directory file (`@~/.claude/my-project-instructions.md`) instead of a gitignored `CLAUDE.local.md`, which exists only in the worktree where it was created.

| Situation | Use |
|---|---|
| Share a doc across files | Import |
| Cut always-on context | Skill or path-scoped rule, not an import |
| Personal notes across worktrees | Import a file in `~/.claude/` |

The failure mode: **Local-file orphan.** You keep personal rules in a gitignored `CLAUDE.local.md`, and a new worktree starts without them.

The fix: Move the personal rules to a home-directory file and import it.

Cross-references: worktrees are Module 6.4.

**If you remember one thing:** worktrees need home-level files.
