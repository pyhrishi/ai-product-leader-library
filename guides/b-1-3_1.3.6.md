## 1.3.6.1 — COMMANDS THAT ANSWER QUESTIONS

**Framing.** Six commands cover most self-service: `/help`, `/powerup`, `claude doctor`, `/context`, `/memory` and `/release-notes`.

| Command | Answers |
|---|---|
| `/help` | What commands and shortcuts exist |
| `/powerup` | Guided interactive lessons |
| `claude doctor` or `/doctor` | Is my installation and configuration healthy |
| `/context` | What is in my context right now |
| `/memory` | Which CLAUDE.md and memory files loaded |
| `/release-notes` | What changed in this version |

The failure mode: **Docs-first debugging.** You spend half an hour searching the web for a symptom that `claude doctor` would diagnose in seconds.

The fix: Run `claude doctor` first, then search with the exact error string.

Cross-references: context inspection is Module 3.1; memory is Module 3.2.

**If you remember one thing:** ask the product before the internet.

## 1.3.6.2 — /POWERUP: WHAT IS VERIFIED AND WHAT IS NOT

**Framing.** `/powerup` opens short interactive lessons with animated demos inside the terminal. Community sources date it to v2.1.90, released 1 April 2026 [secondary: dev.to and community pages, 2026]. Sources disagree on the lesson count: some say 10 lessons, others 18, and one notes there is no dedicated Anthropic docs page or announcement [secondary, 2026].

| Claim | Status |
|---|---|
| Interactive lessons with animated demos | Consistent across sources |
| Introduced in v2.1.90 | Consistent across sources |
| 10 lessons | Reported by some sources |
| 18 lessons | Reported by others |
| Official docs page | Not found in this research |

Treat the lesson list as version-dependent: open `/powerup` and read it.

The failure mode: **Lesson-count assumption.** You plan an onboarding around a specific number or list of lessons quoted online, and your version shows something different.

The fix: Open `/powerup` in your version and build the plan from what it shows.

Cross-references: the Anthropic Academy courses are linked from the overview; feature modules are Part 5.

**If you remember one thing:** the menu in your terminal is the source of truth.

## 1.3.6.3 — INSPECTION COMMANDS IN PRACTICE

**Framing.** `/context` shows live usage by category with optimisation suggestions, and `/memory` shows which CLAUDE.md and auto-memory files loaded at startup [Claude Code docs, Context window, 2026].

| Symptom | First command |
|---|---|
| Answers getting worse in a long session | `/context` |
| Claude ignores a project rule | `/memory` |
| Command not found or odd behaviour after install | `claude doctor` |
| Something changed after an update | `/release-notes` |

The failure mode: **Blind-session.** You keep working in a degraded session without looking at context or memory.

The fix: Run `/context` at task boundaries and `/memory` whenever a rule seems ignored.

Cross-references: the context window is Module 3.1.

**If you remember one thing:** look before you theorise.

## 1.3.6.4 — BUILDING AN ONBOARDING PATH

**Framing.** For a team, a short path using in-product commands gives every member the same baseline.

| Day | Activity |
|---|---|
| 1 | Install, `claude doctor`, first session on a throwaway branch |
| 2 | `/powerup` lessons on context, plan mode and CLAUDE.md |
| 3 | `/init`, `/memory`, a scoped real task |
| 4 | `/context` habit, `/usage`, cost habits |

The failure mode: **Onboarding-by-link.** New teammates get a list of links and no structured practice, so habits diverge.

The fix: Give a 4-day path with verifiable outputs from the product itself.

Cross-references: cost habits are Module 1.4; first session is Module 1.3.3.

**If you remember one thing:** structure beats a link list.
