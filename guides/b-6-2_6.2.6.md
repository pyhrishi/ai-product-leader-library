## 6.2.6.1 — THE FOUR CHECKS

**Framing.** While a session is isolated in a worktree, Claude Code blocks tool calls under four checks, whether the session started with `--worktree`, entered a worktree with EnterWorktree, or resumed one. Subagents spawned from the isolated session carry the same checks [Claude Code docs, Worktrees, 2026].

| Check | Blocks |
|---|---|
| File edits | Edit, Write or NotebookEdit targeting a path in the main checkout |
| Command working directory | A Bash, PowerShell or Monitor command whose working directory resolves to the main checkout, or whose working directory it cannot verify stays outside it |
| Git redirects | `git -C`, `--git-dir`, `GIT_DIR`, `GIT_WORK_TREE`, or a `cd` into the main checkout before git |
| Command shape | A command whose git cannot be verified from its text, such as a runtime-computed command name, unparseable syntax, or expansions like `${!name}` |

For PowerShell commands only the working-directory check applies. You cannot turn the command-shape check off [Claude Code docs, Worktrees, 2026].

The failure mode: **Absolute-path escape.** Claude writes to `/repo/src/a.ts` (the main checkout) from inside the worktree because a pasted stack trace used the absolute path, and the edit is blocked.

The fix: Point Claude at the worktree-relative path and say the worktree is the working copy.

Cross-references: sandboxing is Module 4.4; tools are Module 1.2.

**If you remember one thing:** four blocks, one purpose: the main checkout stays untouched.

## 6.2.6.2 — READING A REFUSAL

**Framing.** Claude sees each refusal as a tool error that names the worktree and says how to proceed. For the command-shape check Claude Code tells Claude how to rewrite the command, such as splitting it into plain, separate commands [Claude Code docs, Worktrees, 2026].

| Refused | Rewrite |
|---|---|
| `cmd=git; $cmd status` | `git status` |
| `git -C /repo/main log` | `git log` from the worktree directory |
| `cd /repo/main && git add .` | Stay in the worktree; `git add .` |
| `${!name} status` style expansion | Spell out the command |

*The rewrites above are illustrations of the stated rule, not quoted refusals.*

The failure mode: **Bypass hunting.** You loosen permissions or try to disable the check instead of rewriting a refused command, and the check does not go away.

The fix: Rewrite the command in plain separate steps; the docs say the command-shape check cannot be turned off.

Cross-references: error text for blocked commands lives under the errors reference (Module 12.6).

**If you remember one thing:** the refusal tells you the rewrite.

## 6.2.6.3 — HOOK ENVIRONMENT

**Framing.** Claude Code keeps `${CLAUDE_PROJECT_DIR}` where the session started and passes the worktree path to hooks through the `cwd` field of the hook's input JSON, which moves again when Claude runs `cd` [Claude Code docs, Worktrees, 2026]. This matters for hooks that format, lint or scan files.

```bash
#!/usr/bin/env bash
# runs from a hook; the script lives at the project root, the work is in cwd
input=$(cat)
work=$(echo "$input" | jq -r '.cwd')
"${CLAUDE_PROJECT_DIR}/.claude/hooks/check-style.sh" "$work"
```

*The pattern is derived from the two documented facts; the script body is illustrative.*

The failure mode: **Wrong-root hook.** A style hook uses `${CLAUDE_PROJECT_DIR}` as the directory to scan, so it checks the main checkout while edits happen in the worktree and never fails.

The fix: Read `cwd` from the hook input for the files to act on; use the project directory only to find the script.

Cross-references: hook input fields are in the hooks reference (Module 5.4).

**If you remember one thing:** scripts at the root, targets at cwd.

## 6.2.6.4 — RESUME AND REFUSAL MESSAGES

**Framing.** When Claude Code cannot return a resumed session to its worktree it says so. `Your worktree <path> no longer exists` continues without isolation; `Could not verify your worktree <path> this time` keeps the binding and continues; `Did not re-enter` clears it; `Could not re-enter` keeps it. In `-p` mode and Agent SDK resumes, Claude Code stops with an error for every refusal except a gone worktree [Claude Code docs, Worktrees, 2026].

| Message starts with | Binding | Next step |
|---|---|---|
| `Your worktree <path> no longer exists` | Cleared | None |
| `Could not verify your worktree <path> this time` | Kept | Resume again |
| `Did not re-enter your worktree <path>` | Cleared | Match the refusal text |
| `Could not re-enter your worktree <path>` | Kept | Launch from the main checkout |

In stream-json the `startup_failure_reason` is `worktree_unverified` or `worktree_resume_refused` (v2.1.274 and later) [Claude Code docs, Worktrees, 2026].

The failure mode: **Resume-from-inside.** You resume a worktree session from inside the worktree directory and get `Could not re-enter`, then recreate a healthy worktree.

The fix: Launch from the main checkout, where Claude Code can vouch for the worktree; do not delete it.

Cross-references: session resume is Module 2.4; the SDK is Module 8.5.

**If you remember one thing:** launch from the main checkout to resume.
