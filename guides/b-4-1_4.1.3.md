## THE THESIS OF THIS TOPIC

**You can change settings through /config, by editing JSON, per session on the command line, or by describing the change to /update-config; each has a different durability and a different failure.**

**Prove-it, in one sentence:** change one setting four ways and state, for each, where it was saved and when it takes effect.

**The single most important discipline: pick the editing path by how long the change should last, not by what is closest to hand.**

## 4.1.3.1 — INTERACTIVE PATHS: /CONFIG AND /UPDATE-CONFIG

**Framing.** `/config` opens the Settings interface; passing `key=value` sets a value directly, such as `/config verbose=true` or `/config thinking=false`. `/update-config [request]` is a bundled skill: you describe the change and Claude edits the matching settings.json file; for options such as theme and model, use `/config` [Claude Code docs, Commands, 2026].

| Option saved from /config | Lands in |
|---|---|
| Most options (theme, editor mode) | `~/.claude/settings.json` |
| A few, such as Show tips | `.claude/settings.local.json` |
| Global config options | `~/.claude.json` |

`/config` is part of the terminal interface; the VS Code chat panel and desktop app do not open it. In a cloud session in the browser it opens your claude.ai settings page instead of changing a value [Claude Code docs, Settings files and precedence, 2026].

The failure mode: **Wrong-surface /config.** You run /config in VS Code or a cloud session expecting it to change a value, and nothing is saved.

The fix: Edit the settings file directly, or in cloud set an environment variable on the environment.

Cross-references: scopes are Module 4.1.1.

**If you remember one thing:** /config saves for you; /update-config edits for you.

## 4.1.3.2 — DIRECT EDITS AND WHEN THEY TAKE EFFECT

**Framing.** Open the file for the scope you want and add the key. Add `$schema` for editor validation. Claude Code watches the files and reloads most edits without restart, including `permissions`, `hooks` and credential helpers such as `apiKeyHelper` [Claude Code docs, Settings files and precedence, 2026].

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": { "allow": ["Bash(npm run lint)"], "deny": ["Read(./.env)"] }
}
```

| Fails as | Cause |
|---|---|
| Settings Error dialog | Invalid JSON or schema-rejected value in user/project/local file |
| Settings Warning | Single bad entry; Claude Code skips it and keeps the rest |
| Configuration error | `~/.claude.json` unparseable; copied to `~/.claude/backups/.claude.json.corrupted.<timestamp>` |

The ConfigChange hook runs for each file change but not for MDM or console-delivered managed settings.

The failure mode: **Comment in JSON.** You add a `//` comment or a trailing comma to settings.json and the whole file fails to load.

The fix: Remove it, then run /status and claude doctor to confirm what loaded and what was dropped.

Cross-references: diagnostics are sub-topic 4.1.5; hooks are Module 5.4.

**If you remember one thing:** strict JSON; reload is automatic for most keys.

## 4.1.3.3 — ONE-SESSION CHANGES AND THE LASTING ONES

**Framing.** To try a value without saving it: `--settings` with inline JSON or a file, a per-key flag such as `--model` or `--effort`, or the paired environment variable [Claude Code docs, Settings files and precedence, 2026].

| Method | Persists? | Notes |
|---|---|---|
| `claude --settings '{"model":"claude-opus-5-5"}'` | No | Above user/project/local, below managed; cannot set Managed or Global config keys |
| `/model` Enter | Yes | Saved to `model` in user settings |
| `/model` then `s` | No | Session only |
| `/effort` Enter vs `s` | Yes vs no | `s` needs v2.1.257+ |
| `/config key=value` | Yes | Written to the matching file |

If you cannot write `~/.claude/settings.json` (generated or read-only), a saved choice applies only to the current session.

The failure mode: **Silent session-only.** You switch model with `s` or a flag and assume it is your new default, then the next session starts on the old model.

The fix: Use Enter in the picker or edit the file for a lasting default.

Cross-references: model and effort choices are Module 4.6.

**If you remember one thing:** decide persistence first, then the tool.

**A passing artifact looks like this:**

| Path | Saved to | Persists | Effect |
|---|---|---|---|
| /config theme | user file | yes | immediate |
| --settings model | nowhere | no | this session |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| Used `s` and called it default | **Silent session-only** |

**The verdict.** Passes if all four paths were executed once, each with observed location and persistence, and the broken-file recovery was shown.
