## 14.1.1.1 — KNOWLEDGE: /INIT AND /MEMORY

**Framing.** `/init` initialises the project with a CLAUDE.md guide. Setting `CLAUDE_CODE_NEW_INIT=1` gives an interactive flow that also walks through skills, hooks and personal memory files, and if `/init` finds OpenAI Codex or Google Gemini CLI configuration it offers to carry it over with `/import` [Claude Code docs, Commands, 2026]. `/memory` edits CLAUDE.md files, turns auto memory on or off and shows auto memory entries [Claude Code docs, Commands, 2026].

| Command | Changes | Observe |
|---|---|---|
| `/init` | Creates a starter CLAUDE.md | The file exists at the project root |
| `CLAUDE_CODE_NEW_INIT=1 /init` | Interactive flow incl. skills, hooks, memory files | Prompts appear |
| `/memory` | Opens CLAUDE.md files; toggles auto memory | The list of loaded files |

```bash
CLAUDE_CODE_NEW_INIT=1 claude      # then run /init inside the session
```

The failure mode: **Draft-as-final.** You run `/init`, accept what it wrote and never prune it, so the file carries generic or wrong lines into every later session.

The fix: Read the generated file line by line, delete anything Claude could infer from the code, and keep only commands and rules that differ from defaults.

Cross-references: CLAUDE.md design is Module 3.2; the file inventory is Module 14.4.

**If you remember one thing:** the generated file is a draft.

## 14.1.1.2 — REACH: /MCP

**Framing.** `/mcp` manages MCP server connections and OAuth authentication. With no argument it opens the interactive list; `reconnect`, `enable` or `disable` take a server name or `all`, and in non-interactive mode with no argument it prints a text summary of server status [Claude Code docs, Commands, 2026].

| You type | Effect |
|---|---|
| `/mcp` | Interactive list and OAuth |
| `/mcp reconnect <server>` | Retry one server |
| `/mcp reconnect all` | Retry every server that failed or needs authentication |
| `/mcp disable all` | Turn servers off for the session's context budget |
| `claude -p "/mcp"` | Text status summary, no UI |

The failure mode: **Silent-server.** A server shows as configured but never connected, and you debug the prompt while no tool from it exists in the session.

The fix: Run `/mcp` first, read the status, and use `reconnect` before touching anything else.

Cross-references: MCP in depth is Module 5.5; the `claude mcp` subcommand is Module 14.3.

**If you remember one thing:** check the server list before blaming the model.

## 14.1.1.3 — CONTROL: /PERMISSIONS

**Framing.** `/permissions` manages allow, ask and deny rules in an interactive dialog: view rules by scope, add or remove them, manage working directories and review recent auto mode denials. Run while Claude is responding, it opens at once and applies changes from Claude's next tool call in the same turn; before v2.1.234 it queued until the turn ended [Claude Code docs, Commands, 2026]. Alias: `/allowed-tools`.

| Dialog area | Use |
|---|---|
| Rules by scope | See where each rule lives |
| Add or remove | Edit allow, ask, deny |
| Working directories | Widen or narrow file access |
| Auto mode tab | Review denials and classifier rules |

The failure mode: **Prompt-fatigue allowlist.** You approve the same prompt repeatedly and then add a broad allow rule to stop the interruptions, which also permits commands you never meant to.

The fix: Add the narrowest rule that matches the prompt you keep seeing, and confirm its scope in the dialog.

Cross-references: rule design is Module 4.2; modes are Module 4.3.

**If you remember one thing:** narrow rules, checked in the dialog.

## 14.1.1.4 — HEALTH AND LEARNING: /DOCTOR AND /POWERUP

**Framing.** `/doctor` runs a setup checkup that diagnoses installation, settings, extension and CLAUDE.md problems and proposes fixes that Claude applies after you confirm; `/doctor prompt-audit [path]` audits instructions and requires v2.1.283 or later; alias `/checkup` [Claude Code docs, Commands, 2026]. `/powerup` offers quick interactive lessons with animated demos [Claude Code docs, Commands, 2026].

| Command | When |
|---|---|
| `/doctor` | After install, after editing settings, when behaviour surprises you |
| `/doctor prompt-audit CLAUDE.md` | Before committing a long instruction file |
| `/powerup` | When you want guided feature discovery |

Availability varies by platform, plan and version; if a command is missing, run `/help` and check `claude --version` before assuming it does not exist.

The failure mode: **Fix-without-reading.** You confirm every fix `/doctor` proposes without reading it, and a settings change you did not understand is now in your config.

The fix: Read each proposed change, apply one at a time, and re-run `/doctor` to confirm the finding cleared.

Cross-references: debugging configuration is Part 12.

**If you remember one thing:** confirm fixes one at a time.

## THE PROVE-IT SECTION

**Deliverable.** A first-session log for a real repo: six commands, six observed results, and a pruned CLAUDE.md.

**Close this topic. Build the artifact below from memory. Return to the text only after your first attempt is complete.**

| Step | Action | Output |
|---|---|---|
| 1 | Create a throwaway repo and run `/init` | A CLAUDE.md |
| 2 | Run `/memory` and list which files loaded | File list |
| 3 | Run `/mcp` and record each server's status | Status table |
| 4 | Run `/permissions`, add one narrow allow rule, trigger it | Log line |
| 5 | Run `/doctor` and record each finding and your decision | Findings table |
| 6 | Prune the CLAUDE.md to commands and differing rules | Diff |

**A passing artifact looks like this:**

| Command | Observed result |
|---|---|
| `/init` | 41-line file, pruned to 12 |
| `/mcp` | Two servers connected, one failed, reconnected |
| `/permissions` | `Bash(npm run test)` allow fired once |
| `/doctor` | Three findings, two fixed, one declined with reason |

**A failing artifact (a realistic near-miss):**

| Element | What is wrong |
|---|---|
| CLAUDE.md unchanged from `/init` | **Draft-as-final** |
| `/doctor` fixes all accepted, no reasons | **Fix-without-reading** |

**The verdict.** The artifact passes only if every command has an observed result and the CLAUDE.md differs from the generated draft.
