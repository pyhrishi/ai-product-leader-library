## 1.2.4.1 — WHAT LOADS BEFORE YOU TYPE

**Framing.** The context window holds everything Claude knows about your session: instructions, files it reads, its own responses and content that never appears in your terminal [Claude Code docs, Context window, 2026]. Before your first prompt, startup content loads: a system prompt, tool definitions, skill descriptions, your user and project CLAUDE.md files and auto memory.

| Startup item | Notes |
|---|---|
| System prompt | About 4,200 tokens in the docs' simulation [representative, not exact; check `/context`] |
| Tool definitions | MCP schemas deferred by default; only names and server instructions load |
| Skill descriptions | Names and descriptions; full content only when used |
| CLAUDE.md files | Concatenated broadest to most specific, loaded as a user message after the system prompt |
| Auto memory | First 200 lines or 25 KB of `MEMORY.md` |

[Claude Code docs, Context window and Glossary, 2026]

Window size depends on model: 200,000 tokens in the docs' simulation; a third-party summary says 1,000,000 on Sonnet 5, Opus 4.6 and later, Sonnet 4.6 and Fable 5 [secondary: dev.to, 2026; confirm in `/context`].

The failure mode: **Startup-bloat.** CLAUDE.md, memory and many skills consume a large share of the window before you type, leaving less room for work.

The fix: Run `/context` at session start, prune CLAUDE.md, and keep skill descriptions short.

Cross-references: the context window in depth is Module 3.1; CLAUDE.md is Module 3.2; skills are Module 5.2.

**If you remember one thing:** measure startup cost; do not guess it.

## 1.2.4.2 — WHAT GROWS: TOOL RESULTS AND FILE READS

**Framing.** Every tool result stays in context for the rest of the session unless compaction clears it. A read of a large file and a command that prints thousands of lines cost the same kind of tokens, and hook output enters context without truncation [Claude Code docs, Context window, 2026].

| Source of growth | Control |
|---|---|
| File reads | Read only what you need; scope the directory |
| Command output | Pipe to a file and read the tail |
| Search hits | Narrow patterns |
| Hook output | Keep `additionalContext` short; it is capped at 10,000 characters [Claude Code docs, Hooks, 2026] |
| Web fetch | Uses a separate context window to limit injection risk [Claude Code docs, Security, 2026] |

```bash
npm test 2>&1 | tail -50          # instead of dumping the whole run into context
```

The failure mode: **Output flood.** A test run or log dump pours thousands of lines into context, pushing out earlier instructions and degrading later answers.

The fix: Pipe to a file and read the tail, run noisy work in a subagent, or add a trimming hook.

Cross-references: subagents are Module 1.2.5; hooks are Module 5.4; large codebases are Module 3.5.

**If you remember one thing:** what a tool prints, the model reads, and keeps.

## 1.2.4.3 — WHAT SURVIVES COMPACTION

**Framing.** Compaction summarises the conversation when the window nears its limit: older tool outputs are cleared first, then the conversation is summarised. After compaction, Claude Code re-reads up to five of the most recently modified files from the session [Claude Code docs, Context window, 2026].

| Mechanism | After compaction |
|---|---|
| Project-root CLAUDE.md, auto memory | Reloaded fresh from disk |
| Conversation-only instructions | May be lost |
| Path-scoped rules, nested CLAUDE.md | Summarised; reload when a matching file is read |
| Skill listing | Not re-injected; only invoked skills preserved |
| Recently touched files | Up to five re-read |

[Claude Code docs, Context window and Glossary, 2026]

Steer it with a focus: `/compact focus on the auth bug fix` [Claude Code docs, Context window, 2026].

The failure mode: **Chat-only rule.** You state an important rule in conversation and compaction summarises it away.

The fix: Put durable rules in project-root CLAUDE.md or enforce them with a hook or deny rule, and verify with `/memory`.

Cross-references: rules and auto memory are Module 3.3; hooks are Module 5.4.

**If you remember one thing:** conversation fades; files reload.

## 1.2.4.4 — SUBAGENT CONTEXT AND DELEGATION

**Framing.** A subagent starts with a fresh context: its system prompt, the delegation message, CLAUDE.md files and a git status snapshot (Explore and Plan skip the last two). A fork inherits the parent conversation [Claude Code docs, Subagents, 2026]. This is how you keep large reads out of your main window.

| Context | Main session | Subagent |
|---|---|---|
| Conversation history | Yes | No (except a fork) |
| CLAUDE.md | Yes | Yes (not Explore or Plan) |
| Files already read | Yes | No |
| Returns | N/A | A summary |

The failure mode: **Context-blind delegation.** You expect a subagent to know earlier constraints and it returns an answer that ignores them.

The fix: Put every constraint, file path and success criterion in the delegation message, or use a fork.

Cross-references: subagent design is Module 5.3; the background of 1.2.5 is next.

**If you remember one thing:** a subagent is a clean desk; hand it everything.
