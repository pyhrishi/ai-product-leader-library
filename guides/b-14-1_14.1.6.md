## 14.1.6.1 — SETTINGS: /CONFIG AND /UPDATE-CONFIG

**Framing.** `/config [key=value ...]` opens the Settings interface, or sets keys directly such as `/config thinking=false`, `/config theme=dark` or `/config model=sonnet`; the key=value form also works with `-p`, cannot turn on settings that need confirmation such as `autoContinueAtUsageLimit` though it can turn them off, `/config --help` lists accepted keys, and the alias is `/settings` [Claude Code docs, Commands, 2026]. `/update-config` is a bundled skill that edits the matching settings.json from a description such as allowing a command or adding a hook [Claude Code docs, Commands, 2026].

| Option saved from `/config` | Written to |
|---|---|
| Most options | `~/.claude/settings.json` |
| A few, such as Show tips | `.claude/settings.local.json` |
| Global config options | `~/.claude.json` |

[Claude Code docs, Settings, 2026]

The failure mode: **Wrong-scope-write.** You change a setting expecting the team to get it, but `/config` wrote it to your user file.

The fix: Check the table above, and for team settings edit `.claude/settings.json` and commit it.

Cross-references: settings are Module 4.1.

**If you remember one thing:** know which file a command writes.

## 14.1.6.2 — LOOK AND FEEL

**Framing.** `/output-style [style]` lists or switches output styles and needs v2.1.269 or later. `/theme` changes the colour theme, including auto, colourblind-accessible and custom themes. `/statusline` configures the status line, auto-configuring from your shell prompt with no arguments. `/tui [default|fullscreen]` sets the renderer and relaunches with the conversation intact [Claude Code docs, Commands, 2026]. `/keybindings` opens your shortcuts file and `/terminal-setup` installs a Shift+Enter binding for VS Code, Cursor, Devin Desktop, Alacritty or Zed [Claude Code docs, Commands, 2026].

| Command | Changes |
|---|---|
| `/output-style concise` | How Claude writes |
| `/theme` | Colours |
| `/statusline` | Bottom status line |
| `/tui fullscreen` | Flicker-free renderer; relaunch |
| `/terminal-setup` | Shift+Enter newline binding |

Availability varies by platform, plan and version; if a command is missing, run `/help` and check `claude --version` before assuming it does not exist.

The failure mode: **Cosmetic-first.** You spend setup time on theme and status line before the permissions and memory that change outcomes.

The fix: Do `/init`, `/permissions` and `/memory` first (Module 14.1 first-session) and treat appearance as the last pass.

Cross-references: terminal setup is Module 9.1.

**If you remember one thing:** outcomes before looks.

## 14.1.6.3 — BOUNDS AND VOICE

**Framing.** `/sandbox` toggles sandbox mode on supported platforms only. `/autocompact [auto|<tokens>]` sets how full the window gets before automatic compaction, saves it to user settings and applies it now. `/voice [hold|tap|off]` toggles voice dictation and needs a Claude.ai account; `/privacy-settings` is for Pro and Max subscribers only [Claude Code docs, Commands, 2026].

```text
/autocompact 500k      # compact earlier than the default window
/autocompact auto      # return to the model-tuned window
/sandbox               # toggle where supported
```

The failure mode: **Sandbox-assumed-on.** You assume the sandbox is active on a platform that does not support it, so Bash commands run unbounded.

The fix: Run `/sandbox` and read the result; do not infer protection from the command existing.

Cross-references: sandboxing is Module 4.4.

**If you remember one thing:** check, do not assume, the sandbox.
