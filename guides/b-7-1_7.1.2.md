## THE THESIS OF THIS TOPIC

**The platforms page compares the surfaces on four axes (trigger, where Claude runs, setup, best use), and a good choice falls out of answering those four in order.**

**Prove-it, in one sentence:** given five tasks, pick a surface for each and justify it using trigger, runs-on, setup and fit.

## 7.1.2.1 — THE AWAY-FROM-TERMINAL TABLE

**Framing.** The platforms page has a table for work when you are away from your terminal. Each row differs in what triggers the work, where Claude runs, how much setup it takes, and what it is best for [Claude Code docs, Platforms and integrations, 2026].

| Option | Trigger | Claude runs on | Best for |
|---|---|---|---|
| Dispatch | Message a task from the mobile app | Your machine (Desktop) | Delegating while away, minimal setup |
| Remote Control | Drive a running session from claude.ai/code or the app | Your machine (CLI, Desktop or VS Code) | Steering in-progress work from another device |
| Channels | Push events from Telegram, Discord or your own server | Your machine (CLI) | Reacting to external events |
| Slack | Mention `@Claude` in a channel | Anthropic cloud | PRs and reviews from team chat |
| Self-hosted environments | Start a cloud session, pick your organization's environment | Your organization's infrastructure | Cloud sessions that must run inside your network |
| Scheduled tasks | Set a schedule | CLI, Desktop or cloud | Recurring automation |

[Claude Code docs, Platforms and integrations, 2026]. Dispatch requires a Pro or Max plan and is not available on Team or Enterprise [Claude Code docs, Mobile, 2026].

The failure mode: **Laptop-lid assumption.** You start Remote Control or a Dispatch task, close the laptop and expect work to continue, because the session feels remote.

The fix: If the machine will be off, use a cloud session or a project; if it must stay local, keep the machine on with the app running.

Cross-references: the surfaces themselves are Module 7.1; Remote Control is Module 7.5; scheduled tasks are Module 7.4.

**If you remember one thing:** ask where it runs before asking how you reach it.

## 7.1.2.2 — FOUR QUESTIONS, IN ORDER

**Framing.** The table reduces to four questions. Asked in order, each removes options: does it need local files or tools, must it survive your laptop closing, who triggers it, and who else must see it?

```text
1. Needs local files, MCP servers or tools only on your machine?
     yes -> CLI / Desktop / IDE; reach it from afar with Remote Control (machine stays on)
     no  -> continue
2. Must keep running with the laptop closed?
     yes -> cloud session (browser, mobile, --cloud) or cloud scheduled task
3. Triggered by an event, not a person?
     yes -> GitHub Actions / GitLab CI, Code Review, API or GitHub trigger on a scheduled task
4. Team must see and steer it in chat?
     yes -> Slack or Claude Tag
```

This tree is a synthesis of the platforms page; the page itself does not publish a tree [secondary: this guide's reading of Claude Code docs, Platforms and integrations, 2026]. Test it against your own cases before adopting it.

The failure mode: **Tool-first selection.** You pick a surface because it is the one you have open, and a task that needs your database credentials lands in a cloud sandbox that cannot reach them.

The fix: Answer question 1 and 2 before opening anything, and write the answer in the task's first line.

Cross-references: cloud environments are Module 4.5 and Module 7.4; permission modes are Module 4.3.

**If you remember one thing:** choose by need, not by what is open.

## 7.1.2.3 — DEFAULT ROUTING FOR A TEAM

**Framing.** A team decision guide is a default plus exceptions. Three defaults cover most teams: local for exploratory or secret-touching work, cloud for long unattended work on GitHub repositories, CI for event-driven jobs.

| Task type | Default surface | Exception |
|---|---|---|
| Debugging with prod-like data | CLI or IDE | None; keep it local |
| Overnight refactor on a GitHub repo | Cloud session | Local if it needs private MCP servers |
| Review every PR | Code Review (Team/Enterprise) or Actions | `/code-review` locally for one-offs |
| Bug report in Slack | Slack or Claude Tag | CLI if the fix needs local repro |
| Weekly dependency check | Scheduled task | `/loop` for in-session polling |

Cloud scheduled tasks need no open machine; Desktop tasks run only while the app is open and the computer awake [Claude Code docs, Scheduled tasks and Desktop scheduled tasks, 2026].

The failure mode: **Default-drift.** The team's default silently changes as each person picks a favourite, and costs and permissions diverge across surfaces.

The fix: Write the default table into the repository's contributor docs and review it quarterly.

Cross-references: cost governance is Module 10.6; rollout is Module 10.1.

**If you remember one thing:** a default plus named exceptions beats case-by-case choice.
