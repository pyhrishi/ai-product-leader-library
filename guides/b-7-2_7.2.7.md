## 7.2.7.1 — THE KEYS THE DESKTOP PAGE NAMES

**Framing.** Managed settings apply to Desktop sessions through named keys. The page names the following [Claude Code docs, Desktop, 2026].

| Key | Effect |
|---|---|
| `disableAutoMode` | Turns off Auto permission mode |
| `browserExternalPageTools` | Disables Claude's tools on external pages; users can still browse |
| `disableBrowserExternalNavigation` | Blocks all external navigation in the Browser; localhost still works |
| `disableSideloadFlags` | Withholds some local skills and plugins, blocks local skill loading |
| `disableRemoteControl` | Stops sessions connecting to Remote Control |
| `remoteControlAtStartup` | Default for new sessions; overridden once the user saves a Desktop setting |
| `crossSessionInbound` | `refuse` drops inbound cross-session messages |
| `sshHostAllowlist` | Restricts which SSH hosts users can connect to |

Admins can also restrict available permission modes, and local sessions can be disabled per device, shown as **Disabled by your organization** [Claude Code docs, Desktop, 2026]. The iOS Simulator adds `disableMobileSimulatorTools` and `requireCoworkFullVmSandbox` [Claude Code docs, iOS Simulator, 2026].

The failure mode: **Key-from-memory.** You write a policy using a key name you half-remember and it silently does nothing.

The fix: Copy key names from the settings reference and test each one by trying the blocked action as a user.

Cross-references: managed settings are Module 10.4; the settings reference is Module 14.6.

**If you remember one thing:** a misspelled key is a policy that does not exist.

## 7.2.7.2 — PLAN LIMITS VERSUS POLICY

**Framing.** Not every gap is a policy. Some features are simply not offered on some plans, and a key cannot add them.

| Feature | Availability |
|---|---|
| Computer use (Desktop) | Pro and Max only; not Team or Enterprise |
| Dispatch | Pro and Max only |
| Bypass permissions mode | Pro and Max: enable in Settings; Team and Enterprise: org policy |
| Auto mode | Needs a supported model on the Anthropic API; admins can disable with `disableAutoMode` |
| Enterprise providers | Desktop supports Google Cloud's Agent Platform and gateway providers; Amazon Bedrock or Microsoft Foundry need the CLI, an IDE extension or Claude Desktop on 3P |

[Claude Code docs, Desktop, 2026]. The iOS Simulator pane is available on Team and Enterprise except Enterprise organizations with HIPAA configuration [Claude Code docs, iOS Simulator, 2026].

The failure mode: **Policy-for-a-plan-gap.** You search for a managed key to enable computer use for your Enterprise team and conclude the product is broken.

The fix: Check the plan table first; if the plan excludes the feature, no key changes that.

Cross-references: plans and limits are Module 1.4; backends are Module 10.2.

**If you remember one thing:** plan first, policy second.

## 7.2.7.3 — DESIGNING A POLICY BUNDLE

**Framing.** Group keys by the risk they close, then test each as an ordinary user.

| Requirement | Key or control | User sees |
|---|---|---|
| No unattended classifier-driven actions | `disableAutoMode` | Auto absent from the selector |
| No remote steering of local sessions | `disableRemoteControl: true` | Sessions cannot connect |
| No browsing of arbitrary sites | `disableBrowserExternalNavigation` | External navigation blocked, localhost works |
| SSH only to approved hosts | `sshHostAllowlist` | Others rejected; allowlist jump hosts too |
| No local third-party skills | `disableSideloadFlags` | Local skills withheld |

For SSH, the docs say jump hosts and proxied hosts must appear in `sshHostAllowlist`; run `ssh -G <host>` to get the hostname to allowlist [Claude Code docs, Desktop, 2026].

The failure mode: **Untested-policy.** You ship a policy bundle and never try the blocked actions, so one key is mistyped and the control is absent for months.

The fix: After each change, attempt every blocked action as a normal user and record the refusal.

Cross-references: rollout is Module 10.1; incident response is Module 11.8.

**If you remember one thing:** every key gets a user-side test.
