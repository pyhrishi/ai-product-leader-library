# MODULE 1.2.1 — THE LOOP: GATHER, ACT, VERIFY, REPEAT: THE COMPLETE CRAFT

## THE THESIS OF THIS TOPIC

**Every task runs through one cycle, gather context, take action, verify results, repeat, and every control you will learn later attaches to a specific point in it.**

**Prove-it, in one sentence:** draw the loop from memory and mark where a turn begins and ends, where you can interrupt, and where a check closes it.

## 1.2.1.1 — THREE BLENDED PHASES

**Framing.** Claude works through every task in three phases: gather context, take action, verify results. They blend: a question may need only gathering, a bug fix cycles through all three repeatedly, a refactor may lean on verification. You can interrupt at any point [Claude Code docs, How Claude Code works, 2026]. The glossary adds that each tool use returns information that informs the next step [Claude Code docs, Glossary, 2026].

| Phase | What Claude does | Typical tools | Output into context |
|---|---|---|---|
| Gather context | Find and read what the task needs | Grep, Glob, Read, `git status` | File contents, search hits |
| Take action | Change files, run commands | Edit, Write, Bash | Diffs, command output |
| Verify results | Check the change worked | Bash (tests, build), Read | Pass/fail output |

```
   prompt ──► gather ──► act ──► verify ──┐
                ▲                          │ not done? loop
                └──────────────────────────┘
        you can interrupt at any point (Esc to stop, Enter to steer)
```

The failure mode: **Loop-blind debugging.** You blame the model for a behaviour that was a blocked tool call, stale context or a missing check, and rewrite the prompt for a problem the prompt did not cause.

The fix: Place the symptom on the loop first: was an action blocked, did a result mislead, or did Claude stop with no check; then fix that layer.

Cross-references: the chatbot-versus-agent contrast is Module 1.1; verification is Module 2.3.

**If you remember one thing:** every misbehaviour has an address in the loop.

## 1.2.1.2 — A TURN IS THE UNIT YOU CAN REASON ABOUT

**Framing.** A turn begins when you send a message and ends when Claude finishes responding, with any number of tool calls in between; a session is many turns, and Stop hooks fire at the end of each turn [Claude Code docs, Glossary, 2026].

| Boundary | What fires or changes |
|---|---|
| Start of turn | UserPromptSubmit hooks; a checkpoint is created at each prompt that starts a turn |
| During a turn | Tool calls, permission checks, hooks around each call |
| End of turn | Stop hooks; Claude waits for you |

Checkpoints are created per turn, so `/rewind` moves you between turn boundaries, not inside one [Claude Code docs, Glossary, 2026].

The failure mode: **Turn-blur.** You treat a long multi-step answer as one decision and cannot say which tool call went wrong, so you restart instead of rewinding to the right point.

The fix: Read the transcript tool call by tool call, and use `/rewind` to return to the turn boundary just before the bad step.

Cross-references: checkpoints are Module 2.5; hooks are Module 1.2.6 and Module 5.4.

**If you remember one thing:** a turn is many tool calls; the transcript tells you which one went wrong.

## 1.2.1.3 — INTERRUPTING AND STEERING

**Framing.** You are part of the loop. `Esc` stops Claude mid-action and the context is preserved so you can redirect; typing a correction and pressing `Enter` steers without stopping [Claude Code docs, How Claude Code works, 2026]. Double `Esc` or `/rewind` opens the rewind menu [Claude Code docs, Glossary, 2026].

| You want to | Do this | Effect |
|---|---|---|
| Stop a wrong direction now | `Esc` | Action stops, context kept |
| Redirect without stopping | Type and press `Enter` | Correction joins the loop |
| Undo what it did | `Esc Esc` or `/rewind` | Restore code, conversation or both |
| Abandon a cluttered attempt | `/clear` | New session; old one stays resumable |

The docs advise that after more than two failed corrections on the same issue, `/clear` and a better first prompt beat a third correction [Claude Code docs, Best practices, 2026].

The failure mode: **Correction spiral.** You correct the same mistake a third and fourth time inside one context full of failed attempts, and quality keeps dropping.

The fix: After two failed corrections, `/clear` and rewrite the prompt with what you learned.

Cross-references: session management is Module 2.4; prompting after a reset is Module 2.2.

**If you remember one thing:** interrupt early, and reset instead of arguing.

## 1.2.1.4 — CLOSING THE LOOP: CHECKS AND STOP CONDITIONS

**Framing.** Because Claude stops when the work looks done, a stop condition must be something it can run. The docs list ways to gate completion: a prompt that names the check, `/goal`, a Stop hook, or a verification subagent [Claude Code docs, Best practices, 2026]. The glossary calls the check a verification loop and names it the prerequisite for unattended runs [Claude Code docs, Glossary, 2026].

```text
Prompt with a closed loop:
"Run `npm test`. Fix any failures. Repeat until the suite is green or you have
 tried 5 times. Then show me the last test output and `git diff --stat`."
```

| Stop condition | Strength | Weakness |
|---|---|---|
| "Looks done" | None | Claude's own judgement |
| A named command | Good | Only as good as the command |
| `/goal` with a check | Strong for unattended work | Needs a real check |
| Stop hook | Deterministic | Must exit 2 to block |

The failure mode: **Looks-done stop.** Claude ends the turn when the work appears complete and no check was defined, so an incorrect result ships.

The fix: Name the command that proves success and require its output in the final message.

Cross-references: verification is Module 2.3; goals, loops and schedules are Module 6.7; Stop hooks are Module 1.2.6.

**If you remember one thing:** the loop is only closed by a check Claude can run.

## CLOSING REFRAME

This is the craft of the loop: **three phases, a turn boundary, and a check that closes it.** The engineer who understands this does not ask "why did it do that?" — they ask "which phase was that, and what would have closed the loop?"
