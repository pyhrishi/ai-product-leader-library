## THE THESIS OF THIS TOPIC

**Keybindings are a JSON file of context blocks mapping keystrokes to named actions, validated at load, hot-reloaded, with a short list of keys you cannot touch.**

## 14.2.8.1 — FILE AND STRUCTURE

**Framing.** `/keybindings` creates or opens `~/.claude/keybindings.json`. The file is an object with a `bindings` array; each block names a `context` and a map of keystrokes to actions, and changes are detected and applied without a restart [Claude Code docs, Keybindings, 2026].

```json
{
  "$schema": "https://www.schemastore.org/claude-code-keybindings.json",
  "bindings": [
    { "context": "Chat",
      "bindings": { "ctrl+e": "chat:externalEditor", "ctrl+s": null } }
  ]
}
```

| Part | Meaning |
|---|---|
| `context` | Where the block applies (Global, Chat, Autocomplete, Confirmation, Transcript, HistorySearch, Select and others) |
| `"action"` | Namespace:action such as `chat:submit` |
| `null` | Unbinds a default |

The failure mode: **Wrong-context.** You bind a key in `Chat` for an action that belongs to `Confirmation` or `Select`, and it never fires where you expect.

The fix: Look up the action's context in the reference and put the block there.

Cross-references: settings files are Module 4.1.

**If you remember one thing:** an action lives in one context.

## 14.2.8.2 — SYNTAX

**Framing.** Modifiers are `ctrl`, `shift`, `alt`/`opt`/`option`/`meta` and `cmd`/`command`/`super`/`win`; key names are case-insensitive; chords are space-separated and each keystroke must follow within 3 seconds; the `cmd` group is detected only in terminals that report Super, so prefer `ctrl` or `meta` for portable bindings [Claude Code docs, Keybindings, 2026].

```text
ctrl+k ctrl+s     chord: press within 3 seconds
meta+p            Option+P on macOS, Alt+P elsewhere
ctrl+ k           BROKEN: a space next to + makes a chord of "ctrl+" then "k"
```

The failure mode: **Spaced-plus.** You write `ctrl+ k` and Claude Code reads it as a chord whose first stroke never matches, so the binding never fires.

The fix: Remove spaces around `+` and check the debug log.

Cross-references: terminal behaviour is Module 9.1.

**If you remember one thing:** no spaces next to plus.

---

## 14.2.8.3 — RESERVED KEYS AND PREFIXES

**Framing.** Ctrl+C, Ctrl+D, Ctrl+M, Ctrl+[, Ctrl+I, Ctrl+H and Caps Lock cannot be rebound. Default chords share the `ctrl+x` prefix, and unbinding only some of them leaves the prefix in chord-wait mode [Claude Code docs, Keybindings, 2026].

| Reserved | Why |
|---|---|
| Ctrl+C | Hard-coded interrupt |
| Ctrl+D | Hard-coded exit |
| Ctrl+M, I, [ | Arrive as Enter, Tab, Escape |
| Ctrl+B, Ctrl+A, Ctrl+Z | Not reserved, but conflict with tmux, screen and suspend |

The failure mode: **Half-freed-prefix.** You unbind a few ctrl+x chords hoping to use ctrl+x alone and it still waits for a second key.

The fix: Unbind every chord on the prefix, in each context that defines it.

Cross-references: terminal conflicts are Module 14.2 (multiline).

**If you remember one thing:** free a prefix all at once.

## 14.2.8.4 — VALIDATION AND TEAM USE

**Framing.** Claude Code writes warnings to the debug log for parse errors, misspelled modifiers, spaced `+`, invalid contexts, unknown actions, reserved-key conflicts and duplicates; start with `--debug` to see them [Claude Code docs, Keybindings, 2026]. An unknown action name skips the binding and keeps the default for that key.

| Problem | Result |
|---|---|
| Invalid JSON | Warning, file not applied |
| Unknown action | Binding skipped, default stays |
| Reserved key | Warning |
| Duplicate in context | Warning |

The failure mode: **Silent-typo.** You mistype an action name and believe your binding is live because nothing visibly failed.

The fix: Launch with `--debug`, trigger the key and read the log.

Cross-references: debugging is Part 12.

**If you remember one thing:** typos only show in the debug log.
