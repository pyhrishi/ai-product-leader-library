## THE THESIS OF THIS TOPIC

**The five approaches sit on a spectrum from you juggling sessions to a script or a lead agent holding the plan, and the right point is set by how much supervision the task can tolerate, not by how autonomous you want to feel.**

**Prove-it, in one sentence:** place five of your recent tasks on the spectrum, and for each name who decides what runs next and where intermediate results live.

**The single most important discipline: decide who holds the plan before you start, and write it down in the prompt.**

**The counterintuitive claim you will learn to defend:** more autonomy is not free: handing the plan to a script or lead moves intermediate results out of your sight and, for agent teams, adds coordination overhead and token cost [Claude Code docs, Agent teams, 2026].

## 6.1.2.1 — THE SPECTRUM

**Framing.** The docs describe the approaches as differing in how involved you stay, from steering each conversation yourself to letting Claude coordinate a group of workers [Claude Code docs, Run agents in parallel, 2026]. The workflows page makes the same point as a table of who decides what runs next [Claude Code docs, Dynamic workflows, 2026].

| Level | Approach | Who decides what runs next | Where results live |
|---|---|---|---|
| You juggle | Sessions you run, with worktrees | You | Each session's transcript |
| You hand off | Agent view | You dispatch; sessions report only to you | Each background session |
| Claude delegates | Subagents | Claude, turn by turn | Claude's context window |
| A lead supervises | Agent teams | The lead agent, turn by turn | A shared task list |
| A script runs | Dynamic workflows | The script | Script variables |

The failure mode: **Autonomy-by-default.** You pick the most autonomous row because it feels advanced, and a small task burns a team's worth of tokens or a workflow's setup time.

The fix: Start at the least autonomous level that clears the task, and move right only when you can name what the extra coordination buys.

Cross-references: the five approaches are sub-topic 6.1.1; agent teams are Module 6.4.

**If you remember one thing:** the left of the table keeps you in control, the right keeps your context clean.

## 6.1.2.2 — WHO HOLDS THE PLAN

**Framing.** The workflows page frames the difference as who holds the plan. With subagents, skills and agent teams, Claude is the orchestrator and every result goes into a context window; a workflow script holds the loop, branching and intermediate results itself, so Claude's context holds only the final answer [Claude Code docs, Dynamic workflows, 2026].

```text
Subagents:   Claude decides -> spawns -> result lands in Claude's context
Workflow:    Script decides  -> agents run -> results stay in script variables
                                     -> Claude's context gets the final answer only
```

A consequence the same page states: with a workflow, interruption is resumable in the same session, whereas interrupting subagents or skills restarts the turn [Claude Code docs, Dynamic workflows, 2026].

The failure mode: **Plan-in-the-head.** You expect Claude to remember a 40-step plan across turns, and the plan drifts because it lived only in the conversation.

The fix: When the plan is long and mechanical, put it in a script (a workflow) or a file the sessions share, not in turn-by-turn judgement.

Cross-references: workflows are Module 6.5; context limits are Module 3.1.

**If you remember one thing:** the question is where the plan lives, not how smart the agent is.

## 6.1.2.3 — COORDINATION YOU CANNOT DELEGATE

**Framing.** Some coordination stays with you whatever you pick. The agent teams page says a team runs best when you monitor and steer it, and warns that letting a team run unattended too long increases the risk of wasted effort [Claude Code docs, Agent teams, 2026]. Agent view sessions report only to you, so approval of what they produce is yours [Claude Code docs, Run agents in parallel, 2026].

| Approach | What stays with you |
|---|---|
| Subagents | Judging the summary they return |
| Agent view | Reading the result, answering Needs input, approving the PR |
| Agent teams | Monitoring, steering, and approving teammate permission prompts that bubble up to the lead |
| Workflows | Approving the plan before it runs (depending on permission mode) and reading the report |

The failure mode: **Unsupervised sprawl.** You launch a team or a large workflow and walk away, and by the time you return it has spent tokens on a direction you would have stopped in minutes.

The fix: Check in on a schedule you set before launch, and give the run a size guideline or a stop condition so it cannot grow without you.

Cross-references: approvals are Module 4.3; stop conditions for long runs are Module 6.7.

**If you remember one thing:** autonomy removes keystrokes, not responsibility.

## 6.1.2.4 — A HYBRID WORTH KNOWING

**Framing.** Approaches combine. You can dispatch several sessions from agent view yourself and have Claude pass findings between them with cross-session messaging; the comparison page says the dispatched sessions can be messaged this way [Claude Code docs, Run agents in parallel, 2026]. Inside any one of those sessions Claude can still use subagents or run a workflow.

```text
You (coarse):   claude agents  -> dispatch 3 sessions, each in its own worktree
Claude (fine):  each session -> subagents / a workflow for its own task
Between them:   cross-session messaging for findings and status
```

The failure mode: **Flat-plan thinking.** You choose one approach for the whole job, so either you supervise fifty file edits yourself or you trust a team with a decision that needed your review.

The fix: Layer the levels: coordinate coarsely yourself (which tasks), and let a script or subagents coordinate finely (which files).

Cross-references: messaging is Module 6.6; layered patterns are in Module 6.10.

**If you remember one thing:** coordinate the big decisions yourself and delegate the repetitive ones.

## CLOSING REFRAME

This is the craft of choosing coordination: **a spectrum from your hands to a script's, with the plan living where you can inspect it.** The engineer who understands this does not ask "how autonomous can this be?" — they ask "who should hold the plan, and when do I look?"
